# 혼디 보호자 동선 심사 · 2026-11-18

**공식 전문가 배점으로 자체 평가한 결과는 74/100점이다.** 보호자가 원하는 시간과 지원을 결과까지 보존하는지, 빈자리가 없거나 조건을 바꿔도 다음 행동을 찾을 수 있는지를 우선 평가했다. 혼디의 강점은 제주에서 내륙 병원까지 이어지는 준비를 한 방문으로 다루는 점이다. 가장 큰 감점은 예약 조율의 성공이 고정된 가상 회신으로 정해져 있어, 이 동선만으로는 AI가 예외 상황을 해결하는 능력을 평가하기 어렵다는 점이다.

공식 공고와 공고 페이지가 사용하는 평가 원문에서 아래 배점을 확인했다. 대회는 전문가 평가 70%와 참가자 상호평가 30%를 반영한다. 아래 점수는 로컬 시연을 직접 사용한 한 평가자의 판단이며, 참가자 ELO와 최종 대회 점수는 산정하지 않았다. [대회 공고](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge) · [평가항목 원문](https://daker.ai/api/hackathons/jeju-ai-bigdata-agent-challenge)

## 보호자가 수행한 과제

| 과제 | 보완 전 Ego Lite에서 관찰한 실패 | 보완 후 확인한 결과 |
| --- | --- | --- |
| 제주 진료와 휠체어 차량 시각을 한 번에 요청 | 오후 2시 진료와 오전 11시 30분 출발이 각각 10시·9시로 대체됐다. 제외한 동행에도 약속 시각이 인쇄됐다. | 입력 중 표시, 조건 확인, 결과창, 내려받은 파일이 모두 14:00 진료·11:30 출발을 유지했다. 동행은 요청 제외, 의뢰서는 본인의 보유 응답과 병원 확인 전 상태로 표시했다. |
| 선택한 제주 문의처를 저장하고 다른 지역도 탐색 | 내려받은 결과표에 선택한 애월콜이 없었다. 조율 후 문의 지역만 서귀포시로 바꾸자 차량의 출발지가 바뀌고 완료 결과 하나가 사라졌다. | 서귀포시를 둘러보면 차량 문의처는 5곳으로 바뀌고, 이미 조율한 차량은 애월읍 11:30, 완료는 2건을 유지했다. 애월콜의 공개 연락처·기준일·출처 링크가 실제 다운로드에 포함됐다. |
| 내륙 병원의 마감일로 상담 준비 | 달력에서 ‘일정 상담으로 계속’을 눌러도 마지막 단계에서 진료 시각을 요구해 멈췄다. | 11월 24일은 서울 한빛대학교병원 종양내과 상담 메모로 종료했다. 예약 현황에 ‘일정 상담 · 예약 미정’으로 남고, 다시 같은 메모를 열어 다른 날짜를 찾을 수 있었다. |
| 가능한 의사·시간과 공항행을 맞추고 예약 수정 | 결과에 의료진 이름이 없고, 항공 검색은 12월 8일인데 제주공항행 차량은 7일이었다. | 12월 8~10일 범위에 김도윤 10:30·14:40을 비교했다. 전날/당일 선택에 따라 검색 링크와 차량 날짜가 함께 7일/8일로 바뀌었다. 예약 수정으로 14:40을 10:30으로 옮기고, 변경 전후와 갱신된 의료진·동행 시각을 확인했다. |

제주 과제에는 “제주우리병원 정형외과에 12월 8일 오후 2시 진료를 희망해요. 애월읍에서 오전 11시 30분에 휠체어 택시를 타고 싶어요. 병원 동행은 필요 없어요. 진료의뢰서는 가지고 있어요.”를 그대로 사용했다. 애월콜은 연락할 수 있는 공개 후보이며 이 업체가 휠체어 차량을 제공한다는 회신은 없다. 병원 859번 자료의 원문에서 진료과·영업상태와 자료 시점을 확인했다. 원자료의 시점과 전화번호 출처를 가상 예약의 회신 기관과 분리했다. [제주데이터허브 병·의원 등록정보](https://jejudatahub.net/data/view/data/859) · [제주데이터허브 콜택시 자료](https://jejudatahub.net/data/view/data/327)

서로 다른 시각을 같은 진료에 제시한 경우도 따로 시험했다. ‘오전 10시 또는 오후 2시’라고 적자 화면이 시간을 고르도록 안내했고, 누르면 12월 8일 희망 시간 선택으로 바로 연결됐다. 음성 화면에서는 말하기 예시와 시작 버튼을 확인했고, 글쓰기 예시는 실제 초안에 넣어 봤다. 마이크를 통한 음성 왕복과 끼어들기는 이번 평가 범위에서 실측하지 않았다.

차량이 없는 시연에서는 병원 1건만 완료되고 차량 1건은 ‘직접 확인 필요’로 끝났다. 예약 현황에서 이 미해결 내역이 펼쳐졌다. 성공한 두 방문은 내역을 접고 병원·의료진·시각과 수정 버튼을 먼저 보여준다. 1366×768 CSS 뷰포트에서 두 방문의 수정 버튼을 모두 스크롤 없이 볼 수 있었다. 좁은 화면에서는 예약 중 쓸 수 없는 대화 도구를 걷어내고 ‘내 예약 현황’에 글자 라벨을 붙였다. 312×675 CSS 뷰포트에서 상담의 다음 버튼 하단은 627px였고 가로 넘침은 없었다. 좁은 화면의 본문은 세로로 스크롤할 수 있다. 두 해상도 모두 Ego Lite에서 측정한 값이다.

## 재현과 증거

최적화한 Next.js 빌드를 로컬 서버에서 열고 버튼·달력·목록·다운로드를 실제 Ego Lite로 조작했다. 11~12월 예약은 제품의 2026-11-15 기준 고정 시간표다. 공개기관 발신, 좌석·운임 조회, 항공 결제는 수행하지 않았다. 실행과 회귀 검사에는 각각 `npm run build`, `npm start`, `npm test`를 사용한다. 같은 사용 흐름에서 **보호자가 적은 시각 → 화면에 표시된 시각 → 저장표에 인쇄된 시각**을 대조할 수 있다.

최종 소스 지문은 `0f0ca351becc0b68`로 시작한다. 예약 관련 12개 파일의 테스트 98개가 통과했다. Windows 전체 검사에서는 설치된 Python을 테스트 프로세스에 연결한 뒤 620개 중 611개 통과, 8개 실패, 1개 건너뜀이었다. 실패는 파일·디렉터리 심볼릭 링크 생성 권한과 Unix의 `/dev/stdin`을 사용하는 배포·패키지 검사에 남았다.
