## 요청 충족

- 첫 화면의 주 작업은 텍스트와 음성 요청이다. 병원 선택·가능/불가 선택·자료 체크박스 등의 수동 단계가 사라지고, 병원·자료·택시·동행은 읽기용 요약으로 남아 있다.
- 화면은 합성 사례 한 건과 요청 입력에 초점을 둔다. 풍경 배너·인물 그림·반복 카드 없이 기존 PNG 로고와 따뜻한 바탕, 현무암색 본문, 제한된 행동색을 사용한다. 제주·보호자 맥락은 사례와 출발지역으로 드러난다.
- 자유 대화의 모델 미연결을 입력 전에 보여준다. 미리보기는 고정 시나리오, 작성된 예시, 합성 회신과 실제 발신 없음을 구분한다. 병원 절차와 택시 가능 응답도 해당 요약에 합성/시연으로 표시된다. 실제 협진·예약·배차 완료로 읽히는 material 오표시는 발견하지 못했다.
- 오류 화면은 기존 입력을 보존하고 같은 요청 재확인을 제공한다. 원문을 다시 입력시킬 필요가 없다. 준비 상태와 출처·공개 주소 지도 링크는 대화의 보조 정보로 배치된다.

## 남은 작은 개선

1. **P2 — '다음 확인'의 첫 항목이 보호자가 실행할 일처럼 보이는 개발 연결 조건이다.** preview에서 '승인된 공단 기록 연계 설정'이 가장 먼저 나온다. 보호자가 설정 가능한 기능이 없으므로, 향후에는 미연결 이유를 연결 범위에서 설명하고 보호자·의료진이 실제 할 수 있는 확인을 먼저 읽히게 하는 편이 낫다. 현재는 명시적 고정 시연이고 실패 사실을 숨기지 않아 배포를 막지는 않는다.
2. **P2 — 제주 진찰 관련 다음 확인이 중복된다.** '제주 대면 진찰·의료진 기록 확인'과 '제주 대면 진찰 소견을 준비'가 같은 목록에서 반복된다. 서로 다른 원래 항목은 보존하되 의료진 담당 작업으로 묶거나 문구를 구체화하면 모바일의 긴 하단 요약과 중복 경고를 줄일 수 있다.
3. **P3 — 서비스의 도외 주치의 연결 목적이 첫 설명에서 약하다.** 현재 병원·자료·이동·동행 준비는 잘 보이지만, 제주 대면 진찰과 기존 도외 주치의 검토를 연결한다는 핵심은 하단 '기존 도외 병원' 항목에 의존한다. 첫 Agent 설명 한 문장에 이 목적을 넣으면 일반 병원 일정 도우미와의 차이가 더 빨리 이해된다.

미리보기의 긴 설명과 15건 처리 기록은 모바일 안쪽 대화 영역에서 스크롤해 읽어야 한다. 입력이 첫 화면에 남도록 한 일관된 절충이며, 짧은 상태 요약이 위에 있어 현재 범위의 blocker로 보지 않았다. 향후 긴 답변은 처리 결과·다음 행동부터 짧게 쓰면 유리하다.

## 캡처 오탐과 한계

원래 mobile preview/tools fullPage 이미지 가운데 보이던 '본문으로 바로가기'는 실제 UI 중첩 결함으로 분류하지 않았다. 실제 새 탭에서 요약 확장 후 scrollY=256일 때 skip link rect.top=-70/bottom=-26, CSS top=-70px로 viewport 밖에 있었고, 실제 viewport 캡처에도 보이지 않았다. scrollY0으로 돌린 추가 캡처에서도 숨겨져 있었다. 스크롤된 페이지를 fullPage로 캡처한 artifact다.

추가 증거: independent-metrics.json, independent-preview-viewport.png, independent-preview-top.png. 모두 /tmp/jeju-conversation-ui/에 저장했다. 실제 마이크·모바일 하드웨어 키보드/가상 키보드·VoiceOver·실제 LLM 품질은 검증하지 않았다. root의 API 브라우저 자동 검사와 이번 시각 검토를 임상·법률·실기관 연동 검증으로 확대하지 않는다.

## 최종 delta 확인 — dfd0df2

2026-10-31. 최신 conversation-initial-mobile.png와 conversation-preview-desktop.png 두 캡처를 view_image로 다시 직접 확인하고, 최초 검토 기준 3ad044c에서 dfd0df2까지의 관련 소스 diff를 읽었다. 저장소는 수정하지 않았다.

- **최초 P2 공단 연결 항목 해결:** 다음 확인이 '실제 진료기록 확인 필요'로 바뀌었다. 실제 기록은 본인인증·동의를 거친 연계가 필요하다는 설명을 유지하고, 보호자가 API를 설정해야 한다는 실행 과제를 제거했다. 최신 preview PC 캡처에서 변경 문구와 합성·미연결 안내를 확인했다.
- **최초 P3 목적 가시성 해결:** 첫 Agent 설명에 제주 대면 진찰과 그 자료를 통한 기존 도외 주치의 검토 목적이 직접 들어갔다. 최신 initial 모바일 캡처에서 첫 설명을 읽을 수 있고 입력·음성·보내기는 여전히 첫 화면에 남는다.
- **본문 가독성 개선:** 요청 소개·도구 설명·오류·다음 확인 제목 등의 13px 본문을 14px로 올린 diff를 확인했다. 기존 대화 본문14px·모바일 입력16px와 정렬되며, 두 최신 캡처에서 겹침·추가 가로 넘침·큰 빈 영역 같은 material 회귀는 발견하지 못했다.
- **촬영 artifact 대응:** 촬영 함수의 activeElement blur, scrollY0 복귀와 두 animation frame 대기 수정을 읽었다. 실제 viewport에서 skip link가 숨겨져 있음을 확인한 최초 독립 증거와 일치하는 촬영 수정이다.

실제 대면 진찰과 의료진 소견·문서 준비는 서로 다른 두 단계로 남긴다. 현재 '제주 대면 진찰·의료진 기록 확인'과 '제주 대면 진찰 소견을 준비'의 제목이 비슷해 보이는 점은 **작은 문구 개선 한계(P3)**로 기록한다. 완료 단계를 허위 표시하거나 보호자에게 진찰 기록을 직접 작성시키는 문제는 아니므로 blocker로 보지 않는다.
