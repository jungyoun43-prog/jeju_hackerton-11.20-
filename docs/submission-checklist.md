# 대회 제출 요건 추적표

기준일: 2026-10-31 · PRD v0.12 · 사용자 제공 요건과 기존 공식 조사 기록 기준. 제출 전 최신 공지를 다시 확인한다.

현재는 대화 UI·Sol 공개 AWS 연결과 DynamoDB 영속 상태/전역 한도 버전이다. 실제 공개 Sol 단일 도구 스모크200·5.2초와 같은 세션 중복 요청 미차감을 확인했다. 모델 전반 품질·실제 마이크·전화/공단 연계·최종 PDF는 별도다. 최신 검사/CI/ZIP 증거는 [구현 결과](implementation-results.md)를 따른다. 이전 버전의 수치를 새 버전 결과로 옮겨 적지 않는다.

상태는 **설계 반영 / 코드 구현 / 검증 대기 / 후속 보류 / 미완료 / 검증 완료**로 구분한다. 파일 존재·정상 작동·권리 확인·대회 제출 완료는 각각 확인한다.

| 결과 설명 | 문제·구조·기능 | PRD·기능 흐름·구현 결과 | 자연어 도구 루프·공개 Sol 단일 스모크·합성 외부 작업·후속 모델 품질을 구분 |
| 결과 설명 | 실행·검증·한계 | 단위·브라우저·배포 기록·캡처 | 단위220·대화115/수동47·규칙37, 공개Sol·세션저장·동일revision CI·ZIP 독립 설치/빌드 확인. 복합모델·마이크 별도 |
| 결과 설명 | 센터 활용 | PRD8절·구현 결과 | 진료 준비·데이터 활용·조건 변경 교육, 실기기 검증 미완료 |

`output/agent-lambda.zip`은 AWS 함수 게시용이며 최종 제출용 `output/jeju-care-compass-mvp.zip`을 대신하지 않는다. `dist/`에는 backend ZIP·인증정보를 넣지 않는다. ZIP 생성은 대회 사이트 업로드나 제출 완료를 뜻하지 않는다.

## 진료 연결 여정 추가 범위

세 결과의 근거 경계, 기록→할 일, 답변 이후/시간 변경 재확인, 세 상황과 데이터 조건 영향을 추가한다. 최신 통합 단위·브라우저·배포 증거와 비교해 구현/검증 상태를 확정한다. 기존171/47/233 수치를 새 여정의 검사로 확대하지 않는다. 실제 환자/의료진/통화·기록 연계·실증과 최종15페이지PDF는 별도다.

## 4. 다음 제출 작업

1. 이번 대화 UI·API·문서의 같은 커밋에서 PC·모바일·정적/Node API·Lambda ZIP·공개 revision·패키징 검증과 결과 기록을 확정한다.
2. 15페이지 이내 기획서 PDF와 결과 설명·발표/영상에서 현재 구현·합성·미연결·검증 수치를 맞춘다.
3. OpenAI Sol 공개 단일 도구 스모크·영속 전역 한도 다음으로 복합 요청·Terra·한국어 품질·초기 요청 중복 방지를 검증한다.
4. 실제 통화·개인 기록·예약/배차·기관 참여·임상 검토·센터 실기기는 후속 작업으로 관리하고 현재 완성 기능처럼 제출하지 않는다.
5. 최종 source·license·데이터 시점·권리·비밀값·재실행을 대조한 뒤 최신 공지·마감·업로드 결과를 확인한다.

전체 운영 API나 추가 데이터 개수는 기본 공개 자료 활용의 선행 조건이 아니다. 후보229·1304·216·센터교통 등은 실제 다음 행동을 바꾸는 경우에만 선택한다.
