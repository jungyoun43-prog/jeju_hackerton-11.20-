# 제주 진료 나침반 MVP 사용자 매뉴얼

버전: 0.1 개발 기준 · 작성일: 2026-10-31

이 버전은 보호자의 협진 준비 동선을 확인하는 **시뮬레이션**이다. 환자·기관·통화·의료진 회신은 합성이고 실제 병원에 전화하거나 자료를 전송하지 않는다. 문의와 의료진 검토를 구분하는 동작을 확인한다.

## 1. 설치와 실행

Node.js 22 이상과 npm이 필요하다. 저장소 루트에서 실행한다.

```bash
npm ci
npm run dev
```

터미널이 출력한 Local 주소를 브라우저에서 연다. 개발 서버의 기본 예정 주소는 `http://127.0.0.1:4173`이며, 실제 포트·설정은 [README](../README.md)를 따른다. 첫 설치에는 npm 접속이 필요하다.

```bash
npm test
npm run build
npm run preview
```

각 명령의 실제 검증 여부와 환경은 [구현·검증 결과](implementation-results.md)에 기록한다. 센터 PC에서의 실행 확인은 개발 환경 검사와 별개다.

## 2. 첫 시연

1. 진료 준비 화면에서 합성 환자와 기존 도외 병원·제주 기관 역할을 확인한다. 시연에서 제시한 날짜·횟수는 진료 지시가 아니다.
2. 기존 도외 병원 문의를 재현한다. 최근 판독문·제주 진찰 소견 요청 등 응답을 선택하고, 필요 자료와 다음 할 일이 바뀌는지 확인한다.
3. 제주 기관 문의도 재현한다. 공개 기관 목록에 있다고 협진 참여가 확인된 것으로 취급하지 않는다.
4. 진료 자료에서 판독문과 실제 진찰 기록에 해당하는 **예시 자료**를 준비한다. 의뢰서가 요구된 분기에서는 의료진 작성 자료가 별도로 필요하다. 시연 문서 추가는 실제 진찰·검사 수행을 뜻하지 않는다.
5. 문의 허용과 구별된 자료 공유 허용을 확인한다. 필요한 두 기관 확인·필수 자료·공유 허용이 부족하면 검토 접수 재현을 진행할 수 없다.
6. 준비가 완료되면 자료 제출·검토 접수를 재현한다. 이것은 외부 병원 전송이나 예약 완료가 아니다.
7. 의료진 역할의 합성 회신을 입력한다. 추가 자료 요청이면 보완 단계로 돌아가며, 자료 준비 후 다시 검토를 요청한다.
8. 검토 회신에 따른 준비 작업을 확인하고 일정·이동에서 방문 횟수·동행 가능 횟수·가정 금액을 바꾸어 본다. 미확인 금액과 동행 공백이 함께 표시되는지 확인한다.

자료나 문의 조건을 바꾸면 이전 검토 결과가 현재에도 유효한지 다시 확인해야 한다. 시연은 이 변경을 감지해 재준비·재검토로 연결하는 것을 목표로 한다.

## 3. 문의 결과 읽기

| 문의 응답 | 다음 행동 | 의미 |
| --- | --- | --- |
| 자료 요청 | 보유·누락·미수행을 대조하고 담당자 확인 | 운영 절차 안내 |
| 의사 명의 의뢰 필요 | 의료진 작성·확인 작업 준비 | Agent가 의사 대신 의뢰서를 발행하지 않음 |
| 연결되지 않음 | 연락처·창구·재문의 확인 | 진료 불가나 도외 방문의 임상 필요성을 뜻하지 않음 |
| 협진 미참여 | 다른 운영 경로·후보 확인 | 해당 기관의 참여 상태 |

검토 회신과 예약 확정은 별도다. 문의나 검토 완료만으로 기존 외래를 취소하지 않는다.

## 4. 지도와 이동

기본 지도는 Leaflet·OpenStreetMap을 사용하는 구성이다. 초기 집·병원 마커는 **시연용 합성 위치**이며 실제 환자 주소와 참여 병원 위치가 아니다. 지도 자체의 지형·지명과 마커의 출처를 구분한다.

외부 Google Maps 위치·길찾기 링크는 별도 지도 화면으로 연결한다. 외부 페이지의 지원 지역·경로·정보를 직접 확인해야 한다. 앱이 실제 경로를 조회하지 않았다면 이동시간이나 연결선을 도로 경로로 설명하지 않는다. Google Maps Embed는 유효한 키를 별도로 설정한 경우에만 사용한다.

지도 타일을 불러오지 못해도 문서·문의·일정 시연을 사용할 수 있게 설계한다. 실제 네트워크와 폴백 동작의 검증 상태는 결과 기록을 확인한다.

## 5. 비용과 동행

금액 입력은 사용자가 바꾸어 보는 **가정 예산**이다. 병원 견적이나 급여 적용을 확인한 개인별 청구 예상액이 아니다. 미확인은 비워 두고, 미확인 항목이 있는 부분합을 전체 총비용으로 읽지 않는다.

교통·숙박·의료비·보호자 이동의 적용 범위를 구분하고 같은 차량·객실·여행을 두 번 합산하지 않는다. 도내 진료라도 서울 보호자가 제주로 이동하는 부담이 생길 수 있다. 동행 공백은 준비가 필요한 횟수이며, 지원 서비스 예약 완료를 뜻하지 않는다.

## 6. 보고서와 제출

보고서는 시연 표시, 문서·응답 출처, 현재 진행, 다음 할 일, 가정 비용·미확인 항목을 담는다. 의료진 회신을 시뮬레이션한 결과를 실제 진료 소견서로 사용하지 않는다.

개발·제출 점검 명령은 다음과 같다. 통합 전이거나 해당 스크립트가 아직 없으면 완료로 간주하지 않고 결과 기록을 확인한다.

```bash
npm run observe
npm run eval
npm run package
```

ZIP은 현재 버전의 실행 소스·의존성 정보·환경변수 예시·매뉴얼·데이터 명세·결과 설명을 포함해야 한다. 최종 제출 전 [제출 체크리스트](submission-checklist.md)의 열린 필수 항목을 확인한다. ZIP 생성 자체는 대회 제출 요건 충족이나 업로드를 뜻하지 않는다.

## 7. 오류와 제약

| 상황 | 확인·해결 |
| --- | --- |
| 설치 실패 | Node 버전, 네트워크와 npm 접근 확인. 잠금 파일 기준 `npm ci` 재시도 |
| 서버 주소가 열리지 않음 | 실행 프로세스·출력 포트 확인. 원격 서버의 loopback 주소는 다른 기기에서 바로 열리지 않음 |
| 자료 제출 재현 거부 | 양기관 절차 확인·필수 문서·공유 허용 상태 확인 |
| 이전 회신이 사라지거나 재검토가 필요함 | 문서·문의 조건 변경 여부 확인. 오래된 검토 결론을 유지하지 않는 동작 |
| 금액 계산 거부 | 음수·숫자가 아닌 값·비정상 횟수를 수정. 미확인 금액을 0으로 채우지 않음 |
| 지도 로드 실패 | 외부 네트워크·타일 서버 접근 확인. 지도 실패를 병원의 수용 가능 여부로 해석하지 않음 |
| 실제 전화·의료진 연결이 필요함 | 현재 버전은 해당 기능 미연동. 기존 병원의 공식 절차로 확인 |

현재 시연에는 실제 환자 기록·음성·인증정보를 넣지 않는다. 실제 서비스 전환에 필요한 민감정보 처리·외부 전송·보관 구조는 별도 설계·검토 대상이다.
