# 혼디 데이터와 출처 명세

확인일: 2026-10-31 · 연결 문서: [PRD](prd.md)

이 명세는 현재 코드에 연결한 자료와 추가 연동할 자료를 구분한다. 추가 데이터의 적용 여부는 별도 후보 조사에서 문제와의 관련성·공개 범위·최신성을 비교해 정한다. 현재 실제 데이터는 허브859 병원 공개 표본,327 연결 최신 택시 공식파일,254 돌봄 공개 표본과1304 연결 제주시 공공보건 공식파일이다. 공식 병원동행·교통약자 안내2건은 별도 보완 출처다. 전체 운영 API·실시간 수용·빈차·동행인 배정 정보는 사용하지 않는다.

### 2026-10-31 데이터 도구의 실제 활용 범위

병원 자료859는 **공개 미리보기20행을 후보 검색과 집계·품질 분석**에 사용한다. 이동·동행 데이터 도구는 최신택시34·돌봄등록19·공식안내2의55개 문의 경로를 사용한다. 대화 Agent의 도구 dispatcher와 고정 예시가 같은 snapshot·상태 엔진을 재사용하며, Sol 공개 단일 도구 실호출은 확인했으며 복합 모델 품질은 후속이다. 새 PC·모바일·AWS revision의 최종 통합 검증은 결과 기록을 따른다. `app/data/hospital-candidates.json`에는 폐업 7행을 제외한 당시 행정상 정상 13개 기관의 최소 사실(기관명·주소·등록 과목·행정 상태·행별 시점)과 출처를 변환해 둔다. 원문 CSV·전체 행 파일은 저장하거나 제공하지 않는다. `app/data/datahub-profile.json`에는 기관명·주소 없이 20행 집계를 둔다. 기본 공개 표본을 이용하는 데 별도 사용권이나 파일 업로드를 요구하지 않는다. 전체 운영 API 연결이나 현재 제주 의료기관 현황을 확보한 것으로 표시하지 않는다.

| 실제 계산 결과 | 의미 |
| --- | --- |
| 표본 20행, 영업/정상 13행, 폐업 7행 | 과거 행정 상태. 지금 진료 중인 기관 수나 임상 후보 수가 아님 |
| 주소 20/20행(100%), 진료과목 19/20행(95%), 과목 결측 1행 | 공개 미리보기 항목의 완전성 |
| 행별 갱신 범위 2018-08-31~2024-08-10 | 폐업 포함 20행 기준. 최신성 확인이 필요함 |
| 모든 행의 수집일 2024-10-17 13:53 | 페이지 표기 수집기간 2025-09-18~23과 구별 |
| 등록 과목 빈도 | 폐업 포함 표본 전체에서 행별 중복 과목을 제거한 빈도. 환자 적합성·의료가능 평가가 아님 |

공개 응답 URL은 `https://jejudatahub.net/api/data/view?id=859&userId=`이며 실제 응답의 최상위 `id:859`, `title`, `csvData`를 확인했다. 운영 proxy·인증키·내부 사설주소는 호출하지 않는다. 조사에는 insane-search와 공개 SPA 브라우저 렌더링을 사용했다. [공공데이터포털 연계 항목](https://www.data.go.kr/data/80428/linkedData.do)은 같은 설명과 허브 859 URL을 제공하지만 이용허락범위 값은 비어 있었다.

[공개 이용약관](https://jejudatahub.net/signup/step1)의 출처·지침 준수와 통계정보 활용 조항을 확인했다. 현재 결과물은 출처·시점이 있는 최소 기관 사실 변환과 집계이며, 자유 라이선스·전체 원자료 재배포·공적 승인을 확인했다는 주장을 하지 않는다. 개별 라이선스 표시, 전체 운영 API 조건, 센터 내 분석·반출 지침의 적용은 별도로 확인한다.

재현 명령:

```bash
node scripts/datahub-profile.mjs --fetch
node scripts/datahub-profile.mjs --input /path/to/허브 859-메타데이터.json --output /tmp/datahub-profile.json
```

첫 명령은 공개 메타데이터·미리보기만 메모리에서 읽어 집계와 최소 기관 사실 후보를 모두 재생성한다. 원문 전체는 저장하지 않는다. 두 번째는 같은 응답 구조의 기존 파일에서 집계와 같은 디렉터리의 `hospital-candidates.json`을 재현한다. `fetchedAt`/후보의 `retrievedAt`은 실제 조회 시점이고 `generatedAt`은 집계 생성 시점이다. 파일 입력에 원조회 시각이 없으면 조회 시각을 빈 값으로 두어 생성 시각을 조회 시각으로 가장하지 않는다. `--fetch`와 기존 캐시 `--input`을 실제 실행하고 결과를 대조했다.

개발용 `/workspace.html`의 사용자 파일 가져오기는 JSON 행 배열 또는 UTF-8 CSV(2MiB·10,000행 이하)를 브라우저 메모리에서 정규화한다. BOM·인용 쉼표·이스케이프 따옴표·셀 내 줄바꿈과 한글/영문 헤더를 처리하고, 잘못된 열 수·중복 헤더·지원하지 않는 스키마·계정키 유사 열을 거부한다. 서버 전송·영구 저장·운영 API 인증을 하지 않으며 출처는 항상 `user-import`, `apiVerified:false`다. 일반 파일이 허브 원자료라고 자동 인증하지 않는다.

수동 개발 화면의 선택 기관은 기본 공개 미리보기 또는 사용자 파일의 등록정보·출처로만 반영한다. 대화 Agent 도구는 서버의 공개 후보와 사용자가 현재 요청에서 명시한 기관을 사용하며, 임의 클라이언트 caseState·사용자 파일을 모델 검증 없이 신뢰하지 않는다. 기본 후보의 `source.candidateOrigin`은 `public-preview`, 사용자 파일은 `user-import`로 구별한다. 로딩 시 허브 URL·ID859·20행 이하 표본·정상 상태·조회 시점과 기관별 출처를 검증한다. 선택 변경 시 제주 문의를 문의 전으로 되돌리고 기존 검토·접수를 무효화하되 의료자료·도외 문의·위임은 보존한다. 등록 과목을 임상 적합성·협진 참여로 변환하지 않는다. 생성 보고서에도 자료의 출처·2024년 수집 시점과 운영 미확인 상태를 남긴다. 원문 전체 내보내기 기능은 제공하지 않는다.

### 수집·전처리·분석 흐름

1. 지정 목록·센터 명세 확인처와 허브 859 상세 항목을 대조한다.
2. 공개 메타데이터·미리보기 응답을 조회해 ID·제목·행 구조를 검증하고 출처·조회시점·행별 날짜를 기록한다. 인증키·운영 API는 호출하지 않는다.
3. 기관명·주소의 공백과 표기를 정규화한다. 기관명만으로 병합하지 않고 주소와 가능한 식별정보를 대조한다.
4. 진료과목 문자열을 분리하되 원문을 보존한다. 결측과 표기 불일치를 기록한다.
5. 행정 상태·지역·진료과목으로 후보를 조회하고 검색·제외 이유를 남긴다. 오래된 상태나 결측으로 환자 진료 불가를 확정하지 않는다.
6. 현재 전화번호는 데이터에 없으므로 만들지 않는다. 실제 발신 연동 시 공식 기관 연락처와 진료 안내를 별도로 대조한다.
7. 후보 선택을 제주 문의 대상과 보고서에 연결한다. 기관 변경 시 제주 문의·검토 접수 상태를 초기화하고 기록을 보존하는지 검사한다.

분석 단위는 의료기관과 협진 요청의 운영 요건이다. 기관 데이터와 환자 기록을 기관명만으로 결합하거나 병상 수와 비용으로 환자 중증도를 추정하지 않는다. 어댑터의 합성 경계값 검사와 실제 공개 snapshot의 로딩·선택 검사를 구분한다. 표본 20행을 전체 제주 의료기관 현황으로 확대하지 않는다.

## 2. 환자 기록과 의학적 근거

2026-11-08 사용자가 승인한 더미데이터는 `app/data/fhir-demo-bundle.json`에 직접 작성한 FHIR R4 collection Bundle이다. 가상 환자·기관·외래 방문·치료 이력·판독문·체온·과거 복약의7개 리소스이며 실제 환자·공공데이터셋·건강정보 고속도로 수신 자료가 아니다. `app/health-records.js`가 같은 환자의 출처·작성일·현재 준비 여부를 읽고, `request_records(source=demo)`가 보유 치료 이력·판독문을 기존 reducer에 연결한다. 새 진찰·의뢰서나 새 DB 원문 저장은 추가하지 않는다. 예제는 프로젝트에서 작성했으며 외부 환자 자료의 사용권을 추정하지 않는다. 기준 문서와 검증 범위는 [합성 FHIR 계약](fhir-demo-contract.md)을 따른다. 기존 허브 계보4종의 활용 수에 합산하지 않는다.

현재 시연은 **암 치료 후 추적 진료를 준비하는 합성 사례**를 예시로 삼는다. 구체 암종·병기·치료 단계와 실제 협력 의료진은 아직 정하지 않았다. 과거 정형외과 수술 후 외래 초안은 현재 확정 대표 사례가 아니다. 치료 이력·판독문·현지 대면 진찰 소견·의뢰서·의료진 회신의 출처를 따로 보존하며, 새 진찰이나 검사 기록을 Agent가 작성하지 않는다. 제주 공개 카탈로그가 개인 환자의 임상 기록을 제공한다고 가정하지 않는다. `request_records`의 `nhis` 경로는 승인 어댑터 미설정 상태를 반환하고 `demo`만 고정 합성 기록을 읽는다. [건강정보 고속도로 API 안내](https://myhealthway.go.kr/portal/index?page=Individual%2FPortal%2FMediMyData%2FMydataApi)와 [개발기관 절차](https://myhealthway.go.kr/portal/index?page=Login%2FRegPart)는 본인인증·제공/활용 동의·승인 연계가 필요한 별도 경로다. 실제 공단 인증·조회·연결을 수행하지 않았다.

초기 문서는 모두 합성임을 내용·화면·보고서에 표시한다. 문헌은 용어 이해와 의료진에게 확인할 질문의 준비 자료다. 암종과 치료 단계가 정해지기 전에 암종별 추적 간격·검사·도외 방문 조건을 일반 규칙으로 만들지 않는다. 임상 근거 선정과 환자별 적용은 협력 의료진 검토 대상으로 남긴다.

병원 답변은 기관·질문·답변 부서/역할·시점·조건을 단위로 기록한다. 공개 진료과 정보, 접수 창구의 안내, 의료진의 환자별 검토, 예약 확정의 근거를 구분한다. 답변은 문의 당시 정보이며, 미래의 검사·예약·치료 가능성을 보장하지 않는다.

## 5. 이동·숙박·동행

이번 방문은 공개 택시·돌봄 문의처와 공식 서비스 소개를 지역·지원조건에 연결해 준비한다. 실제 배차·동행인 배정·항공·숙박·경로·결제 API는 연결하지 않았다. 비용 계산은 여전히 사용자 가정이며, 문의처 연락정보를 개인 견적이나 확인된 이동시간으로 바꾸지 않는다. 단일 방문의 지원 준비와 반복방문 횟수의 예산 가정을 구분한다.

여행 견적에는 조회일·이용일·왕복/편도·인원·수하물·세금 등 포함 범위를 기록한다. 가족 각자의 출발지와 동행 가능일을 따로 받는다. 같은 차량·객실을 공유하는 비용을 인원별로 중복 합산하지 않는다.

동행 서비스는 비용과 서비스 제공 지역·시간·이용 가능 여부를 따로 확인한다. 공개 서비스 소개나 예산 입력은 해당 방문의 동행 예약 확정을 뜻하지 않는다.

## 8. 대회 요건과 재현 기록

[공식 대회 안내](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)와 [공개 응답](https://daker.ai/api/hackathons/jeju-ai-bigdata-agent-challenge)을 확인했다. 필수 데이터 1종 이상 실질 활용, 15페이지 이내 기획서, 코드·실행환경·데이터 명세·결과 설명 ZIP, 센터 최소 사양과 마감을 PRD에 반영했다. 규정과 이용조건은 제출 전에 다시 확인한다.

원자료·전처리·근거 문헌·급여 규칙·견적·프롬프트·모델·코드·보고서 입력의 버전을 남긴다. 제출 가능한 자료의 범위와 재취득 절차를 명시하고 인증정보를 제거한다. 합성 환자·테스트 통화·가정 견적·실제 공공데이터를 구별한다.

insane-search의 `weak_ok`는 본문 검토의 출발점으로 취급했다. 제주 화면은 브라우저 렌더링으로 공개 텍스트·응답을 보완했고, 새 비용 설명·음성 문서는 insane-search 본문에서 확인했다. 실제 원자료·API·통신 연동·개별 환자의 임상 적용은 위 각 항목의 확인 상태를 따른다.

## 10. 진료 준비용 분류 카탈로그·코드 계산

이 기능은 기존 감사자료를 재사용한 읽기 전용JSON/CSV 저장소다. 새 원자료1,329종을 수집하거나 새로운 실시간 API·관리형DB를 연결한 것이 아니다.

| 저장 구분 | 파일·범위 | 사용 방법·한계 |
| --- | --- | --- |
| 분류 카탈로그 | `app/data/public-data-catalog.json`; 허브 목록1,259·센터 명세70=1,329건, 공식안내2건 별도 | 제목·의료/돌봄/이동 폴더·태그·항목·공식URL·조사 상태로 관련 최대8건 검색. 목록 수정일≠원자료 기준일 |
| 계산·후보 snapshot | 병원859·택시327·돌봄254·공공보건1304와 별도 공식안내2건 | 데이터셋4종+공식안내2건이다. 병원은20행중 정상13개·돌봄19개·택시34개·제주시공공보건35개. 메타데이터만 있는 자료를 계산에 섞지 않음 |
| 공통 계산 모듈 | `app/public-data-skill.js` | 주소기준 지역 집계·중복/폐업 제외·분모·결측, 지원 후보/질문과 유효한 문의준비 제안. 개인 진료기록 미사용 |
| Agent 어댑터 | `agent/public-data-tools.mjs` | 고정 schema·허용 공식HTTPS출처 검증. 임의SQL/URL/경로 없음, 사례 상태 불변·query를 새 로그/세션필드에 저장하지 않음 |

병원 데이터의 공통 원자료 기준일은 미확인(null)이며 원자료 수집2024-10-17, 행별 갱신 범위와2026-10-31 공개응답 취득일을 따로 보존한다. 도구의 `coverage.collectedAt`은 저장 snapshot 취득일이고 원자료 수집일은 `coverage.label`에 표시한다. 병원/돌봄 비교는 관측 등록 주소 기준의 부분 집계다. 서귀포 병원 관측0행을 실제 시설 부재로 해석할 수 없다. 읍면동이 미표기된 돌봄12행은 읍면동 집계 분모에서 빠지며, 시 비교에서는 시를 알 수 있는19행을 사용한다. 읍면동과 시를 섞으면 각 해상도/분모를 따로 반환하고 비율의 직접 비교를 제한한다. 기관 수로 질적 우열·환자 적합성을 판단하지 않는다.

센터7도로망·8노드·10시간대별 평균소요시간은 항목 명세만 확인했다. `travel_time`은 unavailable·수치/평균/ETA 없음과 필요한 원자료·택시 문의 질문을 반환한다. 웹 설명이나 목록 수정일만으로 이동시간을 계산하지 않는다.

```bash
npm run data:catalog -- --check
npm run data:query -- search --purpose taxi --query 택시
npm run data:query -- analyze --analysis facility_compare --areas 제주시,서귀포시
npm run data:query -- analyze --analysis facility_compare --areas 애월,서귀포
npm run data:query -- analyze --analysis support_candidates --area '제주시 애월읍' --wheelchair true
npm run data:query -- analyze --analysis travel_time --area '제주시 애월읍'
```

`--check`는 보관한 `research/datahub_catalog_screening_2026-10-31.csv`와 `research/center_schema_index_2026-10-31.csv`에서 색인을 재생성해 현재JSON과 대조한다. 이 검사는 네트워크/API/raw갱신이 아니다. 원자료 갱신은 앞 절의 `datahub-profile.mjs --fetch`와 확인한 공개파일 취득·`support-data.mjs` 변환 절차를 따른다. 새 자료는 이용조건·항목·시점·저장 범위를 확인하고 loader를 등록해야 계산 가능하다. 목록·공식URL의 보관이 원자료 전체 재배포 허락을 뜻하지 않는다.
