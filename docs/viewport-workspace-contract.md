# 한 화면 작업 공간 계약

기준 `ea4aca5`. 최신 사용자 요청: 혼디 심볼·이름·‘진료 준비 도우미’ 소개 블록을 삭제하고, 배율·해상도에 따라 과하게 달라지는 여백을 정리해 한 화면 안에서 작업한다. 이전 대화 상단 identity·자연 문서 스크롤·모바일 전체 카드 세로 쌓기보다 이 계약을 우선한다.

## 배치

- 소개 블록은 DOM과 전용 CSS에서 제거한다. 대화 영역의 접근성 이름은 유지하며 기존 예시 보기·넓게 읽기 기능을 작은 공통 도구 영역으로 옮긴다. 왼쪽/모바일 홈 로고와 답변의 기존 심볼은 이 요청의 삭제 대상이 아니다.
- 기본 앱은 `100dvh` 안의 작업 공간이다. 주요 컨테이너는 `min-height:0`·grid/flex로 남는 공간을 분배한다. 페이지를 늘리는 채팅 최소높이 calc·viewport 여백·고정 중앙 최대폭 때문에 생기는 큰 빈 공간을 제거하고 일정한 약12~16px 여백을 사용한다. transform scale·CSS zoom·글자 자동 축소·배율 추정 JS는 쓰지 않는다.
- PC는 중앙 대화와 오른쪽 네 준비 요약을 유지한다. 대화 이력은 중앙의 한 스크롤 영역, 공통 입력은 작업 공간 하단에 계속 보인다. 오른쪽 카드는 각각 내부 스크롤을 갖지 않고, 펼친 전체 근거/기록·방문 상세는 같은 오른쪽 영역에서 읽는다. 초기 닫힌 네 요약은 일반 PC 높이에서 함께 확인한다.
- 폭900px 이하 또는 높이650px 이하에서는 ‘대화 / 준비 현황’으로 작업 영역을 전환하고 공통 입력은 유지한다. DOM/ID/입력·상태를 복제하지 않으며 탭을 바꿔도 초안·열림·읽기 위치를 보존한다. 비활성 영역은 키보드/접근성 탐색에서 제외한다. 설정은 기존 서랍을 유지한다.
- 요청 예시·긴 도움말은 필요한 때 펼쳐 높이를 확보할 수 있다. 예시는 입력 가까이에서 찾을 수 있고 직접 선택하면 보이는 문구만 초안에 넣는다. 고지·전체 누락·근거·설정/저장·방문 상세를 삭제하거나 접근할 수 없게 숨기지 않는다. 기존 native details/dialog를 우선 재사용한다.
- 배율로 가용 공간이 줄면 같은 반응형 규칙으로 전환한다. 본문16px·44px 주요 조작·기존 대비/색/가시 포커스를 유지한다. 실제 기기·가상 키보드·다른 브라우저·임의의 모든 크기에 대한 검증을 주장하지 않는다.

## 보존할 동작

API·Agent·공공데이터·state schema·공통 진행 정규화·위임·실제/합성 경계는 그대로다. 단일 텍스트/음성 입력과 초안 교체 확인, pending/취소/재시도/late/새 대화, 넓게 읽기 복사본과 복귀, 전화/기록/여정 창을 보존한다. 대기 중지·오류·새 답변은 현재 작업 영역에서 발견하고 선택할 수 있어야 한다. 준비를 읽는 중 최종 응답은 자동으로 읽는 곳을 바꾸지 않는다.

출처는 동일 DOM·focus·펼침과 viewport 위치를 보존한다. 기존 보정 함수를 새 공유 스크롤 영역에 맞추며 body 스크롤만 바꾸는 방식으로 끝내지 않는다. 비활성 탭에서 새 답변 알림을 선택하면 대화가 열리고 해당 답변으로 이동한다. 새 별도 모델·타이머·가짜 진행을 만들지 않는다. 모션은 기존 짧은 제어/메타 피드백과 reduced motion 대안을 유지한다.

## 소유권과 검증

- UI: `app/conversation.js`, `app/conversation.css`, `app/preparation-board-view.js`, 필요한 경우 기존 `app/icons.js`. 오래된 배치 규칙을 교체하며 override나 일반 UI 프레임워크를 추가하지 않는다.
- QA: 기존 `scripts/conversation-browser-check.mjs`, `scripts/journey-browser-check.mjs`, `scripts/preparation-board-browser-check.mjs`. 페이지 스크롤/identity/모바일 세로 쌓기 단언을 이 계약의 실제 기하·접근·전환에 맞춘다. SHA/실제 preview/일반 POST0·임상 false·취소/음성/전체 누락/출처 DOM/표 키보드의 원래 검증 목적은 유지한다.
- 통합: 문서·하네스·배포. 동일 동결 소스의 기존 네 브라우저 검사와 단위/빌드·규칙 eval 후 현재 CI로 게시한다. 실제 유료 모델/전화/개인기록을 이 UI 작업에서 호출하지 않는다.

가용 CSS 크기는 최소 `1800×1125`, `1440×900`, `1152×720`, `960×600`, `720×450`, `1060×900`, `390×844`, `390×500`, `320×500`, `768×512`를 확인한다. 앞의 다섯 크기는1440×900 화면의80/100/125/150/200%에서 줄어드는 공간에 대응하는 검사이며, 브라우저 확대 UI를 실제 조작한 증거와 구분한다. 초기/장문 응답/12줄 입력/실제 keyless preview/펼친 근거/진행·최종·취소/탭과 키보드 접근에서 앱 경계·페이지 가로/세로 넘침·입력/중지·내용 도달·같은 출처 읽기를 관측한다. `documentFlow` 같은 기존 proof 이름을 새 계약과 같은 뜻으로 쓰지 않으며 `viewportFit`/`sharedComposer`/`scrollRegions`/`compactPanels`에 해당하는 새 증거를 남긴다.
