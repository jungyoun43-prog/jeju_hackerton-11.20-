# 답변 선택으로 이어가는 합성 체험

2026-11-15 · 사용자 승인 범위: 정해진 답변을 선택하면 실제 준비 상태와 도구 실행이 이어지는 해커톤 체험. 자유 입력의 LLM 경로는 보존한다.

## 흐름과 경계

첫 화면에서 `방문 준비 시작`을 누르고 자료 보유 → 병원 접수 → 이동 조건 → 일정 확인의 네 질문에 답한다. 각 질문은 선택지 두 개를 제공한다. 선택에 따라 기존 도구 실행기가 공개 자료를 조회하고 기존 reducer로 자료·문의·이동·동행 상태를 갱신한다. 마지막에는 준비표와 보호자·기관·의료진에게 남은 일을 보여준다.

고정 판독문 보유/미확보, 제주 접수 안내/거절, 일반 택시/휠체어, 현재 일정/14시 변경을 지원한다. 자료 부족과 거절을 뒤 단계에서 지우지 않는다. 일정 변경은 기존 차량·동행 안내를 재확인으로 바꾼다. 체험 종료는 실제 진료 준비·예약·배차 완료가 아니다.

기존 `/api/agent/preview`에 `scenarioId: guided-visit`와 최대 네 개의 고정 선택 ID 배열 `answers`를 보낸다. 서버는 순서·허용값·길이·추가 키를 검증하고 고정 합성 상태에서 선택 이력을 재생한다. 클라이언트 상태·자유 텍스트·환자정보·도구 이름·외부 URL을 받지 않는다. 모델·Secrets Manager·DB·예산·외부 발신을 사용하지 않는다. 재요청도 같은 의미의 합성 상태를 반환한다.

응답의 `guidedDemo`는 `answers`, `stepId`, `title`, `detail`, `choices`, `complete`다. 공통 `app/guided-demo.js`에서 단계와 선택을 정의한다. 본래 업무의 준비 여부는 기존 `getPreparationWorkflow`로 계산하며 체험 단계 번호와 합치지 않는다. LLM 연결은 현재 모델 품질 미검증 상태를 유지한다.

## 화면과 복구

후속 ego lite 실사용 보완: 시작 전에는 네 단계의 용도를 안내하고 실제 응답 전 진행·잔여 건수를 표시하지 않는다. 질문 설명과 앞선 선택 결과를 분리하며, `준비 현황과 근거`는 동일한 단계 DOM을 native details로 펼친다. 단계 탐색을 누르거나 최종 준비표에 도달하면 해당 상세를 연다. 체험 중 같은 textarea는 짧은 읽기 전용 안내로 유지하고 비활성 음성·전송·글자 수를 숨긴다. 자유 입력으로 전환하면 원래 조작을 복원한다. 상단 일괄 예시의 표시명은 `결과 예시`다.

현재 작업 영역에 질문과 답변 선택을 두고 기존 우측 네 단계·출처·기록을 재사용한다. 선택은 즉시 명시된 합성 실행을 수행한다. 체험 중 자유 입력은 읽기 전용이며 `자유 입력으로 전환`으로 전환한다. 전환 시 기존 확인 절차로 초기화하고 체험을 실제 세션에 섞지 않는다.

응답 전에는 기존 상태를 유지한다. 중복 클릭을 막고 실패/중지 뒤 같은 선택을 다시 실행할 수 있다. 늦은 응답은 기존 request 소유권 검사로 무시한다. 체험 답변·환자정보를 localStorage/sessionStorage에 추가 저장하지 않으며 새로고침 시 체험은 처음부터다. 최종 준비표 저장은 기존 Markdown 내보내기를 재사용한다.

## 작업 소유권과 검증

- `guided-demo-engine`: 신규 공통 체험 정의·합성 실행기·검사, preview/validation/service 연결. 전용 `feature/guided-demo-engine` 브랜치.
- `judge-polish`: UI·접근성·문구·중복 유틸 정리, 문서·검사·하네스. 전용 `refactor/judge-polish` 브랜치.
- 시각 A와 기술 B: baseline을 독립 읽기 전용 평가. 통합 담당자가 실제 최종 PC·모바일을 사용하고 단일 gate 검토 후 커밋 단위로 반영·push한다.

검증은 선택 조합, 잘못된 순서/초과/클라이언트 상태 거절, 실제 HTTP와 브라우저의 4단계 완주·실패·취소·재시도·상태/출처·저장·키보드·작은 화면을 포함한다. 과거 모델·기기 검증을 이번 버전의 통과로 재표기하지 않는다. 회귀는 해당 커밋의 revert로 되돌린다.
