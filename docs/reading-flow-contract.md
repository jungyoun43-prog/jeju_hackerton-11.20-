# 혼디 단일 페이지 읽기 UI

2026-10-31 배치 이력. 내부 스크롤 제거 요청을 그리드 삭제로 잘못 해석해 작성한 계약이다. 사용자는 2×2 자체가 없어졌다고 정정했다. 현재는 [2×2·문서 스크롤 계약](grid-flow-contract.md)이 우선하며 아래 단일 본문 배치는 이전 구현 이력으로만 보존한다. ○·△·×와 내부 세로 스크롤 제거 원칙은 유지한다.

## 구성과 시각 방향

- PC·모바일 모두 대화·답변이 주 본문이다. 각 결과 창의 고정/최대 높이와 내부 세로 스크롤을 제거한다. 답변과 준비 내역을 펼치면 문서 높이가 늘어나고 페이지를 스크롤한다. 작은 창·읽기 탭을 옮기며 답변을 찾게 하지 않는다.
- 위에는 자료·병원·이동/동행의 세 가지 상태만 얇은 한 줄로 요약한다. 작은 모바일에서는 자연스럽게 배치한다. ○는 자료/문의 준비 결과 있음, △는 미확인/부분 준비/재확인, ×는 실제 기록된 문의 실패/사람 인계다. 문의 전·필요 없음은 중립 대시다. 색과 함께 글자로 의미를 설명한다. ○를 진료·예약·배차 확정으로 표현하지 않는다.
- 요약 아래 준비 내역은 기본으로 접힌 native details다. 세 항목의 사실·누락·출처·처리 기록을 문서 흐름으로 펼친다. 요약 버튼은 해당 내역을 여는 읽기 동작이며 API를 호출하지 않는다. 펼침·포커스·읽기 위치는 진행 갱신만으로 바꾸지 않는다.
- 대화·답변과 공통 입력 하나를 같은 문서 흐름에 둔다. 답변은 전부 읽을 수 있고 긴 표만 가로 스크롤한다. 기존 읽기 확대는 선택 사항이며 답변을 읽기 위한 필수 과정이 아니다. 긴 입력칸·사용자가 연 기록/전화/여정 native dialog·설정 서랍의 표준 스크롤은 보존한다.
- 로고·인물 없는 제주 배경·Pretendard는 유지한다. 작업면은 밝은 중성/슬레이트, 본문은 짙은 청색, 주 행동·포커스는 절제된 파랑으로 정리한다. 녹색 ○·황갈색 △·붉은 ×는 상태에만 쓰고 모양·텍스트를 함께 제공한다. 큰 풍경 배너·반복 카드·큰 강조 상자를 추가하지 않는다.
- 새 답변의 시작을 페이지에서 읽을 수 있게 한다. 응답 대기와 실제 관측 진행을 구분하고, 사용자에게 필요한 다음 확인 한 가지를 우선 보여준다. 미확인 자료·합성 응답·현재 연결 범위를 숨기지 않는다.

## 공유 모델·DOM과 파일 소유권

- root: `app/preparation-stages.js`의 signal과 관련 단위 검사·문서·하네스·통합·배포. signal은 available/attention/blocked/waiting/not_needed이며 기존 status와 저장 상태는 바꾸지 않는다.
- reading-ui: `app/conversation.js`, `app/conversation.css`, `app/preparation-board-view.js`. 기존 함수·DOM id·도구·전화/기록 dialog·요청/취소/재시도/음성 경계를 보존한다. 기존 격자 CSS를 교체하며 override를 계속 덧붙이지 않는다.
- reading-qa: `scripts/conversation-browser-check.mjs`, `scripts/journey-browser-check.mjs`, `scripts/preparation-board-browser-check.mjs`. 새 읽기 흐름에 맞게 배치/스크롤 단언을 바꾸고 기존 권한·원문·상태·실제/시연·취소·접근성 검사는 보존한다.
- DOM: `#stage-navigation`은 records/hospitals/support 요약 버튼, `#preparation-details`는 접힌 내역이다. 기존 네 `[data-stage-id]`와 사실/이력/출처 선택자는 유지한다. 앞의 세 항목은 준비 내역, plan은 항상 읽는 본문이다. `#conversation-scroll`은 이름을 보존하되 자체 세로 스크롤 없이 문서에 표시한다. `#preparation-board`·`#board-activity`·공통입력·고지·기존 dialog id도 유지한다. 기호의 상태는 `[data-signal]`, 모양은 접근 가능한 SVG 또는 사용자 지정 기호와 텍스트로 표현한다.

## 검증과 끝맺음

PC1440×900/1280×800, 모바일390×844/360×780/390×500/768×512, 긴 답변·입력·표·200%글자에서 주요 내용을 페이지로 읽는다. 준비내역/답변/방문상세의 내부 세로 스크롤과 잘림을 검사한다. 펼침이 문서 높이를 늘리고 답변 첫 문장부터 마지막까지 페이지 스크롤로 도달해야 한다. 의미 색의 대비·44px 조작·키보드·포커스 복원·실제 미리보기와 진행 갱신·문의 실패 인계를 확인한다.

API·모델·데이터·개인기록·실제전화·의료 판단 범위는 바꾸지 않는다. 단위·화면 검사와 실제 모델·마이크·기관 연계는 구분한다. 최종 실화면 독립 검토 후 DESIGN.md/sidecar를 현재 구현에 맞추고 검증한 버전을 기존 CI/CD로 배포한다. Impeccable context launcher126은 직접 문맥 읽기로 보완하며 자동 디자인 통과로 보고하지 않는다.
