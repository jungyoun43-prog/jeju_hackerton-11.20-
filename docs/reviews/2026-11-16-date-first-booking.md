# 날짜 우선 예약·외부 교통 접수 UX 검증

## 바뀐 동작

- 접수 조건 다음에 의료진을 먼저 고르던 단계를 없애고, 월간 달력의 하루/기간으로 가능한 의료진·시간을 비교한다. PC는 달력 옆 결과, 모바일은 같은 DOM의 순차 흐름이다.
- 기간 시작/종료·역순·월/연도 전환, 미완료 기간, 마감/미공개/빈자리 없음, 날짜 조건 변경 후 선택/교통 체크 초기화를 처리한다.
- 항공권은 희망 진료일의 전날/당일, 직접 수정한 출발/귀가일과 성인 인원으로 스카이스캐너에 연결한다. 귀가 미정은 편도이며 역순 날짜는 검색 링크를 막는다.
- 버스/택시/교통약자 차량에 따라 공식 노선·앱 예약 안내·전화·제주 즉시콜·서울 콜접수 창구를 다르게 보여준다. 등록·자격·접수/배차의 차이를 보존한다.
- 큰 체크박스 사각형을 20px 표시 + 44px 조작 영역으로 분리하고, 체크 표시·라벨·키보드 초점을 정렬했다. 긴 체크 목록보다 항공권 검색과 실제 문의/접수 창구를 먼저 둔다.

`output/date-first-qa/verification.json`, `output/appointment-react-qa/summary.json`, `output/guided-demo-qa/summary.json`, `orchestration/runs/conversation-browser.json`에 현재 결과가 있다. 선택 Playwright 모듈은 로컬 npm cache의 설치본을 `PLAYWRIGHT_MODULE`로, 기존 Chrome을 `CHROMIUM_PATH`로 지정했다. 새로운 브라우저 패키지나 서비스는 설치하지 않았다.

## 실제 ego lite 관측

PC·모바일 스크린샷을 직접 열어 확인한 뒤 한 번의 수정 묶음으로 달력/결과 병렬 배치, 병원 맥락 표시, 중복 오류 문장과 첫 입력 시 불필요한 재확인 경고를 정리했다. 최종 `final-date-desktop.png`, `final-date-mobile.png`, `final-flight-desktop.png`를 확인했다. 체크박스의 전후 원본도 `output/date-first-qa/`에 있다. 브라우저 viewport 관측을 실기기 검증으로 확대하지 않는다.

혼디의 실제 항공권 버튼을 눌러 외부 새 창이 열리고 제주→김포·12월 7일·성인 1명·편도 조건이 반영된 원문 화면까지 확인했다. 별도 왕복 링크의 출발/귀가 날짜도 공식 사이트에서 확인했다. 가격 결과는 검색 중이었으므로 실운임·최저가·좌석 확인을 주장하지 않는다. 제주/서울 접수 링크는 공식 로그인 화면까지 확인했으며 로그인하지 않았다.

## Impeccable

이번 `context` 실행은 성공했다. `distill`·`operate`·`craft-floor`를 적용하고 기계 검사를 1회 수행했다. 색·반경·글자 크기 및 기존 글꼴 선언의 디자인 문서 불일치가 보고되어 detector 전체 통과로 표시하지 않는다. 부수적인 디자인 sidecar 정리/스킬 업데이트는 수행하지 않았다. [계약](../date-first-booking-contract.md)과 [공식 창구 조사](../../research/booking-handoffs-2026-11-16.md)를 따른다.

로컬 미리보기만 갱신했다. 공개 배포·실제 의료진 빈자리·본인인증·기관 예약 결과·실시간 교통/항공 운임·외부 접수 완료의 자동 수신은 미연동이다.
