# 혼디 기능 파이프라인

작성일: 2026-10-31 · PRD v0.14 · 대화 UI·AWS Sol·전화 협진/휠체어 준비·내부 공공데이터 스킬

**보호자가 말한 요청에서 병원·자료·택시·동행 준비가 이어지고, 무엇을 확인했고 무엇이 남았는지 설명한다.** 진찰·검사·진료 장소·치료 계획은 의료진이 판단한다.

## 1. 현재 실행 경로

| 경로 | 실제 동작 |
| --- | --- |
| 텍스트·브라우저 음성 → 일반 API | `POST /api/agent`. 키 설정 시 기본Sol/선택Terra 도구 루프. 키 없는 로컬은 `MODEL_NOT_CONNECTED`/503·입력 복원. AWS는 Sol·DynamoDB 연결 |
| 대화 흐름 미리보기 | 별도 `POST /api/agent/preview`. 고정 scenarioId의 공개 snapshot 검색·도메인 상태 변경·합성 문의 실행. `isPreview:true`·작성된 예시·`llm:false` 유지 |
| 공급자 주입 → 도구 루프 | `createAgentService({provider})`. 구조화된 tool-use를 검증하고 허용 도구 실행. 단위검사는 mock fetch이며 실제 Sol 호출은 별도 실행 증거로 구분 |
| 기존 수동 UI | `/workspace.html`. 조건·자료·합성 응답 분기·변경을 직접 검사하는 개발용 화면 |

고정 예시는 자유 입력을 해석하지 않으며 일반 세션으로 이어지지 않는다. SDK 설치·모델 목록·환경값을 실제 모델 연결 성공으로 간주하지 않는다. Bedrock 실호출은 계정 Error 002로 차단됐으며 추가 시도를 중단했다.

## 2. 요청에서 처리 기록까지

> “서울에 사는 딸입니다. 애월 어머니의 11월 12일 진료 준비를 해 주세요. 저는 동행하지 못하니 택시와 병원 동행도 알아봐 주세요.”

완성 서비스의 주 동선은 **요청 → 기존 사례 확인 → 부족한 핵심 정보 질문 → 데이터·준비 도구 → 결과·출처·다음 행동 → 변경 시 재확인**이다. 보호자가 같은 내용을 기관·자료·택시 폼에 다시 입력하지 않는다. 아래 도구는 고정 예시 또는 주입한 공급자가 호출할 수 있다. 실제 외부 행위는 시연·미연결로 구분한다.

| 단계 | 도구·처리 | 현재 결과와 경계 |
| --- | --- | --- |
| 사례 확인 | `get_case`, `update_visit` | 합성 사례의 방문일·시각·지역·동행/휠체어 조건. 실명·상세주소·임의 의료기록은 도구 입력으로 받지 않음 |
| 필요한 데이터 찾기·계산 | `search_public_data`, `analyze_public_data` | 의료/돌봄/이동 분류 목록→필요snapshot→코드집계·출처/시점/분모/결측→문의 제안. 읽기 전용이며 비교로 방문 조건을 덮어쓰지 않음 |
| 병원 문의 대상 | `search_hospital_contacts`, `select_hospital_contact` | 허브859의13개 등록 후보. 사용자가 현재 요청에 명시한 기관을 선택하며 임상 적합성·현재 수용 추론 금지 |
| 자료 확인 | `request_records` | `nhis`는 승인 어댑터 미설정 반환. `demo`는 서버의 고정 합성 자료만 준비. 본인인증·조회 완료를 가장하지 않음 |
| 양기관 문의 | `request_hospital_contact` | 병원 역할의 합성 접수·자료 안내. 실제 발신·의료진 참여 확인 아님 |
| 이동·동행 후보 | `find_support` | 327 최신택시·254 과거돌봄·별도 공식안내를 지역/지원 유형별로 조회. 현재 가능일·차량·동행인 미확인 |
| 문의 준비 | `prepare_inquiries` | 현재 조건의 공개 문의처와 질문·초안을 연결. 날짜·지역·기관·지원 조건만 사용하고 환자 진단·실명은 자동 포함하지 않음 |
| 지원 응답 | `request_support_contact` | 시연 어댑터의 합성 가능·불가·불통. 보호자가 응답 분기를 직접 고르지 않으며 실제 배차·배정 아님 |
| 검토·보고서 | `prepare_review`, `build_report` | 자료·절차·동의의 준비 상태, 출처·누락·다음 작업. 미수행 진찰·의뢰서·임상 결론을 생성하지 않음 |

공통 `buildCallPlan(state,target)`은 기존 도외 병원·제주 병원·택시/휠체어·동행의 질문·최소 전달·AI 고지 예정문·기록 처리 미설정·실발신 전 확인과 합성 결과를 계산한다. get_case는 요약만, 전화 도구와 시연 어댑터는 같은 전체 계획을 사용하고 UI도 같은 상태에서 읽는다. DB에 새 동의나 callPlan을 저장하지 않는다.

협진 요청은 양 기관의 행정 문의 → 자료 공백 → 실제 의료진 작성 기록과 공유·수신 절차 확인으로 이어진다. 휠체어 요청은 해당 지원 조건과 교통약자센터 문의 경로 → 자격/등록·탑승/승하차·동행·시각·차량 질문 → 미확인과 다음 행동으로 이어진다. 접수 안내·가능 응답을 실제 진료 수락·배차·예약으로 바꾸지 않는다. [전화 계약](call-workflow-contract.md)을 따른다.

모델의 도구명·인자·출처는 서버 allowlist로 검증한다. 클라이언트가 임의로 보낸 caseState를 믿고 완료 상태로 만들지 않는다. 실패·타임아웃 때 미완료를 숨기지 않으며 실제 외부 작업이 추가되면 별도 승인·수신처·영속 중복 방지가 필요하다.

## 3. 고정 예시에서 확인하는 일

미리보기는 제주우리병원·11월 12일 10시·애월·보호자 동행 불가 조건을 사용한다. 병원 등록정보, 공단 연계 미설정, 합성 기록, 양기관 접수 안내, 애월콜·동행 문의 경로, 초안과 합성 응답을 처리 기록으로 남긴다. 택시 가능 응답과 동행 연락 실패를 재현하고 실제 진찰 소견·의뢰서·동행 재확인을 남긴다.

실제 공공데이터 조회 결과와 환자·기관 역할의 합성 응답은 event의 출처·상태·`isSimulation`으로 구분한다. 이 결과를 현재 수용·예약·배차 성공으로 표시하지 않는다. 자유 대화에서 날짜가 바뀌는 과정은 현재 공급자 주입 테스트와 수동 개발 화면으로 검증하며, 실제 모델이 변경 요청을 이해했다고 주장하지 않는다.

## 4. 데이터가 다음 행동을 바꾸는 조건

| 조건·응답 | 준비 작업의 변화 |
| --- | --- |
| 애월 출발·일반 택시 필요 | 327 최신 연결 원출처의 애월 지역 문의처 우선. 왕복·픽업·운임·가능시간 질문 |
| 가족 동행 불가 | 아름동행 공식 소개와 일반 돌봄 등록을 구분해 범위·대상·서비스지역·비용 확인 |
| 애월읍 돌봄 행 없음 | 같은 시 문의처로 확장한 근거 표시. 애월 담당으로 확정하지 않음 |
| 휠체어 필요 | 차량 장비·교통약자센터 자격·회원등록 우선. 일반택시의 과거 응답 재확인 |
| 지원 불가·불통 | 미배정·미확인 유지, 재문의 또는 다른 문의처 확인 |
| 병원·날짜·지역·지원조건 변경 | 관련 응답·확인조건을 무효화하고 새 조건으로 재확인 |
| 의뢰서·자료 보완 요청 | 의료진 작성·실제 자료 보완으로 복귀. 기관 불통·미참여를 도외 진료의 임상 필요로 해석하지 않음 |

현재 구현한 허브 계보는 859·327·254 세 종이다. 공개 기관·등록 과목·대표번호는 진료 적합성·현재 배차·동행 가능 정보가 아니다. 택시는2026-03-19 기준34업체이며 허브 자체2020 미리보기45행과 섞지 않는다. 돌봄은2020-04-17 기준19개 등록이며 현재 병원동행 제공 여부는 미확인이다. 교통약자센터의 ‘동행콜’은 공동탑승 차량 개념이다.

내부 공공데이터 스킬은 같은 대화창에서 지역 비교·주변 문의처·이동시간 질문에 사용한다. 허브1,259·센터70의 메타데이터를 분류한 JSON목록과 보유 원자료를 분리하며 관련 결과만 반환한다. 집계는 코드가 수행하고 LLM은 표본·자료 시점·분모·빠진 정보를 설명한다. 병원 관측0을 지역 부재로, 돌봄 주소를 서비스 관할로 바꾸지 않는다. 센터7/8/10 원자료가 없으면 시간 수치를 만들지 않고 택시에 확인할 질문으로 연결한다. 현재 지역·휠체어 조건과 다른 탐색 결과는 문의 준비 제안을 보류하고 기존 방문 상태를 유지한다. 조건이 맞고 준비를 요청하면 기존 `prepare_inquiries`로 이어간다. 일반 준비는 providerId를 생략해 선호/지역/휠체어 규칙을 적용하고 사용자가 해당 문의처를 이번 요청에서 선택했을 때만 후보ID를 넘긴다. 새 데이터 메뉴·범용 챗봇은 없다.

후속 후보 229 전문센터·1304 관할구역·216 심야약국은 아직 코드에 연결하지 않았다. 센터7·8·10 도로망·시간대 평균소요시간은 명세만 확인했고 원자료는 미접근이다. [데이터 감사](../research/datahub_opportunities_2026-10-31.md)의 조사 수를 구현 수로 표시하지 않는다.

## 5. 상태·비용·개인정보

이번 지원 준비는 **다가오는 방문 1건**이다. 반복방문 횟수·비용·보호자 가능 횟수는 수동 개발 화면의 별도 가정이다. 실제 급여·비급여 견적·항공·숙박·경로시간 API는 없다. 미확인을0원으로 채우거나 임의 픽업시각·ETA를 만들지 않는다. 의료진 회신·검토 접수·예약 확정은 별도 상태다.

대화 원문·전체 이력·실환자 기록은 서버 로그/DB에 저장하지 않는다. 연결 후의 기본 세션 저장소는 정규화된 합성 상태를 보관하는 인스턴스별 메모리다. 미연결 일반 요청과 preview는 store에 접근하지 않는다. DynamoDB 어댑터·분산 전역 budget은 미구현이다. 브라우저 음성 인식과 전화망 발신, 공급자 주입 테스트와 실제 모델 품질을 구분한다.

## 진료 연결 여정과 변경의 전파

`get_care_journey`는 현재 상태·합성 의료진 안내·보유 문서·공개 문의처에서 세 진료 결과의 확인 여부, 원문/작성일/확인 근거를 가진 할 일, 응답 뒤의 다음 문의, 일정 변경 재확인과 데이터 적용 이유를 읽습니다. 모델이 임의 진료결과나 기록 원문을 인자로 주입하지 않습니다.

정상 요청은 기존 방문 업데이트·자료·병원·이동/동행 도구를 통해 상태를 바꾸고 이 요약을 다시 확인합니다. `run_journey_demo`는 명시적 시연 요청에서만 세 고정 상황을 실행합니다. preview API의 같은 scenarioId도 동일한 도구/reducer를 사용합니다. 기존 aewol-parent-visit15이벤트는 별도로 유지합니다.

의존 흐름은 **안내의 요구 사항 → 보유 자료 비교 → 빠진 자료 발급 절차 문의 → 제출 창구/방식 확인 → 검토 준비**입니다. 미시행 진찰/검사는 의료진이 수행해야 하며 Agent가 검사 지시·의뢰서·실제 기록을 생성하지 않습니다. **병원 시각 변경 → 기존 차량/동행 응답의 조건 불일치 → 재확인할 문의**도 같은 상태에서 계산합니다. 접수 거절은 운영 응답이고 임상 진료 경로는 의료진 근거가 필요합니다.

상세 데이터/DTO·세 상황 수락 기준은 [진료 연결 계약](care-journey-contract.md), 실제 검증 결과는 구현 결과의 최신 절을 따릅니다.

## 전화가 막혔을 때의 인계

실패 이유·시도 내역·남은 일·담당자를 보존합니다. 무응답은 사용자가 명시한 시연 횟수/시간 안에서만 재시도하며 기본은 정책 미설정입니다. 최초 포함 최대1~3회·1~120분을 지원하고 같은 정책을 반복 적용해도 시도/시간 범위를 초기화하지 않습니다. AI 응대 거절은 자동 반복을 멈추고 보호자에게 번호·문의 내용을, 본인확인은 환자 본인이 해야 할 단계를 넘깁니다. 서류 부족은 발급/제출 작업으로, 예약 불가는 허용한 다른 날짜의 문의로 이어집니다.

별도 무응답·AI 거절·본인확인·서류/일정 막힘 예시는 합성입니다. 재시도 정책이나 다음 가능 시각은 실제 발신 예약이 아니고 현재 실발신은 없습니다. 실제 위임·민감정보·전화/예약 확인 경계를 유지합니다.

## 요약과 대화로 관측하기

공통 요청은 기존 Agent도구 루프를 실행하고 실제tool진행을 고정 메타데이터로 전달한다. 자료·병원·이동/동행 요약과 전체 답변 본문에서 읽으며, 지역비교처럼 읽기만 하는 질문은 실제 방문조건을 바꾸지 않는다. 현재 단계와 완료된 결과는 다를 수 있고 문의 대기/인계·변경 재확인은 해당 역할에 남는다. 최종응답 전에는 마지막확인 caseState를 유지한다. 진행조회 실패·지연·이전토큰 응답이 사례/새초안/현재요청을 덮지 않으며, 진행조회 자체는 모델·세션·budget을 만들지 않는다.
