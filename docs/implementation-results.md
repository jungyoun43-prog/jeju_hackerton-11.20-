# MVP 구현·검증 결과 기록

기준일: 2026-10-31 · 현재 범위: 실제 공개 기관 데이터 + 합성 의료 업무 흐름. 새 UI·이미지 로고의 최종 통합·배포 검증은 아래 기록을 갱신한다.

개발 환경은 Linux·Node v22.23.2·npm 10.9.8, 브라우저 QA는 Playwright 1.64.1·Chromium이다. 실행 소스 지문·검사 수·캡처는 검증한 버전의 `orchestration/runs/` 증거를 따른다. 이전 버전의 통과 결과를 새 UI·데이터 버전의 검증으로 대신하지 않는다.

## 1. 문제와 구조

제주 환자와 기존 도외 주치의 사이의 협진 준비에서 보호자가 기관 문의·필요 서류·추가 요청·회신·동행을 연결해야 하는 문제를 다룬다. 환자 진료 장소를 AI가 결정하는 기능은 구현 범위에 포함하지 않는다.

구조는 **공개 기관 조회·선택 → 보호자 UI → 상태·허용 범위·누락 검증 → 문의·문서·검토 시뮬레이션 → 변경 이력·실행 계획**이다. 기관 등록 정보와 문의·의료진 회신은 출처가 다르다. 개발 서브에이전트는 별도 worktree에서 작업하며 서비스의 다중 임상 Agent 구조로 설명하지 않는다.

## 2. 실제 데이터 활용 결과

사용자가 지정한 제주데이터허브의 [병·의원 정보 · ID 859](https://jejudatahub.net/data/view/data/859), 원 제공처 표기 LOCALDATA를 사용한다. 2026-10-31 공개 응답을 조회해 다음 결과를 만들었다.

| 결과 | 사용 범위·근거 |
| --- | --- |
| 공개 표본 20행 분석 | 행정 정상 13행·폐업 7행. 주소 20/20·진료과 19/20, 결측 1행. `app/data/datahub-profile.json` |
| 실제 기관 후보 13곳 | 폐업 제외 후 기관명·주소·등록 진료과·행정 상태·행별 날짜·출처를 변환. `app/data/hospital-candidates.json` |
| 후보 조회·선택 | 등록 진료과·주소로 필터하고 선택 기관을 제주 문의 대상으로 반영. 선택 변경 시 제주 문의·검토 접수 초기화, 기존 의료기록 보존 |
| 자료 시점 | 20행 모두 2024-10-17 13:53 수집. 전체 20행 갱신 범위 2018-08-31~2024-08-10. 허브 페이지 수정일·표기 수집기간과 구분 |
| 재현 | `node scripts/datahub-profile.mjs --fetch`로 공개 응답에서 후보·집계 재생성. 원문 전체 CSV는 저장하지 않음 |

기본 공개 후보 연결에 프로젝트 키나 파일 업로드가 필요하지 않다. 전체 운영 API는 미연결이다. 공개 표본을 전체 제주 의료기관 목록으로 확대하거나 과거 행정 정상 상태를 현재 수용·예약·협진 참여로 표시하지 않는다. 출처·시점·변환 범위는 [데이터 명세](data-sources.md)를 따른다.

## 3. 구현 범위와 검증 상태

| 구성 | 구현 내용 | 확인할 증거 |
| --- | --- | --- |
| 한국어 보호자 UI | 사례·현재 병목·다음 행동·담당자 중심으로 재설계. 반복 강조 카드·홍보 문구 축소 | 최종 1440×900·390×844 캡처, 첫 주 행동·넘침 확인 |
| 문의 재현 | 자료·의사 의뢰·불통·미참여 분기 | 단위 검사·양기관 브라우저 동선 |
| 문서·허용 범위 게이트 | 양기관 확인·필수 자료·공유 허용을 검사 | 준비·공유 전 접수 차단, 허용 후 접수 |
| 보완·회신 | 추가 자료→재접수, 조건 변경 시 기존 결과 무효화 | 보완 루프·완료 후 중복 회신 차단 |
| 부담 계산 | 가정 비용·null 미확인·동행 공백 | 방문3·동행1→공백2 대조 |
| 공공데이터 도구 | 실제 13곳·20행 집계 로드·출처 검증, 선택적 JSON/CSV 메모리 처리 | 실제 snapshot 검사와 합성 경계값 검사를 구분 |
| 지도 | Leaflet·OSM 배경, 합성 마커, Google Maps URLs 외부 링크 | 실제 지도 배경·가상 지점 구분, 타일 실패 안내. Google Embed 미구현 |
| 생성 이미지 | 투명 PNG 이미지 로고. 의사·가족 일러스트는 화면에서 제거 | `app/assets/manifest.json`의 원본·정확 프롬프트·도구·날짜, 화면과 ZIP 포함 |
| AWS 호스팅 | 비공개 S3·CloudFront HTTPS 공개 데모 | [사이트](https://d1mfksxrj025bx.cloudfront.net), `/api/health`, `/deployment.json` |
| CI/CD | 검사·빌드한 같은 artifact, production OIDC·제한된 배포 역할·revision 검사 | 실제 Actions 완료와 공개 revision의 일치 |
| 런타임 LLM·실제 전화·병원 전송·예약 | 미연동 | 모델 추론·발신 성공·기관 참여를 주장하지 않음 |

최종 통합 증거는 새 UI·데이터·로고의 같은 revision으로 `npm test`, `npm run build`, `npm run test:browser`, `npm run eval`, ZIP 재실행과 AWS 배포를 대조한 뒤 갱신한다. 센터 실기기 검증은 별도다.

## 4. 보존한 이전 검증 이력

공개 후보 연결·이번 UI 재설계 이전의 합성 MVP에서 확인한 결과다. 현재 버전의 검사 수나 독립 검토 판정으로 인용하지 않는다.

- 단위·서버·하네스 검사 26개, 브라우저 동선 22개, 자동 규칙 eval 12/12 통과.
- PC·모바일 지도 타일 표시와 타일 전체 차단 시 안내·외부 링크·문의 동작을 확인했다.
- 첫 ZIP을 새 디렉터리에 풀어 설치·검사·빌드·주요 HTTP 5개 응답을 확인했다.
- 임시 worktree에서 marker commit을 revert한 뒤 기준선 tree가 복원되는 것을 확인했다.
- 읽기 전용 검토가 당시 소스·두 캡처·브라우저 기록·소스 지문을 대조했다. 이후 사용자의 디자인 피드백으로 화면을 다시 설계한다.
- AWS 첫 CI 실행 [41196741118](https://github.com/jungyoun43-prog/jeju_hackerton-11.20-/actions/runs/41196741118)은 검사·빌드·artifact 업로드 후 OIDC 인증에서 실패했다. GitHub immutable subject에 맞춘 신뢰 정책을 수정해 CloudFormation `UPDATE_COMPLETE`를 확인했으며, 다음 실제 배포 실행은 별도 확인한다.

## 5. 한계와 센터 활용

- 기관 정보는 실제 공개 표본이지만 환자 기록·문의 응답·자료 제출·의료진 회신은 결정적 재현이다. 실제 발신·기관 전송·임상 판단이 아니다.
- 런타임 모델과 모델별 Prompt·Tool 호출은 연결하지 않았다.
- 지도 위 가상 위치는 실제 참여 기관·환자 주소가 아니다. 경로 API 없는 이동시간을 만들지 않는다.
- 비용은 사용자 가정이다. 한국 급여 적용·환자별 본인부담·항공·숙박 견적을 검증한 결과가 아니다.
- 최소 PC 사양을 고려한 가벼운 구성과 센터 i7-8700 / GTX 1060 / RAM 32GB 실기기 검증을 구분한다. 센터 실행은 미완료다.
- 최종 기획서 PDF의 15페이지 이내 렌더링·확인은 남아 있다.

센터에서는 공개 기관 데이터의 조건 변경이 후보·문의 대상·준비 결과에 미치는 영향을 합성 의료 사례로 시연하고, 문의·자료·검토 상태와 누락 담당자를 확인할 수 있는지 평가한다. 실제 환자 운영은 의료진·기관·정보 처리 책임자와 검증 범위를 정한 뒤 진행한다.

미완료 항목은 [제출 추적표](submission-checklist.md)를 따른다. 자동 규칙 준수율을 임상·법적 타당성 또는 최종 제출 준비 점수로 사용하지 않는다.
