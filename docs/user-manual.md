# 제주 진료 나침반 사용자 매뉴얼

버전: AWS 대화 모델 연결 · 작성일: 2026-10-31

첫 화면은 보호자가 텍스트·음성으로 요청하고 처리 기록과 이번 방문 요약을 읽는 화면이다. 루트 .env의 OPENAI_API_KEY를 입력하고 서버를 재시작하면 모델 API를 사용한다. 키가 없으면 자유 입력은 미연결 안내를 반환한다. 기본 모델은 gpt-6.1-sol이며 OPENAI_MODEL=gpt-6.1-terra로 선택할 수 있다. Sol 실제 계정 접근은 로컬·AWS의 단일 도구 사례에서 확인했다. Terra·복합 요청·일반 품질은 별도다. 별도 **대화 흐름 미리보기**에서 공공데이터 검색과 합성 준비 과정을 확인할 수 있다. 병원·지원 문의처는 실제 공개 자료이며 환자·기록·전화 응답·의료진 회신은 합성이다.

## 1. 설치와 실행

Node.js 22 이상과 npm으로 저장소 루트에서 실행한다.

```bash
npm ci --ignore-scripts
npm run dev
```

터미널의 Local 주소를 연다. 기본은 `http://127.0.0.1:4173`이다. 최초 npm 설치에는 인터넷이 필요하지만 고정 예시에 모델 키·AWS 인증은 필요하지 않다. `HOST`, `PORT`, `MAP_TILE_URL`은 [환경변수 예시](../.env.example)를 따른다.

```bash
npm test
npm run build
npm run preview
```

`npm run preview`는 빌드 화면과 Node API를 함께 실행한다. 기본 포트가 같으므로 개발 서버를 먼저 종료한다. 단순 파일 서버·정적 S3만으로는 대화 API가 실행되지 않는다. 센터 실기기 확인과 실제 브라우저·AWS 새 revision 확인은 [검증 기록](implementation-results.md)을 따른다.

## 2. 대화 흐름 미리보기

1. 첫 화면 상단의 연결 설정과 가상 사례 표시를 확인한다. 공개 AWS는 Sol 연결 설정됨, 키 없는 로컬은 AI 모델 미연결이다.
2. **대화 흐름 미리보기**를 누른다. 사전 작성 요청과 답변에 **작성된 예시** 표시가 붙는다. 이 예시는 자유 입력을 해석하지 않는다.
3. 11월 12일 10시, 애월 어머니의 제주우리병원 방문이라는 고정 사례를 읽는다. 병원 공개 등록정보 검색, 공단 연계 미설정 확인, 합성 자료·병원 문의, 택시·동행 문의처와 초안이 처리 기록에 표시된다.
4. 택시 가능 응답과 동행 연락 실패는 합성이다. 실제 배차·동행 배정은 이루어지지 않는다. 필요한 실제 진찰 소견·의뢰서와 동행 재확인 작업이 남는지 확인한다.
5. **이번 방문 준비**, **지금 연결된 범위**, **준비에 사용한 출처**에서 상태·자료 시점·미확인 조건을 읽는다. 모바일에서는 요약을 펼칠 수 있다.
6. **준비 내역 저장**으로 예시 결과를 내려받는다. 실제 진료 소견서·예약 증빙으로 사용하지 않는다. **새 대화**는 브라우저의 사례·이력·진행 표시를 초기화한다.

이 예시는 실제 공공 snapshot과 상태 변경 도구를 실행하지만 LLM·DB·전화망은 호출하지 않는다. preview의 sessionId는 일반 대화 세션으로 이어지지 않는다.

## 3. 텍스트와 음성으로 요청하기

입력란에 요청을 적고 **보내기** 또는 Enter를 누른다. Shift+Enter는 줄바꿈이다. 예시 요청 버튼도 일반 대화 API를 사용한다. 키가 없을 때는 모델 미연결 안내가 나온다. 입력한 문장은 복원되며, 자유 입력을 고정 예시 답변으로 바꿔 보여주지 않는다.

**말로 요청**은 지원 브라우저의 `SpeechRecognition` 또는 `webkitSpeechRecognition`을 사용한다. 마이크 권한을 허용하면 한국어를 텍스트로 바꾸고, 말이 끝났을 때 인식한 요청을 API로 보낸다. **듣기 중지**로 중단할 수 있다. 미지원·권한 거절·마이크 없음·인식 실패 때는 텍스트로 계속한다. 브라우저 음성 인식은 병원 전화 발신이 아니다.

대화 이력은 브라우저 메모리에 있으며 새로고침하면 사라진다. 전송한 요청은 동일 출처의 Node/Lambda API에서 처리하고 원문·대화 전문을 로그나 DB에 저장하지 않는다. 음성 인식의 처리 위치·외부 전송 여부는 브라우저 제공 서비스 정책을 따른다. 실제 환자 기록·주민번호·인증정보·민감한 음성은 입력하지 않는다. 실제 마이크 인식 품질은 음성 API mock 검사만으로 검증되지 않는다.

공급자 연결 개발은 [Agent API 문서](../agent/README.md)를 따른다. `createAgentService({provider})`가 연결 지점이며 환경변수에 모델 이름만 넣는다고 활성화되지 않는다.

AWS는 하루80개 대화 요청을 UTC 기준으로 제한하고 실패한 요청도 차감한다. 같은 sessionId 안의 중복 요청은 재실행하지 않는다. 첫 응답을 받지 못해 세션 없이 재시도하면 추가 턴이 될 수 있다. 한 요청 안에서 모델은 최대8회 호출될 수 있다.

## 4. 상태와 출처 읽기

| 표시·상태 | 읽는 방법 |
| --- | --- |
| 처리됨 | 해당 데이터 조회·초안 등 도구 작업이 끝남. 합성 응답이면 합성 표시를 함께 확인 |
| 확인 필요 | 빠진 자료·시각·이용자격·동행 가능 여부 등이 남음 |
| 미연결 | 공단 기록 등 승인된 연계 어댑터가 없음. 조회 완료가 아님 |
| 확인 실패 | 오류·불통 등의 상태. 진료 불가나 도외 방문 필요의 임상 판단이 아님 |
| 자료 준비·검토 접수·의료진 회신 | 서로 다른 사건. 하나가 완료됐다고 예약이나 외부 전송이 끝난 것은 아님 |
| 조건 변경 후 재확인 | 병원·방문일·지역·휠체어 등의 변경으로 과거 응답을 새 조건에 다시 확인해야 함 |

병원 859는 2024-10-17 수집 공개 표본 20행 중 폐업을 제외한 13개 등록 기관이다. 택시는 327이 연결한 2026-03-19 기준 공식 파일 34업체, 돌봄은 254의 2020-04-17 기준 19개 등록 문의처다. 아름동행·교통약자센터 안내는 별도 공식 출처다. 등록 상태·지역 일치·대표번호는 현재 진료·배차·동행 가능의 확인이 아니다.

지원 문의 초안은 날짜·출발지역·기관·지원조건과 확인할 질문으로 구성한다. 환자 실명·진단명·검사내용을 자동 포함하지 않는다. 고령이나 암진단만으로 교통약자센터 자격을 정하지 않으며 ‘동행콜’을 병원동행인 배정으로 해석하지 않는다.

## 5. 개발용 수동 화면

기존 화면은 **`/workspace.html`**에 보존했다. 기관 선택·자료 상태·합성 응답 분기·지원 조건 변경을 직접 확인하는 개발 도구다. 대화 서비스 이용을 위해 이 화면의 폼을 먼저 채울 필요는 없다.

- 기관·데이터: 공개 13개 후보를 조회하고 문의 대상을 선택한다. 사용자 기관 파일 가져오기는 이 화면에만 있으며 JSON/UTF-8 CSV, 2MiB·10,000행 이하를 브라우저 메모리에서 처리한다. 출처는 사용자 제공으로 표시한다.
- 병원 문의·진료 자료: 양기관 절차, 필수 문서, 별도 공유 허용이 있어야 검토 접수 시연을 진행한다. 의뢰서와 미수행 진찰 소견을 Agent가 작성하지 않는다.
- 일정·동행: 방문 1건의 지역·휠체어·지원 필요를 바꾸고 후보·초안·합성 응답·재확인을 검사한다. 문의 전 응답 기록은 거절한다.
- 반복방문 비용: 가정 횟수·금액·보호자 가능 횟수를 바꾸어 부분합과 동행 공백을 확인한다. 미확인을 0원으로 확정하지 않으며 현재 급여·견적 API는 없다.
- 지도: Leaflet·OSM의 지형·지명과 합성 위치 마커를 구분한다. Google Maps 외부 링크는 키 없이 열지만 앱이 경로·이동시간을 조회한 것은 아니다. 타일 장애 안내와 대안을 확인한다.

기관을 바꾸거나 문서·문의 조건을 바꾸면 과거 검토 결과를 다시 준비한다. 이전 결과를 유지하지 않는 동작을 오류로 해석하지 않는다.

## 6. 실행·제출 자료

```bash
APP_REVISION=local-preview npm run build:agent
npm run package
```

Python 3가 필요하다. `output/agent-lambda.zip`은 AWS 함수용 `index.mjs`·`deployment.json`이고, `output/jeju-care-compass-mvp.zip`은 제출 준비용 개발 스냅샷이다. 생성만으로 대회 제출 요건 충족·업로드가 완료되는 것은 아니다. [제출 추적표](submission-checklist.md)를 확인한다.

`npm run observe`, `npm run eval`, `npm run rollback -- <통합-커밋-SHA>`는 브랜치·worktree가 있는 개발 저장소용이다. ZIP의 일반 실행에는 필요하지 않다. 모델·프롬프트·도구·의존성과 실제/시연 범위는 [외부 명세](../THIRD_PARTY.md)와 [API 문서](../agent/README.md)를 따른다.

## 7. 오류와 제약

| 상황 | 확인·해결 |
| --- | --- |
| AI 모델 미연결·HTTP503 | 키가 비었거나 모델 접근을 확인하지 못한 상태. .env의 OPENAI_API_KEY를 설정하고 서버 재시작. 고정 예시는 별도 버튼으로 확인 |
| 미리보기 실패 | Node API 실행 여부 또는 AWS의 Lambda 연결·배포 revision 확인. 정적 파일만 게시하면 API는 없음 |
| 음성 버튼 비활성·권한 거절 | 지원 브라우저·기기 권한 확인 후 텍스트로 계속. 실제 마이크 검증과 mock 검사는 별개 |
| 처리 중 오류·타임아웃 | 입력을 확인하고 재시도. 실제 연동을 완료한 것으로 표시하지 않음 |
| 설치·서버 접속 실패 | Node22·npm 접속·실행 프로세스·출력 포트 확인. 원격 서버 loopback은 다른 기기에서 바로 열리지 않음 |
| 기관·지원 후보 없음 | snapshot 로드·지역/유형 필터 확인. 같은 지역 후보가 없으면 확대 문의 근거를 읽음 |
| 수동 파일 가져오기 거절 | UTF-8 JSON/CSV·크기·행 수·스키마 확인. 인증정보나 지원하지 않는 열은 넣지 않음 |
| 지도 로드 실패 | 외부 타일 접근과 안내 확인. 타일 장애를 병원 수용 여부로 해석하지 않음 |
| 실제 예약·발신·기록 조회가 필요함 | 이번 버전은 미연동. 기관의 공식 접수·본인인증·동의 절차로 확인 |

## 8. 검증의 범위

공급자 주입 테스트는 도구 인자·출처·권한·상태 전이·중복 요청·한도·오류를 검사한다. 실제 LLM의 한국어 이해나 임상 품질 검증은 아니다. 로컬 메모리와 AWS DynamoDB를 구분한다. AWS는 TTL1시간·UTC 전역80요청이며 같은 세션의 중복 재전송 미차감을 실제 확인했다. 초기 응답 유실 재시도의 추가 차감은 남아 있다. 새 대화 UI의 PC·모바일, 공개 AWS revision과 제출 ZIP의 최종 검증은 [구현 결과](implementation-results.md)에 확인된 기록만 남긴다.
