# 현재 할 일 중심 흐름 검토 · 2026-11-01

검토 대상은 [현재 할 일 계약](../guided-visit-contract.md)에 따른 중앙 작업·단계 상세, 오른쪽 네 단계 탐색과 같은 요청 안의 제한된 문의 초안 준비다. UI·서버 작성자가 서로 작성하지 않은 코드를 읽고 root가 실제 캡처·호출 경로·검사 결과를 대조했다. 최신 실행 지문·최종 수치는 [구현 결과3.20절](../implementation-results.md#320-현재-할-일-중심-방문-준비)을 따른다. 검토 중 발견은 수정 전 상태를 설명하며 현재의 미수정 결함 목록이 아니다.

| 발견 | 원인과 반영한 수정 |
| --- | --- |
| 기본 설정과 새 휠체어 요청이 충돌할 수 있음 | 기기 기본 설정을 이번 메시지의 명시 조건 반영으로 세던 경로를 제거. 실제 UI와 같은 preferences를 포함한 provider fixture에서 새 조건 미반영 시 추가 초안 보류와 갱신 성공 시 휠체어 문의 경로를 대조. |
| 새 날짜·기관을 건너뛰고 예전 조건으로 초안이 추가될 수 있음 | 명시 조건의 도구 갱신 근거가 없으면 보류. 공개 목록 밖 병원/의료원 이름도 탐지하고 역할·기존 기관의 전체 이름 일치를 확인. 문자열에서 새 값을 만들어 자동 갱신하는 파서는 추가하지 않음. |
| ‘동행은 빼고’를 동행 준비로 해석 | 같은 절의 대상별 빼고·제외하고·제외한 제한을 긍정 요청보다 먼저 적용. 전체 방문·독립 택시 요청이 제외한 동행으로 확대되지 않는 fixture 추가. |
| 후속 실패·중지 후 최근 답변 버튼이 무동작 | 마지막 자식이 assistant라고 가정하던 선택자를 실제 마지막 assistant로 교정. ‘최근 답변 보기’로 표시하고 PC·모바일의 성공→503/중지·늦은 응답에서 기존 답변·초안·선택 단계 보존을 확인. |
| 준비 전인데 녹색 ○ 표시 | 접수 응답 수로 계산한 기존 기호를 제거하고 업무 상태와 같은 mapping을 사용. 준비 결과·추가 준비·확인 필요·인계를 문구와 기호로 함께 표시. |
| 중앙 작업 때문에 비교 답변이 묻힘 | 작업 근처에 최근 답변 접근을 제공하고 실제 대화 기록으로 이동. 원문을 복제하지 않으며 복구에 과거 답변이 없으면 버튼도 숨김. |
| 출처 추가 시 읽던 링크가 재생성될 수 있음 | URL별 기존 링크를 유지하고 새 링크만 추가. 읽던 단계·DOM·초점·출처·위치를 지키고 새 결과는 알림으로 접근. |
| 준비표 남은 일이 두 번 표시됨 | 같은 workflow의 단일 목록에 제목·담당자·상태·설명을 모아 실제 항목 수와 요약 건수를 일치시킴. |

건강기록 미연결이나 의료진 확인 필요가 독립된 공개 문의 초안을 막지 않도록 하고 지원 실패는 해당 대상에 남긴다. 실제 발신·자료 조회/전송·예약·배차·동의 변경은 자동 이어가기 범위에 넣지 않았다. 같은 요청의 도구·시간 한도, 지문/receipt와 읽기 전용 복구를 재사용한다.

브라우저 초기 실패는 원본 지문과 함께 보존했다. 중앙 안내의 높이 변화에 따른 scrollTop 보정은 같은 출처의 실제 화면 위치·초점·가시성으로 검사하고, 열린 안내 닫기·단계 선택·native transition이 끝난 뒤 관측한다. 성공을 위해 출처/원문/초안·키보드·한도·실제/합성 경계의 요구를 지우지 않았다.

API 크레딧 소진 뒤 실제 모델 호출을 추가하지 않았다. 새 Prompt·조건 처리·자동 이어가기의 실제 모델 품질은 미검증이다. 고정 provider·실제 keyless preview·HTTP·브라우저 검사와 과거12과업의 실제 모델 결과는 서로 다른 증거다. 실제 보호자·기관·전화·개인기록·임상/법률·실기기 검토를 완료한 것으로 확대하지 않는다.
