## 범위와 소유권

- `submission-package`: 전용 worktree에서 `scripts/package.mjs`, `tests/package.test.mjs`만 수정한다. 오래된 캡처 디렉터리 전체와 과거 실행 증거의 장황한 선택 목록을 제출용 목록으로 줄인다. 기본 실행 코드·Prompt·데이터·매뉴얼·라이선스·기획서·테스트·기존 정적 빌드는 유지한다.
- root: 계약·등록·README/제출 설명·결과 기록·통합·검증·ZIP·기존 CI/CD. 자동 동기화되는 AGENTS.md는 수정하지 않는다.
- 별도 읽기 전용 점검은 호출자·동적 참조까지 확인한 명백한 미사용 코드만 제안한다. 파일이 크거나 현재 첫 화면에 없다는 이유만으로 삭제하지 않는다.

새 패키징 모드·설정·일반화한 의존성 수집기·프레임워크를 추가하지 않는다. 원본 개발 검증 이력은 보관하고 제출 ZIP에서는 최신 요약과 대표 화면만 제공한다. 전체 검증 원본이 ZIP에도 전부 포함됐다고 표기하지 않는다. 오래된 문서의 당시 실행 기록은 재표기하지 않는다.

## 보존과 검증

1. 링크·민감정보·외부 경로의 거절과 실패 시 기존 ZIP 보존을 유지한다. 사용하지 않는 이미지의 제외와 최신 대표 화면/검증 요약 포함을 실제 패키지 명령 fixture로 확인한다.
2. 고정된 앱/Agent/Prompt/데이터·입력·초안·복구·동의/시연 경계를 바꾸지 않는다. 실행 지문이 같으면 기존 브라우저 증거는 원래 실행 시각으로 재사용하며 새로 실행했다고 쓰지 않는다. 유료 모델·실발신·개인기록 호출은0이다.
3. 전체 단위·정적/Lambda 빌드, ZIP CRC·필수 파일·키 제외·소스 지문·별도 설치와 실행을 확인한다. 제출 ZIP 목표는50MB 이하이며 실제 바이트와 SHA를 기록한다.
4. 전용 브랜치 커밋을 root가 검토·cherry-pick한다. `npm run eval`의 파일 소유권·현재 증거·롤백 경계를 확인하고 기존 승인된 GitHub/AWS 경로로 반영한다.

제출 ZIP의 축소나 코드 정리를 현재 모델 과업 품질·실기관 성공·대회 업로드 완료의 검증으로 바꾸지 않는다. 현재 실모델 품질은 미검증 상태를 유지한다.
