# Ponytail 기술부채 감사와 수정

2026-10-31. 기준 소스는 `d7cd983`이다. [Ponytail](https://github.com/dietrichgebert/ponytail/tree/96608e078b2d5ea607c5c3b8b5a54d1c1fba6846)의 기본·audit·review 스킬을 설치하고 적용했다. 설치한 스킬은 개발 도구이며 제품의 실행 의존성이 아니다.

## 점검한 서비스와 부하

혼디는 보호자의 요청을 자료·병원 문의·이동·동행 준비 도구로 연결한다. 첫 화면은 네 작업창이며 수동 검증 화면도 유지한다. 공개 합성 MVP의 Lambda 동시 실행2·UTC 하루80턴·요청45초·모델8회/도구16개를 기준으로 살폈다. 프런트·서버 감사를 나누고, 호출자·테스트·설정·문자열 참조와 합성 재현 사례를 확인한 뒤 세 전용 worktree에서 수정했다.

## 수정이 필요했던 동작

1. **취소한 음성 인식이 새 초안을 바꿀 수 있었다.**
   - 역할: 음성 결과를 보호자가 확인할 초안으로 만든다.
   - 문제: 종료 이벤트에만 인식기 소유권 검사가 있었다. 새 대화 뒤 옛 인식기의 result가 도착하면 새 초안을 옛 전사로 덮었고 start/error도 현재 상태에 영향을 줄 수 있었다.
   - 수정: start/result/error/speechend에서 현재 인식기와 취소 상태를 확인한다. 실제 Chromium의 지연 abort fixture에서 취소·새 대화·다음 음성 시작 뒤 옛 이벤트가 초안과 상태를 바꾸지 않는지 검사한다.
   - 방치 영향: 사용자가 고친 날짜·기관명 등을 잃거나 이전 초안을 다시 보낼 수 있다. 자동 전송이 발생한 문제는 아니다.

2. **문서 링크의 외부 파일이 사전 검사에서 빠지고 ZIP에는 들어갈 수 있었다.**
   - 역할: 검사한 소스·문서·증거만 제출 ZIP으로 모은다.
   - 문제: 소스 검사는 심볼릭 링크를 건너뛰고 Python ZIP 입력은 링크를 따라 읽었다. 프로젝트 밖 가짜 인증 파일을 문서 링크로 연결한 fixture에서 재현했다. 실제 비밀 유출을 확인한 것은 아니다.
   - 수정: 선택 경로·그 부모·중첩 파일/디렉터리의 링크를 모두 거절한 다음 ZIP을 연다. 실패하면 기존 ZIP을 보존한다. 실제 패키지 명령으로 정상 파일·라이선스·환경파일 제외와 네 링크 위치를 검사한다.
   - 방치 영향: 개발자가 링크로 붙인 외부 파일의 내용이 제출물에 섞일 수 있다.

## 유지보수 부담을 줄인 부분

3. **같은 진행 DTO를 세 구현이 다르게 검증했다.**
   - 역할: 진행 화면에 고정 단계·도구·상태만 전달한다.
   - 문제: 서버와 두 브라우저 검증의 순번0·시각·단계 순서·객체 prototype 허용이 달랐다. 도구19개 목록도 반복돼 변경할 곳이 늘어났다.
   - 수정: 기존 `app/preparation-stages.js`의 공통 함수와 고정 목록을 재사용한다. 서버의 엄격한 객체·시각·순번·4단계 순서·32이벤트·UTF-8 8KiB·사본 반환과 TypeError 경계를 보존했다. 이전 서버와481개 변형 입력의 허용·거절 결과가 같았다. 빈 진행 예시는 유효한 순번1로 고치고 순번0 거절도 따로 검사한다.
   - 방치 영향: 도구나 필드 하나를 바꿀 때 일부 화면만 진행을 받지 못하거나 서버가 만들지 않는 값을 화면이 수용할 수 있다.

4. **호출되지 않는 이전 화면의 함수와 전용 스타일이 남아 있었다.**
   - 역할: 과거 수동 화면의 환자 strip·작업 카드·가족 할 일·병원 연결 그림을 생성하던 코드다.
   - 문제: `patientStrip`, `tasksPanel`, `familyTasks`, `connectionPanel`은 전체 호출자·문자열·동적 참조 확인에서 정의만 남았다. family/connection 전용42개 CSS 규칙도 이 함수들에서만 사용됐다.
   - 수정: 해당 함수4개와 전용 스타일만 삭제해211줄을 제거했다. 공유 스타일과 실제 `/workspace.html`의 페이지·지도·준비 동작은 유지했다.
   - 방치 영향: 사용하지 않는 대체 구현을 함께 읽고 수정하게 되고 정적 산출물에 불필요한 코드가 남는다. 체감 속도 개선 수치는 측정하지 않았다.

## 결과와 보존한 판단

- 앱·서버·패키징 실행 코드의 물리 줄 수는 순239줄 감소했다. 테스트·문서·작업 추적 기록은 이 수치에서 제외한다. 의존성 추가·삭제는 없다.
- 진행 검증 구현은3개에서1개, 도구 목록도 고정 표시 목록 하나로 합쳤다. 실제/시연 경계·입력 검증·에러 처리·접근성은 유지했다.
- 모달마다 다른 복원 대상·초안/미리보기 동작을 옵션 객체로 옮기는 큰 추출, 전체 CSS 재작성, Bedrock·수동 화면·preview 삭제는 이번 정리 범위에 넣지 않았다. 파일 길이만으로 나누지 않았다.
- [독립 변경 리뷰](reviews/2026-10-31-ponytail-refactor.md)는 소스·연결 호출부·회귀 fixture에서 수정 항목 없이 Ship으로 판정했다. 상세 파일 소유권·보존 계약·검증 절차는 [작업 계약](refactoring-contract.md)을 따른다. 최신 통합 검증은 [구현 결과](implementation-results.md), 공개 버전은 실행 증거의 revision과 sourceHash를 확인한다.

## 검증 범위

동결된 통합본에서 단위·서버359/359, 대화178/178, 여정222/222, 수동47/47, 네창108/108, 자동규칙54/54와 서버 빌드를 확인했다. 실행 지문은 `b74ddf4901db7185bb959546bc19abe6cc55bc96e8a5d99c00f5645dd9269a64`이며 공개 버전·ZIP은 별도 실행 증거를 따른다.

진행의 실제 owner·고정TTL·순번·기록 예산과 부모 deadline은 바꾸지 않았다. 음성 검사는 브라우저 합성 이벤트이며 실제 마이크 서비스의 품질 검사가 아니다. 외부 링크 재현은 임시 가짜 파일만 사용했다. 실제 환자 기록·전화·기관 수락·의료·법률 검토는 이번 코드 감사의 검증 범위가 아니다.
