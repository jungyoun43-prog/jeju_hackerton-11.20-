# API 연결·평가기준·제주 데이터 활용 점검

확인일: 2026-11-17. 현재 작업은 로컬 구현과 검증이며 AWS 재배포·대회 제출은 하지 않았다.

## 판단

제주 데이터는 단순 출처 표시를 넘어 병원 필터, 지역별 문의처 정렬, 휠체어 문의 대상 변경, 준비표 근거에 사용된다. 다만 수동 예약 준비에서 AI 대화로 선택 조건이 전달되지 않아 Agent의 이어지는 준비가 약했다. 이를 요청 초안으로 연결했다. 실제 AI 응답 생성은 키 계정 잔액 소진으로 검증하지 못했으므로 현재 전체 Agent 완성도를 검증 완료라고 표현할 수 없다. 대회 점수나 수상을 예측하지 않는다.

## 공식 원문과 대조

Ego Lite로 [대회 평가기준](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)의 평가 항목을 펼쳐 읽고, [사용자 지정 허브 목록](https://jejudatahub.net/data/list/12), [병·의원 859 원문](https://jejudatahub.net/data/view/data/859), [센터 제공데이터](https://jejudatahub.net/center/data)를 확인했다. 공식 평가는 전문가70%·참가팀 상호평가30%다.

## UX 검토와 수정

Method: dual-agent (A: /root/design_assessment · B: /root/detector_assessment). 두 검토는 소스 수정 없이 독립 진행했다. A는 기존 화면 한 흐름을 직접 사용하고 25/40의 내부 휴리스틱 평가를 남겼다. 대회 점수와 다른 주관적 UX 평가다. B는 변경 JSX4개 detector 0건과 실제 Ego Lite 조작·키보드·PC/모바일 viewport를 확인했다. 실제 기관 연락이나 모델 요청은 하지 않았다.

1. **선택 조건의 단절:** 병원·진료과·기간·시간·선택 문의처를 기존 작성 문장과 함께 AI 요청 초안에 옮긴다. 확인 후 보내기를 누르기 전에는 호출하지 않는다. 기간을 임의의 확정일로 바꾸거나 가상 병원을 실기관으로 조회하지 말라는 경계를 포함한다.
2. **문의 창구의 막연함:** 실제 전화번호가 없는 표본은 기관명이 이어지는 공식 창구 검색을 제공한다. 검색 결과 자체를 검증된 공식 전화번호로 표시하지 않는다.
3. **단계명 불일치:** 공개자료의 3단계는 문의 내용 확인, 가상 접수 경로는 접수 확인으로 구분한다. 좁은 화면은 4칸 안에서 단계명을 줄바꿈한다.
4. **시간대 소실:** 오전/오후/정확한 시각 희망을 이동 화면·저장표에 유지한다. 하루의 정확한 시각만 입력 계획의 순서에 대조하며 실제 빈자리로 해석하지 않는다. B가 관측한 ‘희망 희망’ 중복도 정리했다.
5. **API 오류 오안내:** 계정 잔액 소진을 잠시 후 재시도로 안내하지 않고 운영자 확인 필요와 초안 보존·수동 준비 가능을 알린다.

기존 준비와 새 예약 선택은 별도 상태다. 이번 변경은 선택을 명시적인 요청으로 전달하는 연결이며 AI가 이미 상태를 반영했다거나 실제 예약이 되었다는 표시를 추가하지 않는다. 재시작 전 임시 선택 보존 범위도 기존과 같다.

## API 실제 확인

사용자 지정 키를 서버에만 넣고 Sol·medium, 하루 실제 전송60회·요청당6회·출력4,096토큰을 적용했다. 모델명/추론 설정은 화면과 공개 응답에서 제거했다. Ego Lite 요청1회와 최소 진단1회는 성공 응답을 얻지 못했다. 최소 진단은 HTTP429 `credit_balance_exhausted` / `insufficient_quota`. 추가 유료 호출을 중단했으며 실제 도구·답변 품질은 미검증이다. [호출 한도 계약](../api-usage-contract.md)에 저장·차감·실패 경계를 기록했다.

## 검증 자료

원문 본문, 키 없는 회귀 검사와 Ego 캡처는 `output/api-connection-qa/`에 보관한다. A/B 자료는 `design-a/`, `design-b/`다. 키 원문을 보관하지 않았다. Overlay 서버는 사용하지 않았고 존재하지 않는 브라우저 overlay를 주장하지 않는다. B는 기본 screenshot의 확대율/잘림을 실제 앱 overflow와 구분해 CSS viewport와 raw CDP 캡처를 확인했다. 모바일은 viewport 에뮬레이션이며 실기기·스크린리더 검증이 아니다.

## 최종 검증

- `npm run build` 성공. 최종 런타임 소스 지문: `d74a26fe7963b7894aac3984d375f5cad03e06af8594bcc50c5f30667d2cee06`.
- 브라우저 검사 **424/424 통과**: 예약 선택→요청 초안26, 단계·검색148, 기존 대화250. PC·390px 모바일·320px 화면과 낮은 창을 포함한다. 자동 검사는 별도 keyless 서버에서 수행했고 모델 오류는 fixture로 검증했다. 새 요청 연결 검사에서 fixture POST2회·실제 API0회다.
- `npm test`: **510개 중500 통과·9 실패·1 건너뜀**. 남은 실패는 Windows 심볼릭 링크 권한(EPERM), 기존 패키징의 `python3` 실행 가정, AWS 비밀값 전달 fixture의 Linux `/dev/stdin` 가정에서 관측했다. 전체 검사를 통과했다고 표시하지 않는다. OS 권한·배포 설정을 임의로 바꾸지 않았다. 세부 오류는 `output/api-connection-qa/final-all-unit-tests.log`에 보존했다.
- 공식 Pretendard92개 바이너리는 보존했다. CSS·OFL에 생긴 CRLF를 공식 해시와 일치하는 LF로 복구하고 `.gitattributes`에 고정했다. 폰트 검사4/4 통과.
- 빌드·검증 산출물484개에서 실제 키 일치0건. 공개 설정에 모델/추론 설정이 없고 `/.env`는404다. 현재 일일 카운터의 실제 전송 시도는 실패한2회이며 추가 실호출하지 않았다.
- 실제 Ego Lite에서도 제주우리병원·정형외과·11월20~23일·오후 희망·애월콜을 선택해 ‘문의 내용 확인’→이동·준비표→AI 요청 초안까지 이어지는 것을 재확인했다. 병원·과·기간·시간대·문의처·중복 문구 없음·입력 초점7개 조건을 확인했다(`output/api-connection-qa/ego-final.json`). 보내기는 누르지 않았다. 희망 기간·시간을 확정 예약으로 표시하지 않는다.

수동 검토와 자동 검사 통과는 실제 의료기관 예약·차량 가용성·임상적 효과·대회 최종 제출 완료를 뜻하지 않는다. 현재 가장 큰 미완료 항목은 API 계정 잔액을 보완한 뒤 실제 Agent 도구 사용과 답변 품질을 확인하는 일이다.
