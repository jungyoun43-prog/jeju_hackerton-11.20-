# 혼디 (hondi)

멀리 있는 가족을 대신해 제주에서 이어갈 진료의 조건을 확인하고, 자료·병원 문의·이동·동행의 후속 일을 챙기는 AI 비서입니다. 「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 참가 프로젝트입니다.

> “서울에 사는 딸입니다. 애월 어머니가 11월 12일에 진료를 받으세요. 저는 못 가니 필요한 자료와 택시·병원 동행도 알아봐 주세요.”

## 지금 실행되는 범위

화면 높이에 맞춘 작업 공간에서 텍스트·음성으로 요청합니다. 중앙에는 지금 확인할 일과 선택한 단계의 상세, 오른쪽에는 네 단계의 진행 안내를 표시합니다. 한 번의 텍스트·음성 요청을 시작으로 이미 아는 조건을 재사용하고 보호자의 답이 필요한 때만 멈춥니다. 좁거나 낮은 창에서도 같은 공통 입력과 단계 DOM을 사용하며, 이전 대화·처리 기록은 중앙에서 펼쳐 읽습니다. 소개 블록과 화면을 늘리던 최소높이를 제거하고 일정한 여백을 사용합니다. **AWS 공개 데모에 `gpt-6.1-sol`과 실제 도구 호출을 연결했습니다.** 초기 공개 연결에서 모델→`get_case`→최종 응답을 HTTP200·5.2초로 확인한 이력을 보존합니다. 새 버전의 단위·화면·배포/실모델 범위는 [최신 검증 기록](docs/implementation-results.md)을 따릅니다. 로컬은 `.env`의 `OPENAI_API_KEY`만 넣으면 실행하며 `gpt-6.1-terra`를 명시적으로 선택할 수 있습니다. 키 없는 로컬은 미연결 상태입니다. Terra 실호출·복합 요청·일반적인 모델 품질은 별도 검증 대상입니다.

| 구분 | 현재 동작 |
| --- | --- |
| 자유로운 텍스트·음성 요청 | 키 설정 시 Responses API→검증된 도구→응답. 키가 없으면 `MODEL_NOT_CONNECTED`/503과 입력 복원 |
| 대화 흐름 미리보기 | 별도 preview API에서 사전 작성 예시를 실행. 실제 공공 snapshot 검색·준비 상태 전이와 합성 응답을 함께 표시 |
| 기관·지원 데이터 | 허브 계보4종과 공식 안내2건으로 문의처·질문·초안·다음 행동 구성 |
| 내부 공공데이터 스킬 | 의료·돌봄·이동 분류에서 관련 자료 검색 → 보유 snapshot 코드 집계 → 출처·범위·빠진 자료 설명 → 기존 문의 준비에 연결 |
| 개인 진료기록·전화·의료진 회신 | 합성 사례·시연 어댑터. 공단 조회·실제 발신·예약·배차·동행 배정·결제·병원 전송 미연동 |
| 수동 작업 화면 | `/workspace.html`에 보존한 개발 검증 도구. 보호자가 순서대로 채워야 하는 서비스 첫 화면이 아님 |

`agent/config.mjs`가 키 설정에 따라 공급자를 구성하고, `agent/openai-provider.mjs`가 요청·도구 호출·reasoning replay를 Responses API 형식으로 변환합니다. 설정됨과 실제 계정 인증·모델 사용 가능은 다릅니다. 연결 절차·오류·한도는 [Agent API 문서](agent/README.md)를 따릅니다. Bedrock 어댑터는 보존하되 자동 선택·대체하지 않습니다.

## 실행과 첫 확인

Node.js 22 이상과 npm으로 저장소 루트에서 실행합니다. 기본 실행과 고정 예시는 모델 키·AWS 인증 없이 사용할 수 있습니다.

```bash
npm ci --ignore-scripts
npm run dev
```

로컬에서는 **`.env`의 `OPENAI_API_KEY=` 뒤에 키만 입력하고 서버를 다시 시작**하면 됩니다. 새로 복제한 저장소에서는 `.env.example`을 `.env`로 복사하되 기존 파일을 덮어쓰지 않습니다. 모델을 Terra로 바꾸려면 `OPENAI_MODEL=gpt-6.1-terra`로 설정합니다. 기본 Sol과 Terra를 동시에 호출하거나 오류 시 다른 모델로 자동 대체하지 않습니다.

터미널의 **http://127.0.0.1:4173** 을 엽니다. 키 설정 후 자유 요청을 보내면 모델 API를 호출합니다. 키 없이도 **대화 흐름 미리보기**에서 병원·자료·택시·동행의 처리 기록과 출처를 볼 수 있습니다. 이 고정 예시는 모델 응답과 구분합니다.

**말로 요청**은 지원 브라우저의 한국어 음성 인식을 사용합니다. 말이 끝나면 인식한 텍스트를 입력창에서 확인·수정한 뒤 **보내기**로 요청합니다. 실제 병원 발신과 구분합니다. 미지원·권한 거절·인식 실패 때는 텍스트로 계속할 수 있습니다. 실제 마이크 인식 검증과 음성 API 모의 검사는 구분합니다.

```bash
npm test
npm run build
npm run preview
```

`npm run preview`는 빌드한 화면과 같은 Node API를 제공합니다. 기본 4173 포트를 쓰므로 개발 서버를 먼저 종료합니다. 단순 파일 서버나 정적 S3만으로는 대화·preview API가 실행되지 않습니다. 대화 이력은 브라우저 메모리에 두고 서버에 원문을 저장하지 않습니다. 요청은 동일 출처의 API로 전달되며, 음성 처리의 외부 전송 여부는 브라우저 구현·정책을 따릅니다. 실제 환자 기록·인증정보는 입력하지 않습니다.

- 실행 환경변수: [예시](.env.example)의 서버·지도·OpenAI 설정. `.env`는 Git·정적 빌드·제출 ZIP에서 제외하며 브라우저에 키를 보내지 않습니다. AWS 배포에는 로컬 `.env`가 자동 전송되지 않습니다.
- 지도: 개발용 수동 화면의 Leaflet 1.9.4·OSM과 키 없는 Google Maps 외부 링크. 실제 경로·ETA·배차 API는 연결하지 않았습니다.
- 저장: 로컬은 인스턴스별 메모리, AWS는 DynamoDB입니다. AWS는 합성 준비 상태를 TTL1시간으로 보관하고 UTC 하루80개 대화 요청을 원자적으로 제한합니다. 한 요청 내부 모델 호출은 최대8회이며 금액 한도나 API 호출80회를 뜻하지 않습니다.
- 자세한 사용법·오류: [사용자 매뉴얼](docs/user-manual.md), [연결 준비](agent/README.md), [실제 검증 기록](docs/implementation-results.md).

## 화면과 보호자 기본 설정

의료·돌봄 서비스6곳의 실제 공개 화면을 비교한 [디자인 근거](docs/medical-reference-design.md)를 바탕으로 왼쪽 설정·중앙 현재 할 일·오른쪽 네 단계 진행 안내를 구성합니다. 선호 택시·휠체어·동행 필요 여부는 선택 사항이며 다음 요청의 실제 문의 준비에 반영합니다. 설정 변경만으로 모델을 호출하지 않습니다. 기기 설정3항목만 localStorage에 보관하고 대화·실환자정보·키는 저장하지 않습니다.

요청 예시는 대화 입력창 바로 위에 두고, 인물 사진은 제거했습니다. GPT Image로 생성한 제주 바다·현무암 배경 위에 현재 할 일과 흰색 단계 안내를 배치합니다. 원본·정확 prompt는 자산 명세, Pretendard 본문 글꼴과 라이선스는 외부 의존성에 기록합니다. 사용자가 지정한 에이전트 대화의 최종 혼디 로고를 적용했습니다. 귤 심볼과 소문자 `hondi`를 헤더에, 같은 심볼을 대화와 favicon에 사용합니다. 기존 프로젝트명은 제주 진료 나침반이며 저장소·배포 리소스 이름은 보존합니다. 외부 로고/사진을 복사하지 않습니다.

왼쪽 **환자 정보·건강 기록**에서 현재 환자·방문 정보와 문서 상태·출처·본문을 읽을 수 있습니다. Agent 응답과 같은 준비 상태를 보며 별도 입력이나 모델 호출이 필요하지 않습니다. **건강정보 고속도로는 실제 미연결**이고 최근 불러온 기록은 없습니다. 현재 기록은 합성 사례이며 실제 개인 기록 수신·동의·인증으로 표시하지 않습니다. [화면 계약](docs/patient-records-contract.md), [공식 연계 조사](research/healthway_integration_2026-10-31.md)를 따릅니다.

예시 버튼은 보이는 문구만 입력 초안으로 채웁니다. 날짜·대상 등을 확인·수정하고 직접 보내며, 숨은 시각을 추가하거나 클릭만으로 요청하지 않습니다. 짧은 화면에서는 보조 내용을 펼쳐 읽고 대화/준비 영역을 전환하며 공통 입력을 유지합니다. **응답 대기 중지**는 현재 화면의 기다림을 끝내고 원문을 복원합니다. 서버 작업이나 실제 발신이 중단됐다는 뜻은 아닙니다. 새 UI는 같은 방문 토큰·요청 ID로 재확인하며, 처리중/중단/완료 상태를 대조해 자동 재실행하지 않습니다. 토큰 없는 레거시 API의 첫 재시도에는 추가 이용 한계가 남습니다.

복합 요청은 최대8회 중 마지막을 요약에 남겨 완료한 준비와 아직 실행하지 않은 일을 설명합니다. [개선 전 실제 보호자 역할 평가](docs/reviews/2026-10-31-caregiver-usability.md)는5회의 공개 모델 대화이며, 후속 검증과 구분합니다.

## 현재 실행 상태 · 2026-11-01 14:07 UTC

웹/API 배포와 고정 예시는 정상입니다. 크레딧 소진 전 공개 Sol2과업과 각 준비 상태 복구를 확인했습니다. 추가 공개 요청은429/MODEL_RATE_LIMITED로 중단됐고, 로컬에 설정된 OpenAI 키의 직접 진단에서 `credit_balance_exhausted` / `insufficient_quota`를 확인했습니다. 일반 모델 대화에는 사용 가능한 API 크레딧이 필요합니다. 추가 모델 호출은 중단했으며 고정 예시·기존 준비의 읽기 복구는 모델 호출과 별개입니다. 성공한 검증과 한도 때문에 완료하지 못한 추가 검사를 [결과 기록3.19절](docs/implementation-results.md#319-방문-준비-이어하기와-실제-모델-과업-평가)에 구분했습니다.

## 현재 할 일에서 준비 이어가기

방문·자료 확인 → 병원·협진 준비 → 이동·동행 조율 → 방문 준비표를 하나의 여정으로 보여줍니다. 네 단계는 현재 상태와 남은 일을 읽는 탐색이며, 순서대로 폼을 제출하거나 다음 버튼을 누르는 절차가 아닙니다. 현재 할 일은 기존 준비 상태에서 계산하고, 보호자가 답할 조건·기관 회신 대기·의료진 확인·사람 인계·조건 변경 후 재확인을 구분합니다. 부족한 자료는 이후 단계에서도 남습니다. 답변이 도착하거나 도구가 실행됐다는 이유로 준비 완료를 표시하지 않습니다.

일반 요청은 `guidedPreparation:true`를 사용합니다. 명시적으로 진행한 방문 준비 범위 안에서 남은 공개자료 기반 택시·동행 문의 초안을 같은 요청의 도구 한도 안에서 최대2개 이어 준비할 수 있습니다. 조회·비교만 한 요청, 준비하지 말라는 제한, 이미 답변/실패/인계/재확인된 지원을 새 초안으로 덮는 작업은 이 경로에서 수행하지 않습니다. 전화·기록 불러오기·예약·배차·동의 변경은 자동 실행 범위가 아닙니다. 단계 탐색·답변 초안 선택·새로고침은 추가 모델 요청을 만들지 않습니다. 선택한 답변은 공통 입력에 초안으로 들어가며 직접 보내야 실행합니다.

새 Prompt·자동 이어가기의 실제 모델 품질은 API 크레딧 소진으로 미검증입니다. 과거12과업의 실모델 결과는 당시 커밋의 참고 이력으로 보존하며 새 로직의 통과로 인용하지 않습니다. 이번 범위와 현재 증거는 [현재 할 일 계약](docs/guided-visit-contract.md)과 [검증 기록](docs/implementation-results.md)을 따릅니다.

## 방문 준비 이어하기

같은 탭에서 새로고침하면 **마지막 확인된 방문 준비와 남은 일**을 불러옵니다. 대화 원문·과거 모델 답변은 보관하지 않습니다. 방문 상세의 **저장된 준비 다시 확인**으로 처리중/중단/완료 상태와 확인·만료 시점을 읽을 수 있습니다.

첫 요청 전에 만든 opaque 토큰만 sessionStorage에 저장합니다. 서버는 전송받은 토큰을 해시로 조회하고 원문 토큰을 DB·모델·로그에 저장하지 않습니다. 같은 방문·요청의 응답이 유실돼도 receipt로 재실행을 막고, 다른 본문으로 같은 요청 ID를 쓰면 거부합니다. 조회만으로 모델·한도·외부 작업을 실행하지 않습니다. 저장 차단과1시간 만료·연결 실패는 따로 안내합니다. 토큰 없는 이전 API 요청과 계정/가족 공유는 [연결 문서](agent/README.md)의 범위를 따릅니다.

## 전화로 협진·이동 준비하기

**전화·협진 준비**에서 기존 도외 병원·제주 병원·택시/휠체어 이동·병원동행의 목적, 문의처, 질문, 최소 전달 항목과 AI 고지 예정 문구를 볼 수 있습니다. **이 내용으로 문의 준비**도 입력 초안을 만들며 자동 발신하지 않습니다. 자연어로 협진을 요청하면 양 기관의 접수·의뢰/회송 절차와 준비 자료, 의료진 확인이 필요한 기록을 이어 정리합니다.

휠체어 요청은 교통약자센터 등 현재 조건에 맞는 문의 경로와 이용자격·회원등록·탑승 방식·승하차 보조·동행인·희망 시각·차량 가능 질문으로 이어집니다. 가능 응답과 자격 확인·실제 배차·예약 확정은 구분합니다.

사용자는 전화 서비스 계정이 없어 **준비 흐름·시연부터 완성**하기로 했습니다. 현재 실제 위임 검증·발신·녹음/전사/보관·민감정보 전달은 수행하지 않습니다. [공통 전화 정책](docs/call-workflow-contract.md)을 Agent Prompt·도구·화면에 함께 적용하며, [참고 출처와 실제 확인 범위](research/ai_phone_policy_2026-10-31.md)를 기록합니다. 법률 검토 완료나 실제 기관의 환자 수락을 뜻하지 않습니다.

## 진료 연결과 후속 할 일

혼디는 진료 장소를 결정하지 않습니다. 의료진·기관의 확인에 따라 **도내 전환 / 일부 제주 진행 / 도외 유지**에 필요한 준비를 연결하며 확인 전에는 미확인으로 남깁니다. 건강기록의 요약에서 끝내지 않고 원문·작성일·확인 여부를 붙여 발급·제출 문의와 다음 일로 이어갑니다.

진료 연결 여정에서는 세 상황을 명시적 합성 예시로 확인할 수 있습니다.

- **자료 누락:** 판독문 미확보 → 발급 절차 문의 → 제주 제출 방식 확인.
- **제주 기관 접수 거절:** 해당 요청의 운영 응답을 기록하고 다른 문의 후보와 기존 병원에 확인할 일을 정리. 임상 부적합으로 단정하지 않음.
- **진료 시각 변경:** 이전 차량·동행 안내를 재확인으로 표시하고 바뀐 조건·귀가/동행 재조정 질문을 연결.

병원 휠체어 대여·수령/반납과 차량 탑승 방식·승하차·동행인·지연 대응을 함께 확인합니다. 공개 데이터의 지역·기관종류·지원조건은 문의할 후보와 질문을 바꾸며, 실제 차량·동행인 가용성은 공개 등록 정보로 확정하지 않습니다. [구현 계약](docs/care-journey-contract.md)을 따릅니다. [공식 비교 자료](research/care_journey_positioning_2026-10-31.md)에서 확인한 AI 전화·기록 연결 기능을 최초라고 주장하지 않으며, 병원 간 후속 작업을 줄이는 것이 차별화 가설입니다.

### 대화에서 필요한 공공데이터 찾아 쓰기

공공데이터 검색은 **혼디가 진료 준비 중 사용하는 내부 스킬**입니다. 새 챗봇이나 데이터 메뉴를 만들지 않습니다. “애월과 서귀포의 의료·돌봄 등록 자료를 비교해줘”, “우리 동네 이동·동행 문의처를 찾아줘”처럼 기존 대화창에 요청하면 모델이 `search_public_data`·`analyze_public_data`를 선택할 수 있습니다. 지역별 집계·분모·중복 제외는 코드가 계산하고, 답변은 근거와 다음 문의를 설명합니다.

저장소는 분류 카탈로그와 실제 계산 자료를 분리한 **읽기 전용 JSON/CSV**입니다. 허브1,259개·센터70개, 총1,329개 **메타데이터**를 의료·돌봄·이동 등으로 색인하며, 원자료를 모두 확보한 뜻은 아닙니다. 계산·후보 조회에는 위의4종과 별도 공식안내2건만 사용합니다. 새로운 관리형 DB나 실시간 API는 추가하지 않았습니다.

병원13개는 공개20행에서 폐업7행을 제외한 표본입니다. 특정 지역에서 관측0행이어도 시설이 없다는 뜻은 아닙니다. 돌봄 자료도2020년 등록 주소 기준이며 서비스 관할·현재 인력을 나타내지 않습니다. 애월읍과 서귀포시처럼 행정 수준이 다르면 분모를 따로 표시하고 비율을 직접 비교하지 않습니다. 센터 이동시간 원자료가 없으면 시간대별 ETA를 만들지 않고, 필요한 자료와 택시에 확인할 질문을 반환합니다. 비교 질문만으로 환자의 실제 출발지·휠체어 조건·예약 상태를 바꾸지 않습니다.

키·네트워크 없이 같은 조회를 재현할 수 있습니다.

```bash
npm run data:catalog -- --check
npm run data:query -- search --purpose hospital --query 병원
npm run data:query -- analyze --analysis facility_compare --areas 애월,서귀포
npm run data:query -- analyze --analysis support_candidates --area '제주시 애월읍' --wheelchair true
npm run data:query -- analyze --analysis travel_time --area '제주시 애월읍'
```

`data:catalog --check`는 저장된 감사CSV로 색인을 대조하는 검사이며 원자료/API 갱신이 아닙니다. 자료별 재취득 명령과 이용조건은 [데이터 명세](docs/data-sources.md), 입력·출력과 준비 도구 연결은 [스킬 계약](docs/public-data-skill-contract.md)을 따릅니다.

## 개발·검사·제출

UI·Agent·인프라·문서는 전용 worktree에서 작업하고 커밋 단위로 통합합니다. [하네스 규칙](orchestration/README.md), [공통 인터페이스](docs/conversation-agent-contract.md), [검증 기록](docs/implementation-results.md)을 따릅니다. 개발용 서브에이전트 분업은 제품의 다중 임상 Agent 기능이 아닙니다.

```bash
npm run observe
npm run eval
npm run rollback -- <통합-커밋-SHA>
```

이 명령은 브랜치·worktree가 있는 개발 저장소용입니다. 자동 eval은 기계 검증한 규칙만 평가하며 임상·법률·데이터 권리·제출 준비 전체를 보장하지 않습니다. 선택 브라우저 검사는 Playwright와 Chromium이 필요합니다. `test:conversation`은 키를 끈 별도 로컬 서버에서 미연결·고정 예시·연결 상태 fixture를 검사합니다. 공개 유료 서버를 대상으로 실행하지 않습니다. 실제 공개 LLM 스모크는 별도 기록으로 구분합니다.

유료 모델을 호출하지 않는 QA 서버를 `OPENAI_API_KEY= PORT=4180 node scripts/server.mjs`로 먼저 실행합니다. 별도 터미널에서 선택 QA 도구를 설치·실행합니다. 기존 설치는 `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH`, 서버 주소는 `BASE_URL`로 지정할 수 있습니다.

```bash
npm install --no-save --package-lock=false playwright@1.64.1
npx playwright install chromium
BASE_URL=http://127.0.0.1:4180 npm run test:conversation
BASE_URL=http://127.0.0.1:4180 npm run test:browser
BASE_URL=http://127.0.0.1:4180 npm run test:journey
```

```bash
npm run eval:agent -- --list
# 합성 과업의 실제 모델 평가: 키 설정 후 명시적으로 실행
npm run eval:agent -- --live
APP_REVISION=local-preview npm run build:agent
npm run package
```

`PLAYWRIGHT_MODULE`·`CHROMIUM_PATH`로 선택 QA 도구를 지정하고 `npm run proposal:pdf`로12페이지 기획서를 재생성할 수 있습니다. 같은 실행 지문의 대화 예시 캡처와 Poppler `pdfinfo`가 필요합니다. PDF는 서비스 실행 의존성이 아닙니다.

Lambda 빌드와 ZIP 패키징에는 Python 3가 필요합니다. Lambda ZIP은 `index.mjs`·`deployment.json`으로 구성하며 제출용 `output/jeju-care-compass-mvp.zip`과 구분합니다. 제출 ZIP은 개발 스냅샷이며 이번 버전의 재생성·독립 설치·최종 제출 확인은 [추적표](docs/submission-checklist.md)를 따릅니다. 센터 PC의 GPU·로컬 모델은 요구하지 않지만 센터 실기기 검증은 별도입니다.

## 전화가 막혔을 때의 인계

실패 이유·시도 내역·남은 일·담당자를 보존합니다. 무응답은 사용자가 명시한 시연 횟수/시간 안에서만 재시도하며 기본은 정책 미설정입니다. 최초 포함 최대1~3회·1~120분을 지원하고 같은 정책을 반복 적용해도 시도/시간 범위를 초기화하지 않습니다. AI 응대 거절은 자동 반복을 멈추고 보호자에게 번호·문의 내용을, 본인확인은 환자 본인이 해야 할 단계를 넘깁니다. 서류 부족은 발급/제출 작업으로, 예약 불가는 허용한 다른 날짜의 문의로 이어집니다.

별도 무응답·AI 거절·본인확인·서류/일정 막힘 예시는 합성입니다. 재시도 정책이나 다음 가능 시각은 실제 발신 예약이 아니고 현재 실발신은 없습니다. 실제 위임·민감정보·전화/예약 확인 경계를 유지합니다.

## 채팅으로 요청하고 오른쪽에서 준비 상태 확인

보호자는 입력창 한 곳에서 요청합니다. 자료·병원·이동/동행을 ○ 준비 결과 있음 · △ 추가 확인 · × 막힌 문의로 요약하고 미시작/불필요는 중립 대시로 구분합니다. ○는 자료나 문의 초안·합성 안내가 있다는 뜻이며 진료·예약·배차 확정이 아닙니다.

한 화면 작업 공간은 [최신 계약](docs/viewport-workspace-contract.md)을 따릅니다. 공통 입력을 하단에 유지하고 PC 오른쪽 네 준비 요약과 좁은 창의 대화/준비 전환을 제공합니다. 각 카드 안의 스크롤 대신 중앙 대화와 전체 준비 영역에서 읽으며, 예시·도움말·방문 상세는 필요한 때 펼칩니다. 환자 이름/주 행동의 주황과 탐색/보조 행동의 초록, 기존 ○△× 의미색을 유지합니다. 초안 선택·상세 열기·패널 전환만으로 모델·전화·예약을 호출하지 않습니다. 실제 진행과 마지막 확인 사례는 최종 응답까지 구분합니다.

진행 조회는256bit 임시토큰과 고정 도구/단계 메타데이터만 사용합니다. 로컬메모리·AWS기존DynamoDB의120초TTL 기록이며 환자이름·원문·인자·결과·reasoning·토큰원문을 저장하지 않습니다. 요청/시도별 최대26번·2.5초 이상 간격·1개씩 조회하고, 응답/중지/새대화 때 멈춥니다. 진행 연결 실패는 원래 모델 응답을 막지 않습니다. 현재 Lambda 동시 실행 상한은2이므로 공개 검증은 순서대로 수행합니다. 전화·건강기록·예약/배차의 실제 연결 범위는 위의 구분을 그대로 따릅니다.

```bash
BASE_URL=http://127.0.0.1:4180 npm run test:board
```
