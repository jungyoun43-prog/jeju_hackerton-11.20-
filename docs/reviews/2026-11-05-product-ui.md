# 제품 화면 리디자인 검토 · 2026-11-05

해커톤의 실행 범위는 공개 데이터와 합성 문의 결과로 방문 준비를 이어가는 시연이다. 실제 택시 배차·기관 발신을 필수 완료 조건으로 두지 않는다. 일반 모델 대화의 품질 검증과 실제 기관 업무는 각각 별도 상태로 관리한다.

[공식 제품 조사](../../research/product-ui-references-2026-11-05.md)에서 Things의 연속된 작업면, Linear의 정렬된 상태 행, Attio의 대상 정보와 작업 구분을 참고했다. Front의 공개 업무 탐색도 확인했다. 제품에 로그인한 조사나 외부 코드·이미지 복제가 아니다. 지정 insane-search는 선택 의존성 부재로 실패했으며 기존 Chromium에서 공개 자료를 관측한 결과와 구분했다.

중앙의 현재 작업을 대표 제목으로 키우고 사례 맥락은 작은 헤더에 뒀다. 반복 프레임 대신 흰 작업면·얇은 경계와 행을 사용하며 왼쪽은 설정/보조 도구, 오른쪽은 네 단계 탐색을 담당한다. 기존 혼디 로고·Pretendard·주황 이름/주 행동·초록 선택·제주 배경·100dvh·단일 입력을 유지했다. 새 런타임 의존성이나 인물 이미지는 추가하지 않았다.

텍스트 초안 선택은 입력 옆의 짧은 상태 문구로 알린다. 실제 음성 실패의 피드백과 명시적으로 여는 전체 안내는 유지했다. 초안 선택·교체 취소·수정·직접 전송을 구분하고, 단계를 읽는 동작은 모델이나 외부 작업을 호출하지 않는다.

첫 시각 검토에서 초기 PC 입력이 하단에서 떠 있는 문제와 연결 상태가 대표 작업 위에서 경쟁하는 문제를 발견했다. 입력 행 위치를 고정하고 상태를 작업 메타정보로 옮겼다. 모바일 전화 창의 닫기 버튼이 가려졌다는 첫 지적은 원본 PNG와 실제 DOM 좌표로 철회했다. 동일 파일을 original로 보면 버튼이 보이므로 제품에 우회 수정을 넣지 않았다. 원문과 정정문을 모두 보존했다.

이후 작은 창·큰 글자에서 접근성 제목의 위치로 문서가 넘치던 문제는 해당 작업 영역에 기준 위치를 지정해 해결했다. 실제 브라우저 배율을 바꿀 때 열린 설정 서랍의 초점 항목이 가려지면 해당 항목을 가까운 위치로 드러내도록 기존 resize 처리에 다섯 줄을 추가했다. 초점·값·선택 범위는 유지한다.

최종 실행 지문은 `83ba34ae6d299935b2626087639473d7c501f9bb4d50b97a4420573399022184`다. 최종14개 화면은 같은 소스의 실제 keyless 체험2건·일반 요청0·모델0에서 확보했다. 독립 검토자는 초기/체험/초안의 PC·모바일과 모바일 안내, 총7개 원본을 직접 보고 **입력 하단 고정과 상태 위치 두 수정이 해결됨**으로 판정했다. 이 ship 판정은 지정된 수정의 확인이며 전체 화면·세계적 품질·사용자 만족 인증이 아니다. 원본과 판정의 SHA는 `orchestration/runs/product-design-review.json`에 연결한다.

Impeccable context launcher는 권한126으로 실행되지 않았다. 기존 PRODUCT/DESIGN과 적용 지침을 직접 읽었으며 detector·seed·roll을 새로 실행하거나 과거 결과를 재사용하지 않았다. 전체 스킬 절차 통과라고 표시하지 않는다. 디자인 명세와 색·반응형·동작 규칙은 [DESIGN.md](../../DESIGN.md)와 sidecar에 기록했다.

기능 검사·실제 탭 확대·성능·PDF·공개 배포·독립 ZIP의 현재 결과는 [구현 결과3.22절](../implementation-results.md#322-제품-참고-기반-작업-화면-재설계)을 따른다. 실제 휴대폰 키보드/마이크·다른 브라우저·스크린리더·보호자 참여 관찰은 이 캡처 검토에 포함하지 않는다. 현재 모델 품질은 기존 크레딧 소진으로 미검증이며 추가 유료 호출은 하지 않았다.
