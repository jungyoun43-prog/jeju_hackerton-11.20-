# 첫 모의 심사 기록

검토일: **2026-10-31**. 실제 서브에이전트 5개가 README.md·AGENTS.md와 조정자가 공식 원문에서 확인한 평가기준을 바탕으로 검토했다. 평가자들은 파일을 수정하거나 외부조사를 하지 않았다.

검토 당시 입력: 주제·데이터셋·기술 스택 미정, 실행 코드 없음. A 소상공인 비교, B 생활시설 비교, C 특정 통계 비교·보고서 작성은 조건부 가설로만 전달했다. 조정자가 뒤이어 목록용 공개 응답 일부를 확인했지만 원자료·이용조건은 여전히 미확인이다.

**전체 판정: 5개 항목 모두 평가불가.** 아직 부족한 증거를 0점으로 환산하거나 예상 총점을 만들지 않았다. 아래는 각 독립 검토의 요약이다.

## `judge_topic` — 주제, 15점

- 확인: 대회 목적과 지정 데이터 활용 방침. 사용자·반복 문제·차별점은 미정.
- 제안: C의 완결된 분석 흐름에 실제 데이터가 지원하는 A 또는 B의 질문 하나를 담는다.
- 우려: 일반적인 챗봇 소개에 머무르거나, 미확인 수요·데이터를 전제하거나, 자료가 설명할 수 없는 추천을 제공하는 것.
- 확보할 증거: 사용자 문제 확인 기록, 같은 과업의 기존 방식과 Agent 비교, 사용자 조건 변경에 따른 실제 결과 변화.
- 다음 작업: 데이터로 답할 수 있고 실제 사용자가 확인한 대표 질문 하나를 선정한다.

## `judge_data` — 데이터, 20점

- 확인: 지정 목록 사용 방침. 실제 자료·스키마·이용조건·처리 코드 부재.
- 제안: 24~48시간 안에 상세 출처·표본·단위·기간·공간 범위·권리를 확인하고 핵심 질문을 계산한다.
- 우려: 출처만 표시하고 계산에는 미사용, 다른 단위·기간을 그대로 비교, 이용조건·결측 처리 누락.
- 확보할 증거: 데이터 명세, 입력부터 계산까지의 기록, 수동 정답 대조표.
- 다음 작업: 후보 자료 하나를 실제로 읽어 대표 질문이 계산되는지 확인한다.

시설 좌표만 있으면 직선거리·분포까지 설명하고 실제 이동 편의는 단정하지 않는다. 데이터 변경 대조는 의존성을 보여줄 뿐 분석의 적절성 전체를 증명하지 않는다.

## `judge_agent` — 기술·완성도, 25점

- 확인: 실행환경 요구사항. 실제 도구 실행·오류 처리·성능 측정 기록 부재.
- 제안: 질문 해석 → 조건 확인 → 분석 계획 → 도구 계산 → 검증 → 보고서의 핵심 흐름을 완성한다.
- 우려: 모델이 수치와 완료를 창작, 시연 한 건 외에는 실패, 실제 외부 의존성과 문서 불일치.
- 확보할 증거: 질문·도구 입력·결과가 연결된 기록, 정상·조건 변경·실패 검증, 새 환경 실행과 자원 측정.
- 다음 작업: 확인된 데이터로 핵심 계산 도구 하나를 만들고 실제 호출한다.

개발 중 심사 에이전트 5개와 제출 서비스의 구성은 별개다. 제출 서비스는 하나의 조정 에이전트와 분석 도구부터 시작할 수 있다. 외부 모델이 실패하면 계산 완료와 설명 미완료의 범위를 구분한다.

## `judge_usability` — 편의·실용성, 25점

- 확인: 비전문가 도민과 센터 이용 맥락. 화면·사용자 관찰 기록 부재.
- 제안: 질문 선택 → 조건 확인 → 결과·근거 확인 → 보고서 저장의 동선을 만든다.
- 우려: 전문용어와 설정 부담, 결과 활용 방법 부재, 실패·오래된 결과의 불명확한 표시.
- 확보할 증거: 첫 사용자 전체 수행 기록, 완료·시간·도움·실패 관찰표, 센터 수준 환경의 오류 복구 기록.
- 다음 작업: 실제 질문 하나를 대상으로 화면 흐름을 준비하고 비전문가에게 과업을 맡긴다.

ELO 비교에서는 대상 사용자·질문·실제 결과·근거가 빠르게 이해되도록 제시한다. 이는 전달 전략이며 새 공식 평가항목은 아니다.

## `judge_reliability` — 신뢰·재현성, 15점

- 확인: 제출 요구사항. 원자료·정답 대조·재실행 기록 부재.
- 제안: 수치별로 출처·기준시점 → 전처리 → 계산식·단위 → 결과를 연결한다.
- 우려: 재계산할 수 없는 출처 표시, 불확실한 자료의 과도한 해석, 시연과 제출 환경 불일치.
- 확보할 증거: 분석 추적 기록, 수동 정답과 실패 사례 대조표, 새 환경 설치·재실행 기록.
- 다음 작업: 작은 실제 표본의 수동 정답을 만들고 핵심 계산과 비교한다.

수치·근거의 재현과 LLM 문장의 일치는 구분한다. 센터에서 실제 검증하기 전에는 센터 실행을 완료했다고 표시하지 않는다.

## 조정 결과

공통 제안은 **데이터 검증 → 사용자·질문 하나 확정 → 실제 계산부터 근거 보고서까지 완성 → 비전문가 사용과 재실행 검증**이다. 서비스 주제나 스택은 확정하지 않았다.

다음 검토의 입력은 개별 데이터 명세·원자료 표본·대표 질문·수동 계산 결과다. 자료를 확보하면 [모의 심사 규약](../judging-agents.md)으로 5개 항목을 다시 검토한다.
