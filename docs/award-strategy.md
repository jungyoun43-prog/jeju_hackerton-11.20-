# 수상 전략 제안

작성·공식 자료 확인일: **2026-10-31**. 서비스 주제·데이터셋·기술 스택은 미확정이며, 아래 실행 순서는 제안이다. 수상 가능성이나 실제 심사 점수를 예측한 문서가 아니다.

## 평가에서 역산한 우선순위

공식 평가는 전문가 평가 70%와 ELO 방식의 참가팀 상호 평가 30%를 결합한다. 아래 배점은 **전문가 평가 내부의 100점** 기준이다.

| 공식 평가항목 | 배점 | 우리가 확보해야 할 증거 |
| --- | ---: | --- |
| 분석 주제의 타당성과 창의성 | 15 | 특정 사용자의 반복되는 문제, 기존 방식과의 차이, 사용자 확인 기록 |
| 필수 데이터 활용 적절성 | 20 | 지정 자료가 실제 계산과 결론을 결정하는 흐름, 적절한 비교·전처리 |
| AI Agent 기술성 및 완성도 | 25 | 질문에 따른 도구 선택, 실제 실행 기록, 조건 변경·실패 처리 |
| 편의성 및 실용성 | 25 | 비전문가가 직접 과업을 완료한 기록, 이해 가능한 결과와 사용 방법 |
| 결과 신뢰성 및 재현성 | 15 | 수치별 근거와 해석 한계, 수동 정답 대조, 새 환경에서의 재실행 |

동점에서는 기술·완성도 → 편의·실용성 → 필수 데이터 활용 순으로 비교한다. 따라서 **사용자 한 명의 분석 과업 하나를 끝까지 안정적으로 처리하는 것**을 개발 우선순위로 제안한다. 이 우선순위는 공식 배점에서 도출한 팀의 전략이다.

출처: [공식 대회 페이지](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge), [페이지가 사용하는 공개 응답](https://daker.ai/api/hackathons/jeju-ai-bigdata-agent-challenge)의 `evaluationCriteria`·`rules`·`stages`. 확인일: 2026-10-31.

## 추천하는 서비스 범위

**확인된 제주 데이터로 지역 또는 기간을 비교하고, 계산 근거가 연결된 보고서를 만드는 Agent**를 우선 검토한다. 데이터 검증 후 대상 사용자와 대표 질문을 하나로 좁힌다.

사용 흐름 제안:

1. 사용자가 처리 가능한 질문 예시를 선택하거나 질문을 입력한다.
2. Agent가 지역·기간·비교 기준을 해석하고, 빠진 조건을 확인한다.
3. 실제 데이터에 맞춰 분석 계획과 도구를 선택한다.
4. 코드가 필터·집계·비교를 수행하고 결과의 단위·결측·분모를 검사한다.
5. 사용자는 비교표·차트·설명과 함께 출처·기준시점·한계를 확인하고 보고서를 저장한다.

모델은 질문 해석·도구 선택·설명을 담당하고 수치 계산은 검증 가능한 코드가 담당하도록 제안한다. 데이터나 API가 없으면 해당 분석을 중단하거나 가능한 범위를 설명한다. 이전 결과를 보여줄 때는 실행일과 데이터 기준일을 표시한다.

### 주제 후보와 선택 조건

| 조건부 후보 | 장점 | 선정 전에 확인할 것 |
| --- | --- | --- |
| 소상공인의 지역·기간별 지표 비교 | 누가 무엇을 판단하는지 설명하기 쉬움 | 비교 가능한 지역·기간·단위·지표가 실제로 있는지. 집계 자료로 개별 점포 수익을 단정하지 않기 |
| 도민의 생활시설 분포 비교 | 결과를 지도·표로 설명하기 쉬움 | 시설 분류·좌표·지역 범위·최신성. 이동망이 없으면 직선거리나 분포로 범위 제한 |
| 센터 방문자의 특정 통계 비교·보고서 작성 | 탐색부터 결과 저장까지 완결하기 좋음 | 사용자가 반복하는 질문 하나와 그 질문을 지원하는 원자료. 범용 분석 도구로 범위가 커지지 않게 제한 |

이 후보들의 필수 데이터 확보와 분석 가능성은 아직 입증되지 않았다. 지정 목록의 모든 자료를 검토하거나 후보 간 우열을 확정한 것도 아니다.

## 먼저 통과해야 할 데이터 확인

기획 초반 24~48시간을 데이터 확인에 배정한다는 제안이다. 다음 증거가 갖춰지는 후보부터 선정한다.

- [사용자 지정 목록](https://jejudatahub.net/data/list/12)에서의 등록 사실과 개별 상세 출처.
- 내려받거나 호출해 확인한 실제 원자료 표본, 항목 정의·단위·기간·지역 범위.
- 공식 원문으로 확인한 이용조건과 제출·센터 제공 시 준수할 사항.
- 실제 표본으로 대표 질문 하나를 계산한 결과와 수동 정답의 일치 여부.

접근 승인 시점이나 필요한 이용 권한이 불명확한 자료는 선정을 보류한다. 메타데이터에 적힌 API 항목과 실제 호출 성공은 구분한다. 여러 자료를 결합한다면 결합 키와 집계 단위가 맞는지도 확인한다.

2026-10-31에는 `insane-search`로 **목록용 공개 응답 첫 페이지의 일부 메타데이터**를 읽었다. 예를 들어 「소상공인시장진흥공단 소상공인 경기동향(BSI) 현황」의 등록 정보는 확인했지만, 원자료·세부 지역 구분·이용조건은 확인하지 않았다. 이 자료를 지역별 입지 분석에 쓸 수 있다는 뜻은 아니다.

출처: [제주데이터허브 목록용 공개 응답](https://jejudatahub.net/api/data?includedKeywords=&excludedKeywords=&categories=&userId=&dataType=&orderBy=createAt&authYn=false&autoUpdateYn=false&keyword=&keywordOrTagFlag=keyword&isPaging=true&start=0&pageNumber=1&length=10). 확인일: 2026-10-31. 응답의 메타데이터만 확인했으며, 사용자 지정 화면 전체와 원자료의 검증을 대체하지 않는다.

## 심사 때 보여줄 장면

- **실제 수행:** 질문 → 해석한 조건 → 사용한 도구 → 계산 결과 → 보고서가 연결되는 한 번의 실행.
- **조건 변경:** 지역·기간 등 지원하는 조건을 바꾸면 실제 계산과 설명이 적절히 달라지는 실행.
- **실패 처리:** 자료 없음·지원하지 않는 질문·외부 서비스 장애를 성공으로 표시하지 않는 실행.
- **직접 사용:** 처음 접한 비전문가가 도움을 얼마나 받고 어디까지 완료했는지 보여주는 기록.
- **재실행:** 다른 환경에서 README를 따라 같은 데이터·조건의 수치를 재현한 기록.

데이터 제거·값 변경 대조는 데이터 의존성을 검증하는 데 사용한다. 이것만으로 분석 방법의 타당성이 입증되지는 않는다. 사용하지 않는 값이나 순위에 영향을 주지 않는 값을 바꿨다면 결과가 같을 수도 있다.

사용성 검증은 시도 인원, 독립 완료 인원, 시간, 도움 요청, 중단 이유를 함께 남긴다. LLM 설명 문장의 완전한 일치와 계산 수치의 재현은 별도로 다룬다. 센터 PC에서의 성능은 실제 또는 동등 조건 측정 전까지 미검증으로 표시한다.

상호 평가 기간은 공식 표기상 11월 23일 12:00~11월 27일 10:00이다. 안내문에는 최소 투표 참여 조건이 있으므로 담당자를 정하고 실제 요구 횟수와 최신 공지를 확인한다. 현재 확인 내용만으로 특정 최소 횟수를 확정하지 않는다.

## 조사 방법과 현재 제약

처음에는 `insane_search`라는 호출 도구를 찾지 못해 공식 페이지를 웹 도구와 직접 요청으로 확인했다. 이후 로컬 `insane-search` 스킬을 발견했다. 첫 실행은 `curl_cffi`와 브라우저 실행환경 부재로 실패했고, 임시 Python 환경에 필수 패키지를 준비한 뒤 엔진으로 공식 대회 공개 응답과 데이터 목록용 공개 응답을 다시 가져왔다.

두 성공 응답의 엔진 판정은 `weak_ok`이며 JSON 내용을 직접 검토했다. 렌더링된 전체 목록, 개별 원자료 다운로드·API 실행, 이용조건 검증은 완료하지 않았다. 조사용 임시 패키지는 서비스의 확정 기술 스택이나 실행 의존성이 아니다.

실제 5개 서브에이전트의 첫 검토는 [2026-10-31 검토 기록](reviews/2026-10-31.md)에 정리했다.
