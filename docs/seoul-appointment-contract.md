# 제주 준비에서 서울 대학병원 예약까지 · 2026-11-16

사용자 요청은 서울 대학병원 진료의뢰서·의료진·월별 빈 시간·왕복 교통을 자연스럽게 연결하는 것이다. 중증도만으로 서울행·진료과·의료진 적합성을 결정하거나 제주 접수 거절을 임상 결론으로 해석하지 않는다.

## 사용자 흐름

1. 첫 화면 또는 제주 체험 중 **서울 대학병원 예약 준비**에서 연다. 기존 대화·자료·초안을 보존한다.
2. 가상 병원과 **27개 진료과**를 선택한다. 내과계·외과계·그 밖의 진료과로 분류하고 이름 검색·키보드 선택·검색 결과 없음 안내를 제공한다. 의뢰서의 진료과와 실제 접수 요건은 병원에 확인한다.
3. 초진·같은 병원/같은 과 재진·미확인, 의뢰서 보유·기존 제출·미준비·미확인을 구분한다. 미준비/미확인도 일정은 둘러볼 수 있고 발급·첫방문 예약 상담으로 이어진다. 판독문을 의뢰서로 대체하지 않는다.
4. **월별 달력에서 희망 날짜 하루 또는 기간을 먼저 선택**하고 해당 기간의 의료진·시간을 비교한다. 2026년 11월~2027년 1월을 이동하고 빈자리·마감·미공개·지난 날짜·시연 휴진일을 구분한다. 최초 빈자리로 이동하는 버튼은 명시적으로 누른다. 날짜만 고르면 예약되지 않는다. 최신 [날짜 우선·교통 연결 계약](date-first-booking-contract.md)을 따른다.
5. 희망 일정 요청과 서류/일정 상담 요청을 구분한다. 의뢰서 상태·방문 유형 미확인은 합성 확정 회신을 허용하지 않는다. 보유 응답으로 실제 문서·병원 접수가 검증되지는 않는다.
6. 접수 대기 → 확정 회신/의뢰서 보완/다른 일정 안내를 시연한다. 실제 전송·예약은 없다.
7. 집→제주공항, 항공편, 도착 공항→병원, 귀가의 네 구간을 준비한다. 버스·택시·교통약자 차량·가족 차량, 전날/당일 이동, 검사 후 귀가·숙박, 첫차/막차·환승·항공사 수속/수하물 마감·휠체어·지연 대안을 정리한다.
8. 선택 입력한 한국 시각을 대조해 항공 출발보다 늦은 공항 도착, 진료보다 늦은 병원 도착, 귀가 순서 충돌을 표시한다. ETA나 실제 탑승 가능성을 계산하지 않는다. 검사 종료 미정은 귀가편 확정 전 확인할 일로 남긴다.
9. 병원·진료과·일정·이동 조건 변경은 기존 체크를 해제하고 재점검을 남긴다. 준비표는 원래 자료 상태·희망 일정·교통 계획·미확인·출처를 함께 내려받는다.

## 데이터와 실행 경계

- 병원 2곳, 진료과 27개, 의료진 55명과 고정 시간표는 합성 fixture다. 실제 기관 명부·의료진 가용성·대기기간 통계가 아니다. 일부 의료진의 일정 미공개도 상담으로 연결한다.
- 진료과는 명칭 탐색용이다. 공공데이터의 실제 제주 기관 데이터 수와 가상 서울 fixture 수를 합산하지 않는다.
- 순수 상태: `app/appointment-demo.js`, `appointment-departments.js`, `appointment-travel.js`. 실제 React 화면: `web/components/appointment-*`와 `department-picker.jsx`. Next 전환은 [전환 계약](react-next-migration-contract.md)을 따른다.
- 탭의 메모리 상태만 사용한다. 예약·항공·교통 입력에 API·LLM·전화·DB·localStorage/sessionStorage 쓰기를 추가하지 않는다. 새로고침하면 초기화되고 요청 내용은 기관에 전송하지 않는다.
- 기존 case의 자료·공개 출처·출발 지역·휠체어 조건을 읽는다. 진찰·의뢰서·동의·예약 확정·임상 결과를 생성하지 않는다.
- 제주 공항행 문의 후보는 기존 공개 택시 또는 공식 교통약자센터 정보다. 실제 운행 범위·이용자격·차량 미확인을 남기며 서울 공급자로 배정하지 않는다.
- 체크는 **문의할 내용 정리**다. 실제 운항·노선별 시간·좌석·운임·예약·배차 확인으로 바뀌지 않는다. 모든 체크를 선택해도 실제 이동 준비 완료는 false다.
- 시연 상태는 `requested_demo`, `consultation_requested_demo`, `documents_needed_demo`, `confirmed_demo`, `change_requested_demo`다. 기존 실제 reservationConfirmed/clinicalAcceptanceConfirmed는 변경하지 않는다.

## 화면·보존

왼쪽 색 막대 박스와 반복 경고 상자는 사용하지 않는다. 의뢰서 상태는 정렬된 행·본문, 재확인은 한 번의 짧은 문장으로 읽는다. 반복 홍보성 제목을 접수 조건·진료 일정·왕복 교통처럼 구체적인 작업 이름으로 바꾼다. 구분선·선택 상태·초점·오류의 의미는 보존한다.

한 화면 공유 스크롤과 같은 공통 입력을 사용한다. 서울 체험을 닫으면 기존 DOM·초안·초점·스크롤·선택 단계로 복귀한다. 숨겨진 영역은 inert, 터치 조작은 44px, 입력은 16px를 유지한다. 마감 슬롯·불완전 요청은 비활성화하고 중복 시연 요청을 무시한다.
