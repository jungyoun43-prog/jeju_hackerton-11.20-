# 제주 진료 나침반 기능 파이프라인

작성일: 2026-10-31 · PRD v0.5 · 상태: 방문 이동·동행 지원 확장과 대시보드 통합 기준

**기존 병원의 진료 준비와 제주 현지 방문을 이어주고, 택시·동행 지원까지 가족이 확인할 수 있게 정리하는 Agent.**

환자·보호자가 사실과 위임 범위를 확인하고 의료진이 진찰·협진·진료 계획을 판단한다. Agent의 목표는 공개 자료와 문의·회신에서 미충족 조건을 찾아 다음 작업으로 바꾸는 것이다. 현재 런타임은 결정적 시연이며 실제 전화·배차·동행 배정·결제·기관 전송·LLM은 연결하지 않았다. 아래 신규 지원 흐름은 구현·통합 중이고 최종 실행 증거는 [결과 기록](implementation-results.md)을 따른다.

## 1. 시작 상황과 입력

> “서울에 사는 딸입니다. 애월 어머니의 제주 진찰 자료를 기존 주치의에게 전달할 준비를 해 주세요. 이번에는 제가 못 가니 택시와 병원 동행 지원도 알아봐 주세요.”

기존 병원·진료 목적·보유 기록·다음 일정·출발지역·지원 필요·보호자 가능일과 문의/공유 허용 범위를 구분한다. 암 치료 후 추적 진료는 합성 예시이며 구체 암종·병기·치료 단계와 실제 참여 의료진은 정하지 않았다. 새로운 진찰·판독·의뢰 기록을 Agent가 작성하지 않는다.

이동·동행은 **다음 방문 1건**에 대해 준비한다. 반복방문 횟수·동행 가능 횟수의 예산 시나리오는 별도 가정이다. 시간·이동시간·견적이 없으면 미확인으로 남긴다.

## 2. 단계별 동작

| 단계 | Agent가 정리할 것 | 사람·기관의 확인 | 남기는 결과 |
| --- | --- | --- | --- |
| 1. 요청·허용 범위 | 목적·일정·보유 기록·전화/공유 범위를 구조화 | 환자·보호자가 입력과 범위 확인 | 사례·허용 범위·빠진 조건 |
| 2. 병원·자료 준비 | 859의 기관명·주소·등록 과목으로 문의 후보를 찾고 자료·누락 대조 | 병원이 창구·필요 문서 안내, 의료진이 실제 기록 작성 | 기관 근거·양기관 절차·필수 자료 |
| 3. 협진 검토 준비 | 기관이 허용한 경로에 맞춰 자료 준비·보완·회신 추적 | 의료진이 환자별 검토·진료 계획 결정 | 검토 접수와 회신을 구분한 상태 |
| 4. 이번 방문 조건 | 방문일·제주 기관·출발지역·택시/동행 필요·휠체어·진료시각 확인 | 가족이 실제 상황 확인 | 지원 요구와 미확인 시각 |
| 5. 지원 문의처 | 327 최신택시·254 돌봄등록·별도 공식서비스에서 지역/지원유형별 후보 구성 | 기관이 담당지역·동행범위·차량·자격·가능일 확인 | 선택 근거·출처·질문 목록 |
| 6. 문의 초안·응답 | 민감정보를 제외한 초안 준비, 가능/불가/불통 응답에 따라 다음 작업 변경 | 실제 연락·확정은 사람/외부 도구로 별도 확인 | 현재 MVP에서는 합성 응답과 미확인 조건 |
| 7. 가족 실행 계획 | 병원·자료·택시·동행 상태를 한 화면에 모으고 예산·공백 표시 | 가족·의료진이 실행 조건 확인 | 이번 방문 계획과 반복방문 가정 |
| 8. 보완·재확인 | 병원·날짜·출발지역·지원요건이 바뀌면 과거 응답 무효화 | 새 조건으로 기관에 다시 확인 | 최신 조건에 맞는 다음 행동 |

기관의 등록 상태·지역 일치·대표번호는 현재 진료/배차/동행 가능의 확인이 아니다. 현재 문의 초안과 응답은 외부 연락이나 실제 예약을 수행하지 않는다.

## 3. 데이터가 다음 행동을 바꾸는 예

| 입력·응답 | 다음 작업 |
| --- | --- |
| 애월 출발·일반 차량 필요 | 327의 최신 연결 원출처에서 애월콜을 지역 일치 문의처로 제시. 왕복·픽업·운임·가능시간 질문 |
| 가족 동행이 어려움 | 아름동행 공식 소개와 지역 돌봄 문의처를 구분해 동행범위·대상·서비스지역·비용 질문 |
| 애월에 같은 읍의 돌봄 행이 없음 | 제주시 소재 문의처로 확장한 근거를 표시. 애월 지원이 확정됐다고 표시하지 않음 |
| 휠체어가 필요해짐 | 차량 장비와 교통약자센터 이용자격·사전회원등록 확인을 우선. 일반택시의 과거 응답 재확인 |
| 택시/동행 문의가 불가·불통 | 미배정/미확인 조건을 유지하고 재문의 또는 다른 후보 확인 |
| 지원 가능의 합성 응답 | 시연 출처를 유지하고 시각·장비·자격 등 빠진 조건을 계속 표시. 배정 완료로 바꾸지 않음 |
| 병원·방문일·지역·지원조건 변경 | 관련 문의·휠체어/자격 확인을 재확인 상태로 돌려 오래된 응답 재사용 차단 |
| 병원이 의뢰서·추가자료 요청 | 의료진 작성·기록 보완 작업으로 복귀. 문의 불통·미참여를 도외 진료의 임상 필요로 해석하지 않음 |

택시 최신CSV는 기준 2026-03-19의34업체이고 허브 자체2020 미리보기 45행과 다르다. 돌봄 254는 기준 2020-04-17의19개 기관이며 현재 병원동행 제공 여부는 미확인이다. 교통약자센터의 ‘동행콜’은 공동탑승 차량 개념으로 동행인 배정과 다르다.

## 4. 문의·근거·비용의 범위

이동 문의 초안에는 출발지역·방문일·기관·지원조건·미확인 질문만 넣고 환자 실명·진단명·검사 내용을 자동 포함하지 않는다. 병원에 필요한 건강정보 공유는 별도의 허용 범위와 기관 절차를 따른다.

논문·가이드라인은 기록 이해와 의료진에게 할 질문의 근거다. 개별 환자의 진료 장소·협진 충분성·검사 변경은 의료진이 판단한다. 실제 급여 인정 기준·보험 조건·견적은 아직 연결하지 않았다. 현재 비용 입력은 가정이며 미확인 항목을0원으로 확정하지 않는다.

픽업 시각은 확인된 진료시각·도착 여유·이동시간이 있어야 계산할 수 있다. 경로·이동시간 자료 없이 임의의 ETA나 차량 도착시각을 만들지 않는다.

## 5. 결과물과 첫 검증

- 이번 방문의 병원·자료·택시·동행 상태, 막힌 조건과 다음 행동을 모은 대시보드.
- 자료별 출처가 연결된 협진 준비 목록과 의료진에게 확인할 질문.
- 단일 방문 지원 문의 초안·선택 출처·합성 응답·재확인 상태와 별도 반복방문 예산 가정.

합성 환자 1명·기존 도외 병원 역할 1곳·선택한 제주 기관 1곳·다가오는 방문 1건에서 기존 자료 보완 흐름과 새 지원 분기를 함께 검사한다. 실제 국내 발신은 협조받은 테스트 번호로, 실제 배정·임상 유효성은 참여 기관과 별도로 검증한다. 개발 서브에이전트 분업을 서비스의 실제 다중 임상 Agent로 설명하지 않는다.
