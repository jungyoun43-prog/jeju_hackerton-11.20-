# 혼디 2×2·문서 스크롤 계약

2026-10-31. 사용자는 작은 창 내부 스크롤을 없애길 원했으며 “2×2 그리드 자체가 없어졌다”고 정정했다. 이전 단일 본문 배치는 잘못 해석한 변경이다. 이 계약이 reading-flow와 이전 고정 높이/모바일 한 창 선택보다 우선한다. 기존 Impeccable Operate 방향과 혼디 브랜드를 유지하는 범위 수정이다.

> 최신 정보 위계: [입력 우선 UX 계약](task-first-ui-contract.md)에 따라 공통 입력을 먼저 두고 네 칸은 핵심/상세로 구분한다. 그리드·내부 스크롤 없음·실행 경계는 아래 원칙을 유지한다.

## 수락 기준

- PC 900px 초과에서 네 작업칸은 요청·자료 / 병원·협진, 이동·동행 / 혼디의 정리 순서의 2열 2행이다. 모바일900px 이하에서는 같은 네 칸을 한 열로 모두 읽는다. 다른 칸을 고르면 기존 칸을 숨기는 동작은 없다.
- 각 칸과 본문은 height auto, 최대 높이 없음, overflow-y visible이다. 긴 결과·펼친 처리 기록이 칸과 문서 높이를 늘린다. 페이지 전체만 세로로 스크롤한다. 입력의 표준 textarea·명시적으로 연 native dialog·설정 서랍과 표의 가로 스크롤은 기존 예외다.
- 각 칸의 제목·기호·짧은 상태/핵심은 항상 보인다. ○ 자료/문의 준비 결과, △ 미확인·부분 준비·재확인, × 문의 실패·사람 인계와 중립 대시를 유지한다. 실제 관측 진행과 마지막 확인 사실을 구분한다. 처리 이력 등 세부는 native details로 펼칠 수 있지만 네 작업칸 자체를 하나의 접힌 준비 내역 뒤에 숨기지 않는다.
- 현재 청색/슬레이트와 의미 색, 사용자 지정 혼디 로고·제주 배경·Pretendard를 유지한다. 새 시각 방향·이미지·의존성·네 개 별도 LLM·새 API는 추가하지 않는다. 공통입력·기존 설정/전화/기록/여정·취소/재시도/음성·실제/시연 경계를 보존한다.
- 요약 탐색이 있으면 네 칸의 읽기 위치로 이동하는 동작이다. 진행 갱신만으로 칸 표시·native details·focus를 바꾸지 않는다. 확정/진행 이력의 DOM 분리·동일 출처 링크와 현재 읽는 위치 보존을 유지한다.
- 실제 PC/모바일·짧은 화면·긴 답변/입력/표·200% 글자에서 네 칸 표시, PC2×2/모바일1열의 좌표, 칸 내부 세로 스크롤 없음, 문서 첫/끝/공통입력 접근을 확인한다. 기존 안전/권한/취소/의미 색 대비와 출처 focus 회귀를 유지한다. 입력을 첫 화면에 억지로 맞추려고 결과 높이를 자르지 않는다.

## 소유권과 검증

- grid-ui: app/conversation.js, app/conversation.css, app/preparation-board-view.js. 기존 CSS/DOM과 읽기 이동을 최소 수정한다.
- grid-qa: scripts/conversation-browser-check.mjs, scripts/journey-browser-check.mjs, scripts/preparation-board-browser-check.mjs. 단일 본문/접힌 세 칸 단언을 실제 PC2×2/모바일 네 칸·문서 스크롤 수락 기준으로 바꾼다. 기존 기능/실행 경계 검사를 삭제하지 않는다.
- root: 문서·하네스·통합·최종 검증·기존 CI/CD와 ZIP. 전용 worktree·커밋 단위로 통합한다. 최종 source 동결 후 네 브라우저 proof와 단위/eval을 확인한다. 실제 전화·개인기록·임상/법률/실마이크 검증을 확대하지 않는다.
