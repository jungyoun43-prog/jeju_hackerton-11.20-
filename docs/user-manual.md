# 혼디 사용자 매뉴얼

버전: AWS 대화 모델 연결 · 작성일: 2026-10-31

공공데이터도 기존 대화창에서 요청한다. 예: “애월과 서귀포의 의료·돌봄 등록 자료를 비교해줘”, “어머니 동네에서 휠체어 이동·동행 문의처를 찾아줘”, “시간대별 이동 부담을 확인할 수 있어?” 혼디가 관련 자료를 찾아 보유 snapshot을 코드로 계산하고 출처·자료 시점·범위·확인할 질문을 설명한다. 비교표는 모바일에서 가로로 움직여 읽을 수 있다.

별도 설정·데이터 메뉴는 필요하지 않다. 현재는 데이터셋4종과 공식안내2건을 읽으며 목록1,329건 전체의 원자료를 확보한 것은 아니다. 병원 표본의 관측0은 시설 부재가 아니고, 과거 돌봄 등록은 현재 병원동행 가능 여부가 아니다. 센터 이동시간 원자료가 없어 ETA를 계산할 수 없으면 필요한 자료와 택시 문의 질문을 알려준다. 지역 비교만으로 실제 출발지나 지원 조건을 바꾸지 않는다. 문의 준비를 요청하고 현재 조건이 맞으면 기존 병원·택시·동행 흐름으로 이어진다. 실제 발신·예약·배차는 현재 수행하지 않는다.

첫 화면은 보호자가 텍스트·음성으로 요청하고 처리 기록과 이번 방문 요약을 읽는 화면이다. 루트 .env의 OPENAI_API_KEY를 입력하고 서버를 재시작하면 모델 API를 사용한다. 키가 없으면 자유 입력은 미연결 안내를 반환한다. 기본 모델은 gpt-6.1-sol이며 OPENAI_MODEL=gpt-6.1-terra로 선택할 수 있다. Sol 실제 계정 접근은 로컬·AWS의 단일 도구 사례에서 확인했다. Terra·복합 요청·일반 품질은 별도다. 별도 **대화 흐름 미리보기**에서 공공데이터 검색과 합성 준비 과정을 확인할 수 있다. 병원·지원 문의처는 실제 공개 자료이며 환자·기록·전화 응답·의료진 회신은 합성이다.

## 1. 설치와 실행

Node.js 22 이상과 npm으로 저장소 루트에서 실행한다.

```bash
npm ci --ignore-scripts
npm run dev
```

터미널의 Local 주소를 연다. 기본은 `http://127.0.0.1:4173`이다. 최초 npm 설치에는 인터넷이 필요하지만 고정 예시에 모델 키·AWS 인증은 필요하지 않다. `HOST`, `PORT`, `MAP_TILE_URL`은 [환경변수 예시](../.env.example)를 따른다.

```bash
npm test
npm run build
npm run preview
```

`npm run preview`는 빌드 화면과 Node API를 함께 실행한다. 기본 포트가 같으므로 개발 서버를 먼저 종료한다. 단순 파일 서버·정적 S3만으로는 대화 API가 실행되지 않는다. 센터 실기기 확인과 실제 브라우저·AWS 새 revision 확인은 [검증 기록](implementation-results.md)을 따른다.

## 2. 대화 흐름 미리보기

1. 첫 화면 상단의 연결 설정과 가상 사례 표시를 확인한다. 공개 AWS는 Sol 연결 설정됨, 키 없는 로컬은 AI 모델 미연결이다.
2. **대화 흐름 미리보기**를 누른다. 사전 작성 요청과 답변에 **작성된 예시** 표시가 붙는다. 이 예시는 자유 입력을 해석하지 않는다.
3. 11월 12일 10시, 애월 어머니의 제주우리병원 방문이라는 고정 사례를 읽는다. 병원 공개 등록정보 검색, 공단 연계 미설정 확인, 합성 자료·병원 문의, 택시·동행 문의처와 초안이 처리 기록에 표시된다.
4. 택시 가능 응답과 동행 연락 실패는 합성이다. 실제 배차·동행 배정은 이루어지지 않는다. 필요한 실제 진찰 소견·의뢰서와 동행 재확인 작업이 남는지 확인한다.
5. **이번 방문 준비**, **지금 연결된 범위**, **준비에 사용한 출처**에서 상태·자료 시점·미확인 조건을 읽는다. 모바일에서는 요약을 펼칠 수 있다.
6. **준비 내역 저장**으로 예시 결과를 내려받는다. 실제 진료 소견서·예약 증빙으로 사용하지 않는다. **새 대화**는 브라우저의 사례·이력·진행 표시를 초기화한다.

이 예시는 실제 공공 snapshot과 상태 변경 도구를 실행하지만 LLM·DB·전화망은 호출하지 않는다. preview의 sessionId는 일반 대화 세션으로 이어지지 않는다.

## 3. 텍스트와 음성으로 요청하기

입력란에 요청을 적고 **보내기** 또는 Enter를 누른다. Shift+Enter는 줄바꿈이다. 예시 버튼은 보이는 문구만 입력창에 넣고 자동 전송하지 않는다. 날짜·대상 등을 확인·수정한 뒤 보낸다. 기존 초안이 있으면 변경 전에 확인한다. 키가 없을 때는 모델 미연결 안내가 나오고 원문이 복원된다. 자유 입력을 고정 예시 답변으로 바꿔 보여주지 않는다.

응답 중 **응답 대기 중지**를 누르면 이 화면의 기다림을 끝내고 요청을 복원한다. 서버 처리는 계속될 수 있으며 실제 발신 중단 확인이 아니다. 새 UI의 같은 요청 다시 확인은 원래 본문·방문 토큰·요청 ID를 사용한다. 처리중/중단/완료를 대조하고 자동 재실행하지 않는다. 토큰 없이 호출하는 레거시 API에서 sessionId 없는 첫 재시도에는 추가 실행·차감 한계가 남는다. 미리보기 중지도 기존 대화와 초안을 유지한다.

**말로 요청**은 지원 브라우저의 `SpeechRecognition` 또는 `webkitSpeechRecognition`을 사용한다. 마이크 권한을 허용하면 한국어를 텍스트로 바꾸고, 말이 끝나면 인식한 요청을 입력창에서 검토·수정하고 **보내기**로 전송한다. **듣기 중지**로 중단할 수 있다. 미지원·권한 거절·마이크 없음·인식 실패 때는 텍스트로 계속한다. 브라우저 음성 인식은 병원 전화 발신이 아니다.

대화 이력은 브라우저 메모리에 있으며 새로고침하면 사라진다. 전송한 요청은 동일 출처의 Node/Lambda API에서 처리하고 원문·대화 전문을 로그나 DB에 저장하지 않는다. 음성 인식의 처리 위치·외부 전송 여부는 브라우저 제공 서비스 정책을 따른다. 실제 환자 기록·주민번호·인증정보·민감한 음성은 입력하지 않는다. 실제 마이크 인식 품질은 음성 API mock 검사만으로 검증되지 않는다.

공급자 연결 개발은 [Agent API 문서](../agent/README.md)를 따른다. `createAgentService({provider})`가 연결 지점이며 환경변수에 모델 이름만 넣는다고 활성화되지 않는다.

AWS는 하루80개 대화 요청을 UTC 기준으로 제한하고 실패한 요청도 차감한다. 새 UI는 첫 요청 전에 만든 방문 토큰으로 같은 요청을 확인하고 재실행을 막는다. 토큰 없는 레거시 API의 세션 없는 첫 재시도는 기존 한계가 남는다. 한 요청 안에서 모델은 최대8회 호출될 수 있다.

## 선택적인 이동·동행 기본 설정

PC 왼쪽의 **이동·동행 설정**에서 선호 택시 문의처, 휠체어 차량 필요 여부, 병원 동행 필요 여부를 바꿀 수 있다. 모바일은 상단 **설정**에서 열고 닫는다. 설정을 입력하지 않아도 대화를 시작할 수 있다. 변경은 다음 요청부터 반영하며 설정 조작 자체로 모델을 호출하지 않는다.

이 기기에는 공개 문의처ID·두 boolean만 저장한다. 대화·의료기록·인증정보는 저장하지 않는다. 선호 업체도 현재 지역·휠체어 조건에 맞는지 별도 확인하며 예약·배차·동행을 확보했다는 뜻이 아니다. 대화에서 말한 이번 조건을 기본 설정보다 먼저 따른다.

새 준비를 시작하거나 화면을 새로고침하면 이전 대화는 사라질 수 있다. 필요한 준비 내역은 먼저 내려받는다. 새 대화 시 내용이 있으면 소실을 확인하고, 음성 인식 결과는 보내기 전에 수정할 수 있다.

## 4. 상태와 출처 읽기

왼쪽 **환자 정보·건강 기록**을 열면 환자·보호자·진료 준비 목적·방문 정보와 준비 자료를 확인할 수 있다. 모바일은 상단 **설정**에서 같은 메뉴를 연다. 각 기록을 펼치면 현재 본문·출처가 보이며, 대화 응답·미리보기·새 대화와 같은 상태로 갱신된다. 창을 보는 행위는 모델·개인 건강정보 API를 호출하지 않는다.

**건강정보 고속도로**는 현재 미연결이며 최근 가져온 기록이 없다. 합성 치료 이력이나 준비된 문서는 해당 플랫폼에서 실제 수신한 자료가 아니다. 조회하지 않은 약물·검사값을 ‘없음’으로 판단하지 않는다. 연결 안내에서 공식 소개를 열 수 있지만 실제 인증·정보 제공 동의·조회는 수행하지 않는다.

| 표시·상태 | 읽는 방법 |
| --- | --- |
| 처리됨 | 해당 데이터 조회·초안 등 도구 작업이 끝남. 합성 응답이면 합성 표시를 함께 확인 |
| 확인 필요 | 빠진 자료·시각·이용자격·동행 가능 여부 등이 남음 |
| 미연결 | 공단 기록 등 승인된 연계 어댑터가 없음. 조회 완료가 아님 |
| 확인 실패 | 오류·불통 등의 상태. 진료 불가나 도외 방문 필요의 임상 판단이 아님 |
| 자료 준비·검토 접수·의료진 회신 | 서로 다른 사건. 하나가 완료됐다고 예약이나 외부 전송이 끝난 것은 아님 |
| 조건 변경 후 재확인 | 병원·방문일·지역·휠체어 등의 변경으로 과거 응답을 새 조건에 다시 확인해야 함 |

병원 859는 2024-10-17 수집 공개 표본 20행 중 폐업을 제외한 13개 등록 기관이다. 택시는 327이 연결한 2026-03-19 기준 공식 파일 34업체, 돌봄은 254의 2020-04-17 기준 19개 등록 문의처다. 아름동행·교통약자센터 안내는 별도 공식 출처다. 등록 상태·지역 일치·대표번호는 현재 진료·배차·동행 가능의 확인이 아니다.

지원 문의 초안은 날짜·출발지역·기관·지원조건과 확인할 질문으로 구성한다. 환자 실명·진단명·검사내용을 자동 포함하지 않는다. 고령이나 암진단만으로 교통약자센터 자격을 정하지 않으며 ‘동행콜’을 병원동행인 배정으로 해석하지 않는다.

## 전화·협진·휠체어 이동 준비

PC 왼쪽 또는 모바일 설정에서 **전화·협진 준비**를 연다. 기존 도외 병원·제주 병원·택시/휠체어 이동·병원동행 항목을 펼쳐 목적·문의처·질문·최소 전달·제외 항목·AI 고지 예정 문구와 합성 진행을 읽는다. **이 내용으로 문의 준비**는 입력 초안을 만들며 직접 보내기 전에는 요청·발신이 없다.

“제주 병원과 기존 병원의 협진 접수와 자료를 전화로 알아봐 줘”처럼 요청하면 양 기관의 접수·의뢰/회송 절차와 준비 자료를 이어 정리한다. 실제 진찰 소견·의뢰서는 의료진이 작성하고 실제 환자 수락은 기관·의료진이 확인한다.

“휠체어 이동도 알아봐 줘”는 현재 조건에 맞는 이동 문의처와 이용자격·회원등록·탑승/승하차 지원·동행인·시각·차량 가능을 확인할 준비로 이어진다. 공개 문의번호와 합성 가능 응답을 실제 배차·자격 확인으로 사용하지 않는다.

현재는 전화 서비스가 연결되지 않은 시연이다. 실제 환자의 위임·민감정보 처리·AI 고지·녹음·전사·보관·국외 전송·기관 응대 수락이 확인된 상태가 아니며, 실제 전화·녹음·전사·예약·배차를 수행하지 않는다. 합성 문의 허용이나 기기의 기본 설정을 실제 환자 동의로 간주하지 않는다.

## 5. 개발용 수동 화면

기존 화면은 **`/workspace.html`**에 보존했다. 기관 선택·자료 상태·합성 응답 분기·지원 조건 변경을 직접 확인하는 개발 도구다. 대화 서비스 이용을 위해 이 화면의 폼을 먼저 채울 필요는 없다.

- 기관·데이터: 공개 13개 후보를 조회하고 문의 대상을 선택한다. 사용자 기관 파일 가져오기는 이 화면에만 있으며 JSON/UTF-8 CSV, 2MiB·10,000행 이하를 브라우저 메모리에서 처리한다. 출처는 사용자 제공으로 표시한다.
- 병원 문의·진료 자료: 양기관 절차, 필수 문서, 별도 공유 허용이 있어야 검토 접수 시연을 진행한다. 의뢰서와 미수행 진찰 소견을 Agent가 작성하지 않는다.
- 일정·동행: 방문 1건의 지역·휠체어·지원 필요를 바꾸고 후보·초안·합성 응답·재확인을 검사한다. 문의 전 응답 기록은 거절한다.
- 반복방문 비용: 가정 횟수·금액·보호자 가능 횟수를 바꾸어 부분합과 동행 공백을 확인한다. 미확인을 0원으로 확정하지 않으며 현재 급여·견적 API는 없다.
- 지도: Leaflet·OSM의 지형·지명과 합성 위치 마커를 구분한다. Google Maps 외부 링크는 키 없이 열지만 앱이 경로·이동시간을 조회한 것은 아니다. 타일 장애 안내와 대안을 확인한다.

기관을 바꾸거나 문서·문의 조건을 바꾸면 과거 검토 결과를 다시 준비한다. 이전 결과를 유지하지 않는 동작을 오류로 해석하지 않는다.

## 6. 실행·제출 자료

```bash
APP_REVISION=local-preview npm run build:agent
npm run package
```

Python 3가 필요하다. `output/agent-lambda.zip`은 AWS 함수용 `index.mjs`·`deployment.json`이고, `output/jeju-care-compass-mvp.zip`은 제출 준비용 개발 스냅샷이다. 생성만으로 대회 제출 요건 충족·업로드가 완료되는 것은 아니다. [제출 추적표](submission-checklist.md)를 확인한다.

`npm run observe`, `npm run eval`, `npm run rollback -- <통합-커밋-SHA>`는 브랜치·worktree가 있는 개발 저장소용이다. ZIP의 일반 실행에는 필요하지 않다. 모델·프롬프트·도구·의존성과 실제/시연 범위는 [외부 명세](../THIRD_PARTY.md)와 [API 문서](../agent/README.md)를 따른다.

## 8. 검증의 범위

공급자 주입 테스트는 도구 인자·출처·권한·상태 전이·중복 요청·한도·오류를 검사한다. 실제 LLM의 한국어 이해나 임상 품질 검증은 아니다. 로컬 메모리와 AWS DynamoDB를 구분한다. AWS는 TTL1시간·UTC 전역80요청이며 같은 세션의 중복 재전송 미차감을 실제 확인했다. 새 토큰 흐름은 최초 응답 유실도 receipt로 확인하며, 토큰 없는 레거시의 초기 재시도 한계는 남아 있다. 새 대화 UI의 PC·모바일, 공개 AWS revision과 제출 ZIP의 최종 검증은 [구현 결과](implementation-results.md)에 확인된 기록만 남긴다.

## 진료 연결 여정 살펴보기

진료 연결 여정 창에서 현재 연결 상태, 세 진료 결과의 확인 여부, 자료의 원문·작성일·확인 상태와 다음 할 일을 봅니다. 날짜가 없으면 미상으로 표시하며 합성 의료진 확인은 실제 확인과 구분합니다. 문의 초안 버튼은 입력창에만 채웁니다. 수정·확인 후 보내야 일반 모델 요청이 됩니다.

자료 누락·제주 접수 거절·진료 시각 변경의 상황 미리보기는 고정 합성 예시입니다. 실제 LLM·전화·예약·배차를 실행하지 않습니다. 예시에서 접수 거절은 해당 요청의 운영 안내이고 환자의 제주 진료 가능 여부를 평가한 결과가 아닙니다. 시각이 바뀌면 이미 받은 차량·동행 안내를 재확인으로 읽고 새 조건을 전달할 문의를 준비합니다.

## 전화가 막혔을 때의 인계

실패 이유·시도 내역·남은 일·담당자를 보존합니다. 무응답은 사용자가 명시한 시연 횟수/시간 안에서만 재시도하며 기본은 정책 미설정입니다. 최초 포함 최대1~3회·1~120분을 지원하고 같은 정책을 반복 적용해도 시도/시간 범위를 초기화하지 않습니다. AI 응대 거절은 자동 반복을 멈추고 보호자에게 번호·문의 내용을, 본인확인은 환자 본인이 해야 할 단계를 넘깁니다. 서류 부족은 발급/제출 작업으로, 예약 불가는 허용한 다른 날짜의 문의로 이어집니다.

별도 무응답·AI 거절·본인확인·서류/일정 막힘 예시는 합성입니다. 재시도 정책이나 다음 가능 시각은 실제 발신 예약이 아니고 현재 실발신은 없습니다. 실제 위임·민감정보·전화/예약 확인 경계를 유지합니다.

현재 복구 상태는 대상별(기존 도외 병원·제주 병원·택시·동행) 한 수신처 범위입니다. 한 번이라도 문의를 시연한 뒤 다른 기관을 명시 선택하면 새 문의 초안을 만들 수 있지만 자동 문의는 인계 상태를 유지합니다. 이전 수신처의 실패를 새 기관의 거절로 표시하지 않습니다. 여러 기관별 전화 스레드·새 위임 범위 검증·실제 발신은 후속 구현입니다.

재시도 범위는 “택시에 15분 안에 최초 포함 최대 2회 재시도를 허용해줘”처럼 대상을 포함해 명시합니다. 부정하거나 다른 대상에 허용한 문장을 설정으로 바꾸지 않습니다. 이전에 문의한 수신처가 바뀌면 새 범위를 확인하고 사람이 이어받습니다.

## 요청하고 결과에서 이어가기

가운데 채팅의 공통 입력에 요청하고 같은 곳에서 전체 답변을 읽는다. 오른쪽은 자료·병원·이동/동행·방문 계획의 네 준비 상태를 아이콘과 함께 세로로 표시한다. 모바일은 채팅·입력 뒤 네 상태를 읽는다. 네 칸은 핵심만 먼저 표시하며 사실·누락·근거·기록은 각 칸의 자세히 보기로 펼친다. ○는 자료/문의 준비 결과, △는 미확인·부분 준비·재확인, ×는 문의 실패·사람 인계이며 미시작/불필요는 대시다. 기호 옆 설명과 출처를 함께 읽고 진료·예약 확정으로 해석하지 않는다.

공통 입력창에 필요한 준비를 말하면 가운데 채팅에 답변이 도착한다. 답변에서 요청 입력으로 돌아오거나 다음 문의 초안을 채워 이어갈 수 있다. 기존 입력의 교체를 취소하면 원문이 유지되며 초안은 직접 보내기 전까지 API·전화 요청을 하지 않는다. 앱은 화면 높이를 유지하고 중앙 대화와 전체 준비 영역을 각각 스크롤해 읽는다. 각 상태 카드에 별도 스크롤을 만들지 않는다. 좁거나 낮은 창에서는 대화/준비 탭을 바꾸며 같은 하단 입력창을 사용한다. 내역 열기·답변 확대·환자기록/전화계획 확인은 모델/전화/예약을 실행하지 않는다.

진행연결이 늦거나 실패해도 마지막 확인상태와 원래 응답을 기다린다. 화면의 대기를 중지하면 초안을 복원하지만 서버 처리는 계속될 수 있다. 실제 전화·건강정보고속도로·예약·배차는 현재 연결 전/합성 범위다.

## 저장된 방문 준비 이어하기

새로고침하면 같은 탭의 미만료 방문에서 마지막 확인 상태와 남은 일을 불러온다. 방문 상세의 **저장된 준비 다시 확인**으로 처리중/중단/완료와 확인·만료 시점을 볼 수 있다. 과거 모델 답변과 대화 원문은 복원하지 않는다. 기존 선호 설정으로 복구한 휠체어 조건을 자동 덮지 않는다.

화면 대기 중지를 서버 실행 취소로 해석하지 않는다. 같은 요청 다시 확인은 원래 요청을 확인하며 완료 불명확하면 자동 재실행하지 않는다. 서로 다른 내용이면 새 요청으로 구분한다. 저장소 연결 실패에는 참조를 유지하고, 만료된 경우 현재 내용을 저장한 뒤 새 대화로 시작한다. 브라우저가 sessionStorage를 막아도 현재 대화는 가능하지만 새로고침 복구는 지원하지 않는다.

토큰은 현재 탭의 복구 참조이며 환자별 인증·가족 공유가 아니다. 새 대화는 이 참조만 정리하고 서버 처리 중단이나 즉시 데이터 삭제를 뜻하지 않는다. 고정 예시는 성공적으로 모드가 바뀌었을 때 참조를 정리하며 실패/취소에는 기존 방문을 유지한다.

“판독문 파일이 없어요”처럼 명시하면 미보유 상태와 발급→제출 확인할 일을 함께 바꾼다. 인용·질문·가정이나 다른 문서의 미보유로 상태를 바꾸지 않는다. 실제 원본 기록을 삭제하거나 발급하지 않는다.

보건지소의 관할·연락처를 물으면 제주시1304의35행/2026-03-23 기준에서 등록 문의처와 질문을 반환한다. 병원/택시/동행의 실제 접수나 자동 예약으로 이어지지 않는다. 서귀포는 이 자료의 범위 밖으로 안내한다.
