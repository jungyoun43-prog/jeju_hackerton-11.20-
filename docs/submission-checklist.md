# 대회 제출 요건 추적표

## 2026-11-19 제출본

공식 제출 창은 11월 20일 금요일 오전 10시(한국시간)에 닫힌다. 필수 업로드는 15쪽 이내 기획서 PDF 한 개와 최종 결과물 ZIP 한 개다. 대회 갤러리에서 기획서 및 최종 산출물 제출 단계를 선택한다. 팀 참가는 팀장이 제출한다. [공식 대회 페이지](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)

평가용 외부 AI는 참가자 비용으로 공개 서버에서 실행한다. 11월 19일 합성 질문 한 건에 공개 앱에서 실제 응답을 확인했다. 운영 키는 ZIP에 넣지 않는다. 최신 예약 시연은 ZIP을 풀어 실행한다. 두 실행 경로와 데이터 출처는 [심사용 안내](evaluator-readme.md)에 있다. 아래 추적표는 이전 판본의 준비 이력이다.

기준일: 2026-11-15 · PRD v0.25 · [대회 공식 페이지](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)의 렌더링 본문을 다시 확인했다. 업로드 직전 변경 공지는 별도 확인한다.

2026-11-16 추가: 공식 평가 기준의 필수 데이터20점과 지정 목록·센터 페이지를 재확인하고 [제주 데이터의 화면 활용](../research/jeju-data-booking-2026-11-16.md)을 연결했다. 지역·등록 과목으로 병원 후보가 달라지고, 지역·휠체어 조건이 지원 문의처와 준비표를 바꾸는 과정을 키 없이 재현한다. [실행 검증](reviews/2026-11-16-jeju-data-booking.md)은 로컬 빌드 기준이며 공개 배포·심사 점수·모델 품질 검증은 아니다.

최신 구현은 **선택형 네 단계 체험**이며 [평가자 검토](reviews/2026-11-15-judge-review.md)와 [결과3.25절](implementation-results.md#325-선택형-체험과-평가자-검토)을 따른다. 아래 과거 버전 검증은 당시의 이력이다. 체험은 API 모델 키 없이 실행되지만 현재 자유 입력 모델 품질 검증을 대신하지 않는다.

공식 배점은 주제 타당성·창의성15 / 필수 데이터20 / Agent 기술·완성도25 / 편의·실용25 / 신뢰·재현15이다. 전문가70%와 동료 평가30%를 합산한다. 요구 항목의 구현·문서 대응과 실제 심사 점수는 다르며 본 저장소는 만점이나 수상을 예상 점수로 쓰지 않는다.

**실제 모델 평가용 키는 남은 준비 항목이다.** 공식 공지는 외부 AI API 사용 시 참가자가 평가용 API 키와 호출 비용을 준비하도록 안내하며, 실행 매뉴얼에 평가용 키를 포함할 수 있는 예외도 명시한다. 현재 ZIP에는 키를 넣지 않으며 기존 운영 키를 복사하지 않는다. 실제 모델 평가를 받으려면 별도의 한도 있는 평가용 키·크레딧과 제공 방법을 준비해야 한다. 제주데이터허브 키는 코드에 넣지 않고 실행 매뉴얼에 발급·설정을 안내한다. 현재 보유 공개 snapshot의 체험은 이 키 없이 실행된다. 이 두 키의 안내를 혼동하지 않는다.

현재는 공개 자료4종·현재 작업과 네 단계·첫 요청 중복 방지·같은 탭 이어하기를 연결한 Agent 시연이다. 실제 제품 참고를 반영해 화면의 작업 위계와 초안 피드백을 정리했다. 해커톤은 합성 문의 결과로 준비가 이어지는 범위이며 실제 발신·배차는 확장 사항이다. 과거 Sol 합성12과업의 모델/도구/상태 검사·답변 검토와 현재 fixture·고정 예시·브라우저 검사를 구분한다. 현재 모델 품질은 미검증이다. 최신 수치·소스 지문·CI·공개 배포·ZIP은 [구현 결과3.23절](implementation-results.md#323-ponytail-제출-패키지-정리)과 해당 실행 증거를 따른다. 과거 결과를 새 revision으로 재표기하지 않는다.

파일 존재·자동 검사·임상/법률 검토·실기관 성공·대회 제출 완료는 각각 다른 상태다.

## 4. 남은 제출 작업

1. 기획서·같은 소스 ZIP·CI/공개 검증 결과의 마지막 파일/SHA를 대조한다.
2. 발표·영상도 현재 대화/복구·데이터4종과 실제/합성 경계를 맞춘다.
   실제 AI API 평가를 위한 전용 키·비용·안전한 제공 방법은 별도로 준비한다. 키 없는 체험을 LLM 평가 완료로 설명하지 않는다.
3. 실제 휴대폰 키보드/마이크·보호자 참여 과업과 센터 실기기 실행을 확인한다.
4. 최종 공지·권리/민감정보·첨부파일·마감을 확인한 뒤 업로드 결과를 보관한다.

실제 전화 사업자·개인 기록·예약/배차·기관/의료진 참여는 실서비스 확장의 조건부 업무이며 해커톤 합성 시연의 필수 완료 조건이 아니다. 추가 데이터 개수나 전체 운영 API는 기본 공개 자료 활용의 선행 조건이 아니다. 아래는 이전 버전의 검증 이력이며 현재 설명은 위 표와 최신 구현 결과가 우선한다.

## 진료 연결 여정 추가 범위

세 결과의 근거 경계, 기록→할 일, 답변 이후/시간 변경 재확인, 세 여정과 전화실패4개·데이터 조건 영향을 구현했다. 통합 단위261·대화171·여정208·수동47·규칙44를 확인했고 공개 배포/실모델은 별도 revision 증거를 따른다. 이전 버전 수치를 새 기능의 검사로 확대하지 않는다. 실제 환자/의료진/통화·기록 연계·실증과 최종15페이지PDF는 별도다.

## 4. 다음 제출 작업

1. 이번 대화 UI·API·문서의 같은 커밋에서 PC·모바일·정적/Node API·Lambda ZIP·공개 revision·패키징 검증과 결과 기록을 확정한다.
2. 15페이지 이내 기획서 PDF와 결과 설명·발표/영상에서 현재 구현·합성·미연결·검증 수치를 맞춘다.
3. OpenAI Sol 공개 단일 도구 스모크·영속 전역 한도 다음으로 복합 요청·Terra·한국어 품질·초기 요청 중복 방지를 검증한다.
4. 실제 통화·개인 기록·예약/배차·기관 참여·임상 검토·센터 실기기는 후속 작업으로 관리하고 현재 완성 기능처럼 제출하지 않는다.
5. 최종 source·license·데이터 시점·권리·비밀값·재실행을 대조한 뒤 최신 공지·마감·업로드 결과를 확인한다.
