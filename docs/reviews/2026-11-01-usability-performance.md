# 실사용·로딩 개선 검토

2026-11-01 · PRD v0.22 · 실행 지문57ea8657. [계약](../usability-performance-contract.md)과 [최신 실행 결과](../implementation-results.md#321-실사용과-초기-로딩-개선)를 따른다.

보호자 입장에서 고정 흐름을 실행하고 다음 요청 초안·병원/전화 창·AI 거절 인계·모바일 전환을 사용했다. 현재 작업과 이력의 다음 행동이 달랐고, 지원 요약이 AI 거절을 불통으로 축약했으며 모바일 새 대화에 접근 가능한 이름이 없었다. 두 예시 조작도 실행/초안 역할이 모호했다. 수정 후 같은 사용 경로에서 두 작업 제목 일치, 정확한 보호자 인계 이유, 이름 있는 새 대화를 확인했다. 이 관찰은 개발자의 합성 과업 사용이며 실제 보호자 참여 조사가 아니다.

UI·폰트·지원 이유를 별도 worktree에서 구현하고 통합 후 작성자와 다른 검토자가 연결 코드를 읽었다. UI의 최종 렌더/취소·늦은 응답/열린 창·최신값과 공통 초안 보호, 폰트의 원패키지92개 바이너리·CSS 범위/OFL·빌드 포함, 지원 이유의 현재 수신처·재확인·해당없음 우선순위에서 추가 결함을 찾지 못했다. 읽기 검토를 실제 배포 동작의 검증으로 대신하지 않았다.

서버442개와 브라우저/실제 로컬 HTTP1,063개 검사를 같은 실행 지문에서 완료했다. 실제 Chromium 탭 확대와 CSS가용크기를 별도로 확인하고 현재 작업이 보이는 실제 합성 예시로12페이지 PDF를 갱신했다. 실모델 호출0·전화0·개인기록0 경계를 보존한다. 독립 QA5개 suite는973/973·전부exit0/pass/errors[]이며 새 assertion을 위해 기존 보호조건을 삭제하지 않았다.

성능 근거는 orchestration/runs/use-performance.json의 SHA가 연결하는 수정 전·후 원자료와 측정 스크립트다. 초기 폰트 본문85.4%감소와 최종 준비판 갱신3→1, 읽기 전용 탐색의 전체 갱신0을 확인했다. 수정 전/후 서버 구현과 LCP 대상 및 interaction 표본 수가 달라 현장 성능·동일 LCP 대상 개선이라고 결론내리지 않는다. 현재 모델 품질, 실제 휴대폰·스크린리더·보호자 과업 관찰은 후속 검증이다.
