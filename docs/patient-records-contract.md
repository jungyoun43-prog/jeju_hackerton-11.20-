# 환자 정보·건강 기록 창 계약

2026-10-31. 사용자는 입력창 위의 요청 예시, 별도 환자 정보·건강 기록 설정, 인물 사진 제거와 제주 배경, 떠 있는 방문 요약을 요청했다. 기존 대화·기본 설정·공유 동의의 경계를 유지한다.

- `#nav-patient-records`에서 `#patient-records-dialog`를 연다. PC·모바일에서 읽기 전용으로 현재 환자·방문·문서·출처·연계 상태를 확인한다. 대화를 시작하기 위한 입력 단계가 아니다.
- 데이터는 현재 메모리의 `caseState`뿐이며 Agent 응답·고정 예시·새 대화 초기화와 같은 상태를 본다. 설정 창을 여는 동작으로 모델·개인 기록 조회·인증 요청을 보내지 않는다.
- 환자·문서 값은 문자로 안전하게 표시한다. 기록을 실제 진료·외부 전송·환자별 의학적 판단으로 확대하지 않는다. 약물·검사 수치·암종/단계를 만들지 않는다.
- 건강정보 고속도로는 현재 실제 미연결이다. 최근 불러오기와 동의는 수행되지 않았다. 합성 기록은 해당 서비스에서 가져온 기록이 아니다. 일반 `capabilities.healthRecords`는 이 특정 서비스의 연결 성공 증거가 아니다.
- 준비·누락·미수행 문서를 구분하고 출처가 없는 기록의 출처를 추정하지 않는다. 문서 상세를 펼쳐 본문을 읽을 수 있다.
- native dialog의 제목·닫기·Escape·포커스 복귀를 제공한다. 모바일의 기존 설정 서랍에서 기록 창으로 이동할 때 배경 `inert`와 포커스가 충돌하지 않게 한다.
- 기기에 저장하는 값은 기존 선호 택시 ID·휠체어·동행의 세 설정뿐이다. 환자·기록·대화·토큰·인증정보를 localStorage에 추가하지 않는다.

실제 플랫폼 범위는 [공식 조사 기록](../research/healthway_integration_2026-10-31.md)을 따른다. 개인 건강정보 연계는 허브의 익명 공개 기관·이동·돌봄 자료와 별개다.
