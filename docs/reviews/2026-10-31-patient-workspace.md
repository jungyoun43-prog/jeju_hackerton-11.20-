# 환자·기록 창 및 제주 작업 화면 최종 검토

**판정: ship** · 2026-10-31

현재 root의 `app/conversation.js`·`conversation.css`와 새 캡처 5개를 대조했다. `jeju-floating-1440/390/360.png`, `patient-records-1440/390.png`를 각각 직접 열었으며 올바른 화면이 표시되고 비어 있지 않다. 모바일 floating 캡처는 전체 페이지 이미지이므로 PNG 높이를 viewport 높이로 해석하지 않았다.

| 최신 요구 | 판단·근거 |
| --- | --- |
| 예시 요청을 스크롤 밖, 입력 바로 위로 | 충족. `starter-prompts`가 `conversation-scroll` 밖에서 form의 바로 앞 형제다(JS544–552). 캡처에서 입력과 정렬되며, 6개 viewport 기록의 간격은 PC10px·모바일8px이고 대화 스크롤 중 위치를 유지한다. |
| 환자 정보·건강 기록 창 | 충족. 열 때 현재 caseState의 환자·자료 상태·출처·내용을 읽는다(JS110–148). 실제 고속도로 연계와 일반 capability를 혼동하지 않고 ‘미연결’, ‘불러온 기록 없음’, ‘가상 사례의 합성 자료’를 명시한다. 가짜 인증·조회 버튼은 없다. 고정된 닫기와 내부 세로 스크롤이 있어 모바일에서도 내용을 계속 읽을 수 있다. |
| 인물·caption 제거, 제주 바다·현무암 배경 | 충족. 환영 DOM에서 인물·caption이 제거됐고 바다·현무암이 배경으로 보인다. 밝은 오버레이와 흰 작업면이 입력·본문의 가독성을 유지한다. |
| 우측 하나의 흰 floating panel | 충족. 상태·저장·연결·출처가 단일 흰 패널에 묶였다. CSS에서 PC는 sticky, 900px 이하는 static이며 새 모바일 캡처에서 대화 아래 정상 흐름으로 놓인다. 입력을 덮지 않는다. |

**출시를 막는 중대 UI 결함이나 추가 변경 요구는 발견하지 못했다.** 이번 판단은 지정된 네 변경에 한정하며 다른 디자인 방향을 요구하지 않는다.

현재 `runtimeFingerprint()`를 읽기 전용으로 계산한 값은 `a4b982d64e8e9e88c98fc10f41aa81ad47f7f0b599fd41e3092293a9b4b7ec7a`다. 이 값이 새 layout proof 및 완료된 대화115/115·수동 화면47/47 기록과 일치하고 세 기록의 errors는 모두 빈 배열이다. layout proof의 1440·1200·1024·768·390·360px 검사도 모두 pass다. 이는 app/agent/prompts·서버·package 계열 **runtime 범위**의 최신성 증거이며 문서나 전체 커밋의 지문이 아니다. 테스트는 재실행하지 않았다.

미검증 범위는 실제 기기의 소프트 키보드·스크린리더, 실제 건강기록 연계·마이크·일반 모델 품질·공개 배포다. 화면의 연결 설정 표시를 실제 모델 호출 성공 증거로 인용하지 않는다. Impeccable CLI는 권한 오류126 상태이므로 자동 스캔 통과나 오버레이가 있다고 주장하지 않는다. 독립 의학 평가 및 이미지 프롬프트·권리 감사로 범위를 넓히지 않았다.
