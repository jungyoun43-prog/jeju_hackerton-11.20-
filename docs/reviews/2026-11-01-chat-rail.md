# 중앙 채팅·오른쪽 준비 현황 검토

## 구현 전: 독립 배치 평가 A

기준은 0c502c7의 실제PC1440×900/모바일390×844 캡처와 conversation.js/css·preparation-board-view.js다. 기계 탐지 결과를 전달하지 않은 별도 검토자가 읽기 순서·그룹·리듬·구조·밀도·적응·극단 상태를 평가했다.

- 현재 대화가 네 번째 plan 칸 안에 있어 모바일에서는 세 상태칸을 지나 답변에 도달한다. 중앙 대화→예시→입력과 우측 상태 분리는 최신 사용자 목적에 맞는다.
- 전체 message-list는 중앙 한 곳에 두고 plan에는 기존 summary/facts/events만 둔다. 답변·다음 문의 초안·입력을 같은 흐름으로 모은다.
- 오른쪽 약300~320px에서는 제목·상태 줄바꿈을 허용하고 핵심은 촘촘하게, 상세는 native details로 읽게 한다. 중앙 답변은 더 넓은 읽기 폭과 여백을 갖는다.
- 900px 이하는 DOM도 대화 먼저/상태 나중이어야 한다. status4개는 한 열로 모두 읽을 수 있어야 한다. folder/hospital/car/calendar 아이콘을 기존 SVG 체계로 재사용한다.
- 카드나 패널 전체를 viewport 높이로 고정하지 않는다. 하단 입력을 sticky로 쓸 때는 채팅 영역에서만 동작하고 짧은 화면·큰 글자에서 답변/고지를 가리지 않아야 한다. 장문·전체 상세·진행 중 출처 읽기는 구현 후 확인한다.

## 구현 전: 기계·소스 평가 B

root가 별도로 `impeccable detect --json --scope layout app/conversation.js app/conversation.css app/preparation-board-view.js`를 실행했으나 Permission denied/종료126으로 결과를 받지 못했다. 발견0건이나 자동 합격이 아니다. 설치 권한·도구 스키마를 수정하지 않았다. 기존 context의126 오류도 직접 PRODUCT/DESIGN 읽기로 보완했던 이력을 유지한다.
