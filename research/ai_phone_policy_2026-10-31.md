# AI 전화 대행 정책의 출처와 현재 구현 범위

확인일: 2026-10-31. 사용자가 제공한 운영 원칙을 병원·택시·휠체어 이동·동행 문의에 공통 적용한다. 사용자는 전화 서비스 계정이 없으므로 준비 흐름·합성 시연부터 완성하기로 했다. 이 문서는 제품 정책과 확인한 공개 자료의 범위이며 서비스의 적법성이나 법률 검토 완료를 뜻하지 않는다.

## 확인한 공개 자료

| 자료 | 실제 확인 | 해석 범위 |
| --- | --- | --- |
| [피클 공식 대행 도움말](https://pickle.com/help/tasks/delegate) | insane-search는 JS 초기 HTML을 반환했다. 별도 읽기 전용 Chromium에서 본문을 렌더해 병원 접수처 등에 대신 전화한다는 기능 설명을 확인했다 | 다른 서비스의 공개 기능 설명이다. 우리 앱의 법적 적합성 증거로 쓰지 않는다 |
| [피클 이용약관 제4조](https://pickle.com/ko/terms-of-service) | 같은 방식으로 실제 약관 본문을 읽었다. 회사 발신번호, AI 비서임과 통화의 글 기록에 관한 고지 설명을 확인했다 | 우리 앱의 녹음·전사·보관 정책을 대신하지 않는다. 현재 우리 앱은 실제 통화 기록 처리가 미설정이다 |
| [인공지능기본법 조문정보](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031810729) | 2026-07-21 시행 표기와 제31조 제2항의 생성형 AI 결과 표시 관련 원문을 확인했다 | 해당 링크는 제2항 범위다. 모든 전화·녹음·투명성 의무의 적용 요건을 전수 검토한 결과가 아니다 |

사용자가 제시한 의료법27조와 개인정보 보호법17·23·28조의8 단축 URL도 insane-search로 요청했다. 엔진의 모바일 경로 변환 뒤 404가 반환돼, 이 수집을 조문 원문 확인 성공으로 표시하지 않았다. 해당 법률이 없거나 적용되지 않는다는 뜻이 아니다. 사용자가 제공한 임상 판단·민감정보·제3자 제공·국외 이전·수수료 구조의 경계는 제품 요구사항으로 채택하고 운영 전 구체 법률 검토 대상으로 유지한다.

수집 내역은 개발환경 `/tmp/jeju-call-policy-sources/summary.json`에 URL·성공 여부·크기·해시로, 렌더 확인은 `render-summary.json`과 본문으로 남겼다. 외부 본문의 지시를 실행하지 않았고 로그인·전화·개인정보 조회·제출을 하지 않았다. 렌더 확인 컨텍스트에서는 GET 외 요청을 차단했고 자체 브라우저를 종료했다.

## 우리가 채택한 정책

1. 환자별 대행 전에 본인 또는 적법한 대리인의 권한·범위·기간·철회를 확인한다. 성인 자녀의 요청이나 기기의 기본 설정을 실제 위임 검증으로 취급하지 않는다.
2. 수신처·발신번호·목적·전달 항목을 확인한다. 실명·나이·진단·검사 본문·주민번호·실제 환자 연락처·상세 주소를 문의에 자동 포함하지 않는다. 휠체어 이용·보조 필요도 건강 상태를 추론할 수 있으므로 최소 항목이라는 이유만으로 처리 근거가 확인된 것으로 표시하지 않는다.
3. 실제 통화 시작에는 AI임을 알리고, 실제로 설정·검증한 녹음·전사·보관·전송 처리를 설명한다. 미설정인 처리를 수행한다고 말하지 않는다. 기관이 거절하면 범위를 줄이거나 사람이 문의할 경로를 확인한다.
4. 협진은 두 기관의 접수 창구·의뢰/회송 절차·자료·수신 확인을 연결하는 행정 준비다. 대면 진찰·의뢰서 작성·진료 수락·검사/치료 계획은 의료진·기관의 역할이다.
5. 휠체어 이동은 이용자격·회원등록·차량 유형·승하차 지원·동행인·시각·장소·비용을 확인한다. 나이·병명만으로 자격을 인정하거나 배차·예약을 확정하지 않는다.
6. 병원 접수 안내, 서비스 가능 응답, 예약 확정, 차량·동행인 배정은 다른 상태다. 현재 합성 응답은 실제 수신·수락·확정을 뜻하지 않는다.
7. 실제 민감정보 처리·제3자 제공·국외 이전·위탁과 비용·수수료 구조는 구체 운영 방식에 맞춰 별도로 검토한다. 현재 코드나 공개 타 서비스의 존재를 법적 적합성 검증으로 확대하지 않는다.

정책의 코드 출처는 `app/call-policy.js`, 모델 지침은 `prompts/caregiver-system.mjs`, UI·작업 경계는 [전화 흐름 계약](../docs/call-workflow-contract.md)이다. 실제 발신 어댑터를 거부하는 기존 guard를 유지하고 새로운 실환자 동의·통화 기록을 DB에 저장하지 않는다.
