# 요청한 예약 조율의 완료 · 2026-11-18

사용자의 ‘끝없이 준비할 일만 보인다’는 피드백에 따라, 현재 지역·입력·예약 흐름의 끝을 **조건 선택 → 혼디에게 맡기기 → 예약 진행·결과**로 바꾼다. 마지막 `이동·준비표` 화면과 AI 초안 재입력을 반복시키던 경로보다 이 계약이 우선한다. 준비 서류·교통 출처·세부 계획은 접어 두고 주 행동 하나를 고정한다. 기존 자유 대화·선택형 체험의 도메인 readiness는 이 변경으로 실제 완료가 되지 않는다.

## 사용자가 보는 완료

- 마감일에 ‘일정 상담으로 계속’을 고르면 희망 날짜·병원·진료과가 담긴 상담 메모로 끝난다. 현황에서 상담을 다시 열거나 다른 날짜를 찾을 수 있으며, 상담 메모는 예약 완료 건수에 넣지 않는다.
- 텍스트로 적은 진료 시각·가는 차량 출발 시각·서류 보유 응답을 확인 화면과 결과표에 보존한다. 문의처 검색 지역을 바꾸는 일과 실제 시연의 출발지를 바꾸는 일은 별도 동작이다. 내륙 항공권 검색과 제주공항행 차량은 같은 가는 날을 사용한다.

- 병원 예약, 가는 편 차량, 병원 동행의 세 행이다. 차량·동행은 이번 요청에서 제외할 수 있다. 초진·재진·의뢰서 응답은 선택적으로 남기며 미상이라는 이유로 가상 예약 조율 진입을 막지 않는다. 기존 실제 접수 요건 검증과 임상 상태는 변경하지 않는다.
- ‘예약 시연 시작’을 명시적으로 누르면 가상 연결 중 → 시연 회신 대기 → 예약 완료(시연) / 직접 확인 필요로 이동한다. 회신 receipt가 없는 단순 연락·가능 안내·입력 완료에는 체크하지 않는다.
- 요청한 항목이 모두 확정 또는 인계되면 실행이 종료된다. 전부 확정이면 ‘맡기신 예약 조율을 마쳤어요’, 실패가 있으면 ‘N건 예약 · N건 직접 확인이 필요해요’로 표시한다. 마지막 행동은 결과표 저장이다.
- 문서 보유·발급·제출, 항공권 가격 비교·결제, 검사 종료 후 귀가 차량은 ‘출발 전 직접 챙길 일’로 분리한다. 이 일들이 남았다는 이유로 이미 종료한 예약 조율을 무한한 진행 상태로 표시하지 않는다.

## 현재 구현과 실제 연결

2026-11-18 후속: 마지막 유효 회신 뒤 `resultOpen`을 켜고 shadcn/Radix Dialog로 별도 결과창을 자동으로 연다. 제목에 초점을 두고 닫으면 ‘결과창 다시 보기’ 버튼으로 돌아온다. Escape·탭 가두기·명시적 닫기와 결과표 다운로드를 제공한다. 열고 닫는 것은 업무 상태·회신·발신을 바꾸지 않는다. 일정 변경으로 결과가 무효화되면 오래된 결과창을 다시 열지 않는다. 본문만 스크롤하고 닫기·저장 행동은 화면 안에 남긴다.

결과창의 마지막 선택은 **처음으로 돌아가기 / 내 예약 현황**이다. 결과표 저장은 제목 옆 보조 행동으로 둔다. 홈으로 돌아갈 때 결과창을 닫고 기존 지역별 초안을 유지한다. 상단 ‘내 예약 현황’은 어느 단계에서든 현재 제주·내륙 준비와 유효 회신만 읽고, 결과 다시 보기·결과표 저장·준비 이어가기를 제공한다. 열기만으로 발신·조율을 실행하거나 예약 이력을 생성하지 않는다. 진행 중 조율에서 이동하면 기존 중지 규칙을 따른다. 순수 `reservationOverview`는 기존 `coordinationView`의 조건 서명 검증을 재사용한다.

작업면 전환은 내용 높이와 무관한 `.conversation-layout` 전체의 900ms 펼침과 혼디 감귤의 곡선 궤적이다. 단색 가림막과 화면 캡처 기반 전환을 쓰지 않는다. 실제 DOM·초점은 즉시 갱신하며 시각 효과만 이어진다. 결과창은 850ms 등장과 1.2초 감귤 도착 효과를 유지한다. 빠른 연속 조작·크기 변경·화면 숨김 시 이전 효과를 정리한다. 키보드 선택과 움직임 줄이기에서는 큰 공간 이동 효과를 생략한다.

`app/care-coordination.js`의 메모리 전용 fixture adapter다. 유료 모델·전화·기관 전송·결제·배차·DB 호출이 없다. `coordination` 상태와 `synthetic_booking_receipt`는 기존 `caseState`·기관 inquiry·실제 `reservationConfirmed`·`visitReady`를 갱신하지 않는다. 시연 결과는 실제 환자 동의·대리 권한·의료진 진료 수락의 근거가 아니다.

제주 공개 등록 병원은 요청 대상의 이름·주소·진료과·출처를 그대로 보존한다. 그 병원에 가상 회신을 붙이지 않고 **가상 제주 병원 / 가상 이동지원센터 / 가상 병원동행센터**의 결과로 분리한다. 공개 전화번호·빈자리·의료진을 생성하지 않는다. 희망 기간은 첫날, 오전/오후는 10시/14시로 보여주는 **시연용 제안**이며 실제 가능 일정이 아니다. 제주 차량은 예시 진료 1시간 전, 내륙은 전날 9시 공항행을 제안하고 사용자가 수정할 수 있다. 실제 경로 소요시간·항공편 계산을 했다고 표시하지 않는다. 항공권은 기존 가격 비교 사이트에서 직접 예약하는 연결을 유지한다.

향후 실제 adapter는 확인된 수신처·환자 위임·개인정보 처리 범위와 예약 대상/시간/확정 응답을 검증한 결과를 받아야 한다. 예약과 임상 수락·의뢰서 발급을 분리한다. 현재 fixture를 실제 성공으로 승격하거나 기존 `available_demo`를 예약 영수증으로 간주하지 않는다. 상세한 실연동 전제는 `call-workflow-contract.md`를 유지한다.

별도 `agent/phone-*.mjs`는 Twilio outbound 생성과 Realtime 음성을 연결하는 운영자용 코드다. 기본 비활성·dry-run이며 위 화면의 fixture와 실제 receipt를 섞지 않는다. 일반 앱에서 실발신을 여는 API는 추가하지 않았다. 전화 서비스 계정·공개 HTTPS/WSS·실제 위임 확인 및 E2E 검증은 남아 있다. [전화 어댑터 계약](outbound-phone-adapter.md)을 따른다.

## 변경·중지·복구

- 예약 현황·결과창·조율 완료 화면에 **예약 수정**을 제공한다. 기존 조건을 채운 병원·진료과 / 날짜·의료진 / 이동·동행 편집을 재사용하고, 별도의 탭 메모리 초안으로 변경한다. 검색과 월간 달력·의료진 시간 선택의 공개자료/가상 데이터 경계는 유지한다.
- **변경 내용 확인**에서는 바뀐 예약의 전후 조건과 유지할 결과를 보여준다. 적용 전에는 기존 지역별 초안과 결과를 덮어쓰지 않는다. 수정 취소나 화면 이탈은 원래 조건으로 돌아간다. 같은 편집 안에서 원래 조건으로 되돌린 것은 적용된 변경을 취소한 것이 아니므로 기존 회신을 유지한다.
- **변경 적용·다시 조율**은 관련 결과만 제거하고 기존 시연 adapter로 이어진다. 차량 출발 시각만 변경하면 병원·동행 회신을 보존한다. 지원 제외만으로 필요한 결과가 모두 남으면 추가 조율 없이 현황으로 이동한다. 원래 제외된 항목은 변경 목록에 끼워 넣지 않는다. 날짜 미선택·잘못된 차량 시각은 적용을 막는다.
- 좁은 화면의 변경 확인 단계는 수정 탭을 숨기고 전후 조건을 먼저 보여준다. 수정 계속·적용 행동은 하단에 유지하며 여러 항목의 긴 비교는 본문에서 스크롤한다. 시연 안내는 유지한다.
- run ID와 조건 서명을 대조해 현재 실행의 회신만 수신한다. 단계 상태와 receipt 종류·시연 모드·대상·날짜·시간을 검증한다.
- 중지·화면 이탈·새 대화는 진행 중 fixture를 취소한다. 늦은 이벤트는 무시한다. 완료 결과는 남기고 다음 시작에서 미완료 항목만 진행한다.
- 적용한 병원·진료과·날짜·시각 변경은 종속 결과를 제거한다. 출발 장소·시간 수정은 차량 결과만, 휠체어 조건 변경은 차량·동행 결과를 다시 확인한다. 적용한 변경을 나중에 이전 조건으로 되돌려도 오래된 확정 결과가 되살아나지 않는다.
- 실제 완료·실제 예약 저장을 추가하지 않는다. 결과는 탭 메모리와 명시적으로 내려받는 시연 결과표에만 있다. 새로고침 시 초기화된다.

## 차량 회신과 재조율

차량 불가 회신을 받으면 출발지·날짜·탑승 조건을 보존하고 가상 운행표에서 원래 시각의 앞뒤 한 시간 안에 있는 대안을 가까운 순으로 두 개까지 찾는다. 진료·공항 도착·항공 출발·병원 동행의 입력된 시각을 넘기는 안은 제외한다. 선택하면 해당 차량에만 새 회신 번호를 발급한다. 해당 방문에서 이미 받은 병원·동행 회신은 그대로 결과표에 인쇄한다.

희망 시각을 직접 입력했다면 진료 시각을 바꿔도 보존하며, 충돌하면 해당 입력을 바로 열어 수정한다. 날짜가 자정을 걸칠 때는 제주 차량 출발일과 병원 동행 약속일을 각각 판정한다. 가상 운행표·기관 회신과 제주데이터허브 등록 문의처의 출처는 따로 표시한다. [차량 대안과 근거](reviews/2026-11-18-rubric-improvement-plan.md)
