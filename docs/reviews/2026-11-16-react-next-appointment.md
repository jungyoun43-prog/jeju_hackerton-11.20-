# React·Next.js, 진료과·예약·왕복 교통 개선 검증

2026-11-16 KST. 로컬 변경이며 커밋·배포·실제 예약은 수행하지 않았다. 이전 주간 달력 검증과 구분한 최종 기록이다.

## 변경

- 기본 UI를 Next.js 16.4.6·React 19.3.1 App Router로 전환했다. 예약 영역은 실제 JSX와 shadcn 컴포넌트다. 대화·음성·복구 컨트롤러는 DOM 소유권을 분리해 보존한 단계적 전환이다. 전체 대화 화면의 React 재작성은 아니다.
- 진료과를 27개로 확대하고 이름 검색·분류·키보드 선택·검색 결과 없음과 진료과별 가상 의료진 55명을 연결했다. 병원·진료과가 바뀌면 이전 접수 답변과 일정 선택을 해제한다.
- 초진/재진·진료의뢰서를 먼저 확인한다. 미준비·미확인은 발급/예약 상담으로 이어지고 판독문 보유를 의뢰서 준비로 해석하지 않는다. 자기보고로 실제 문서를 만들거나 접수 검증을 표시하지 않는다.
- 당월부터 한 달씩 탐색하며 연도 전환·빈자리·마감·미공개를 구분한다. 실제 대기기간 추정과 고정 시연 데이터를 구분한다.
- 집→제주공항→도외 공항→병원→귀가의 항공·지상 이동, 첫차/막차·환승·전날 이동·숙박·검사 종료 미정·휠체어·지연 대안을 정리한다. 선택 입력 시각의 순서만 대조한다.
- 왼쪽 색 막대, 반복 경고 박스, 장식성 배지와 홍보성 제목을 줄였다. 접수 상태는 행과 본문, 변경 안내는 한 문장, 달력과 시간은 PC에서 나란히 배치한다. 320px 달력 넘침을 수정했다.

## ego lite 사용 및 시각 확인

같은 작업 공간 4에서 로컬 화면을 열고 진료과 검색→소화기내과→의뢰서 보유 응답→의료진→다음 달 날짜·시각→요청/회신→왕복 교통을 직접 사용했다. PC·모바일 viewport 캡처를 열어 확인했다. 초기 달력의 열 정렬과 320px 넘침을 수정한 뒤 재검사했다. 캡처와 요약은 `output/appointment-react-qa/`에 있다.

개발 handler도 별도 keyless 포트에서 페이지 HTTP 200과 `llm:false` capabilities를 확인했다. 최종 확인용 정적 프리뷰는 `http://127.0.0.1:4188/`다. 새 환경은 README의 `npm ci --ignore-scripts`, `npm run dev`, `npm run build`, `npm run preview`를 따른다.

## 남은 범위

실제 병원 슬롯·의뢰서 제출·의료진 수락·예약·항공권·실시간 버스·이동 ETA·배차는 미연동이다. 병원·의료진·달력·회신은 합성이고 교통 입력은 계획이다. 실제 서비스 개인정보/위임/권한 검토나 운영 준비 완료를 뜻하지 않는다. 추가 실제 모델 품질 평가와 AWS 배포는 수행하지 않았다.
